# 数据报与地址

## 学习目标

学完本章后，你应该能够：

- 说出一个 UDP 数据报中程序最关心的内容、来源地址和目标地址。
- 解释 IP、端口和 `IP:端口` 分别回答什么问题。
- 看懂 IPv4 地址结构 `struct sockaddr_in` 的常用字段。
- 正确使用 `htons()`、`ntohs()`、`inet_pton()` 和 `inet_ntop()`。
- 解释 `recvfrom()` 为什么能取得发送者地址，以及该地址如何用于回包。
- 理解 UDP 数据报边界、长度限制与接收缓冲区不足时的后果。
- 优先在 Windows 上运行地址回显示例，并能在 Linux/WSL2 上运行等价版本。

## 1. 先分清：数据报不是只有“数据”

UDP 的一次发送叫作一个**数据报**（datagram）。程序调用 `sendto()` 时，至少会交给系统两类信息：

1. 要发送的字节，例如文本 `hello`、一段传感器读数或游戏坐标。
2. 目标地址，即要发给哪里的 `IP:端口`。

网络传输后，接收程序调用 `recvfrom()`，会同时取得：

1. 该数据报的字节和实际长度。
2. 发送者的来源地址，即发送方的 `IP:端口`。

```text
客户端 127.0.0.1:51001                       服务端 127.0.0.1:9001
      |                                                |
      | sendto("hello", 目标=127.0.0.1:9001)         |
      | ------------------ 一份 UDP 数据报 ----------> |
      |                                                | recvfrom()
      |                                                | 内容: "hello"
      |                                                | 来源: 127.0.0.1:51001
```

可以把它类比为寄一封短信：信的内容是字节；收件地址是目标地址；寄件地址是来源地址。服务端不需要猜测“该回复给谁”，因为 `recvfrom()` 已把寄件地址写入程序提供的变量。

### 1.1 IP 和端口各自解决什么问题

`127.0.0.1:9001` 是一个常见的 Socket 地址：

```text
127.0.0.1:9001
│         └── 端口：这台主机上的哪个网络程序或 Socket
└── IP：要到哪台主机（127.0.0.1 表示当前这台主机）
```

| 部分 | 例子 | 解决的问题 |
| --- | --- | --- |
| IP 地址 | `192.168.1.25` | 数据报应到哪台主机？ |
| 端口 | `9001` | 到达主机后，应交给哪个 Socket？ |
| IP + 端口 | `192.168.1.25:9001` | 网络中一次通信的具体目的地是谁？ |

IP 像一栋楼的地址，端口像这栋楼中的房间号。只有 IP 而没有端口，操作系统不知道应该将数据交给哪个程序；只有端口而没有 IP，网络不知道应先到哪一台主机。

### 1.2 三种容易混淆的 IPv4 地址

| 地址 | 含义 | 适合的练习场景 |
| --- | --- | --- |
| `127.0.0.1` | 回环地址，只能访问本机 | 第一次运行示例，最安全、最简单 |
| 本机局域网 IP，例如 `192.168.1.25` | 当前机器在局域网中的地址 | 两台已授权的局域网机器测试 |
| `0.0.0.0`（仅用于 `bind()`） | 监听本机所有 IPv4 网卡 | 需要在多个本机网卡上接收数据时 |

`0.0.0.0` 不是一个可作为远程目标填写的普通地址。服务端用它 `bind()`，含义是“凡是发往本机任意 IPv4 地址且端口匹配的数据报，都交给我”。初学时优先使用 `127.0.0.1`，避免把未经认证的测试程序暴露到局域网。

## 2. `sockaddr_in`：C 中怎样保存 IPv4 地址

Socket API 用地址结构保存 IP 和端口。IPv4 最常用的是 `struct sockaddr_in`：

~~~c
struct sockaddr_in address = {0};

address.sin_family = AF_INET;       /* IPv4 地址族 */
address.sin_port = htons(9001);     /* 端口，必须使用网络字节序 */
address.sin_addr.s_addr = htonl(INADDR_LOOPBACK);  /* 127.0.0.1 */
~~~

| 字段 | 含义 | 示例 |
| --- | --- | --- |
| `sin_family` | 地址族，IPv4 固定为 `AF_INET` | `AF_INET` |
| `sin_port` | 端口，保存时必须是网络字节序 | `htons(9001)` |
| `sin_addr` | IPv4 地址，二进制形式 | `127.0.0.1` 对应的二进制值 |

名字中的 `in` 来自 Internet，表示 IPv4 的 Internet 地址结构。它不是 C 字符串，不能直接用 `%s` 打印。

### 2.1 为什么参数类型常常是 `struct sockaddr *`

`sendto()`、`recvfrom()` 和 `bind()` 都可以处理 IPv4、IPv6 等多种地址，所以它们的参数使用通用类型 `struct sockaddr *`。但程序知道自己当前使用 IPv4，因此实际变量是更具体的 `struct sockaddr_in`。

~~~c
struct sockaddr_in server_addr = {0};

bind(sock,
     (const struct sockaddr *)&server_addr,
     sizeof(server_addr));
~~~

这里的强制转换**不会改变** `server_addr` 中的内容，也不会把 IPv4 变成其他地址。它只是在告诉编译器：“请把这个 IPv4 地址，作为通用 Socket 地址传给系统调用。”

IPv6 使用 `struct sockaddr_in6` 和 `AF_INET6`。本章为减少初学时的变量，先集中讲 IPv4；不要把 IPv4 的 `sockaddr_in` 用在 IPv6 Socket 上。

## 3. 网络字节序：为什么端口不能直接写 `9001`

不同 CPU 可能以不同顺序保存多字节整数。网络协议规定，端口和 IPv4 地址中的数值要采用统一的**网络字节序**（大端序）。这样不同机器才能对同一段字节作出一致解释。

因此，程序中的端口在写入地址结构前要转换：

~~~c
address.sin_port = htons(9001);
~~~

`htons` 的名字可以拆开读：

```text
h to n s
host -> network, short（16 位整数）
主机字节序 -> 网络字节序，适用于端口
```

从地址结构取端口并打印时，要反向转换：

~~~c
printf("port = %u\n", (unsigned int)ntohs(address.sin_port));
~~~

| 函数 | 方向 | 常用对象 |
| --- | --- | --- |
| `htons()` | 主机 -> 网络，16 位 | 端口 |
| `ntohs()` | 网络 -> 主机，16 位 | 读取或打印端口 |
| `htonl()` | 主机 -> 网络，32 位 | IPv4 常量、32 位数值 |
| `ntohl()` | 网络 -> 主机，32 位 | 读取 32 位数值 |

`s` 表示 short（16 位），`l` 表示 long（这里按网络 API 的 32 位含义理解）。即使当前电脑恰好不转换也能工作，也不要省略这些函数；代码应在不同平台和 CPU 上保持正确。

### 3.1 文本 IP 与二进制 IP 的转换

人适合阅读字符串 `"127.0.0.1"`，网络 API 适合处理二进制地址。推荐用以下一对函数转换：

~~~c
struct sockaddr_in server_addr = {0};
char readable_ip[INET_ADDRSTRLEN];

server_addr.sin_family = AF_INET;
server_addr.sin_port = htons(9001);

/* 把文本 IP 写入二进制地址字段；成功时返回 1。 */
if (inet_pton(AF_INET, "127.0.0.1", &server_addr.sin_addr) != 1) {
    /* 输入不是合法 IPv4 地址，或调用失败。 */
}

/* 把二进制地址转换为可打印文本；失败时返回 NULL。 */
if (inet_ntop(AF_INET, &server_addr.sin_addr,
              readable_ip, sizeof(readable_ip)) != NULL) {
    printf("server IP = %s\n", readable_ip);
}
~~~

`inet_pton()` 中的 `p` 是 presentation，表示人看到的文本形式；`inet_ntop()` 中的 `n` 是 network，表示网络二进制形式。`INET_ADDRSTRLEN` 是保存 IPv4 文本的标准数组大小；不要自行猜测一个很小的数字。

## 4. `sendto()` 和 `recvfrom()` 中地址怎样流动

先看省略错误处理后的形式：

~~~c
sendto(sock, data, data_length, 0,
       (const struct sockaddr *)&target_addr, sizeof(target_addr));

recvfrom(sock, buffer, buffer_capacity, 0,
         (struct sockaddr *)&source_addr, &source_addr_length);
~~~

两者的地址参数方向不同：

| 调用 | 地址参数的角色 | 程序需要在调用前做什么 | 调用后得到什么 |
| --- | --- | --- | --- |
| `sendto()` | **输入**：目标地址 | 填好 `target_addr` | 系统知道向哪里发送 |
| `recvfrom()` | **输出**：来源地址 | 提供空的 `source_addr` 与其容量 | 系统填入刚才的发送者地址 |

### 4.1 `recvfrom()` 的地址长度为什么每轮都要重设

`recvfrom()` 最后一个参数既是输入也是输出：

```text
调用前：source_addr_length = source_addr 可容纳的字节数
调用后：source_addr_length = 系统实际写入的地址长度
```

所以服务端循环中应这样写：

~~~c
for (;;) {
    struct sockaddr_in client_addr;

    /* 每次调用前重新说明结构的容量。 */
#ifdef _WIN32
    int client_addr_length = sizeof(client_addr);
#else
    socklen_t client_addr_length = sizeof(client_addr);
#endif

    int received = recvfrom(sock, buffer, buffer_size, 0,
                            (struct sockaddr *)&client_addr,
                            &client_addr_length);
}
~~~

Windows 的地址长度类型通常是 `int`，Linux/WSL2 使用 `socklen_t`。若把 `client_addr_length` 放在循环外且不重新赋值，代码可能恰好能运行，但它不再遵守 API 的输入要求，也不利于以后改成其他地址族。

### 4.2 客户端没有 `bind()`，服务端为什么仍能回复

客户端通常只创建 Socket 后直接 `sendto()`。第一次发送时，操作系统会自动选取一个合适的本机 IP 和临时端口，例如 `127.0.0.1:51001`。

```text
客户端                                   服务端
socket()
sendto(..., 127.0.0.1:9001)
  系统自动分配 127.0.0.1:51001  ----->  recvfrom()
                                           client_addr = 127.0.0.1:51001
                                         sendto(..., client_addr)
recvfrom() <------------------------------ 回包
```

临时端口不是固定值，每次运行可能不同。服务端直接把 `recvfrom()` 得到的 `client_addr` 原样传给 `sendto()`，就会把回复发回本次请求的发送者。

## 5. 数据报边界、长度和截断

TCP 是连续字节流；UDP 是一个个有边界的数据报。连续发送两份 UDP 数据报：

~~~c
sendto(sock, "one", 3, 0, ...);
sendto(sock, "two", 3, 0, ...);
~~~

接收方会在两次调用中分别取得它们：

```text
第一次 recvfrom() -> "one"
第二次 recvfrom() -> "two"
```

一次 `recvfrom()` 最多读取一份数据报，不会把两份拼接起来。反过来，如果接收缓冲区比当前数据报小，也**不能**在下一次 `recvfrom()` 读到同一份数据报的剩余部分：当前数据报会被截断，剩余部分将丢失（具体错误或标记因平台而异）。

### 5.1 文本缓冲区为什么使用 `BUFFER_SIZE - 1`

网络发送的是原始字节，不会自动在末尾添加 C 字符串结束符 `\0`。当示例想用 `%s` 打印文本时，要留一个字节自行补上：

~~~c
char buffer[1024];
int received = recvfrom(sock, buffer, sizeof(buffer) - 1, 0, ...);
if (received >= 0) {
    buffer[received] = '\0';  /* 仅为把收到的字节显示为文本 */
}
~~~

这不适用于图片、音频、压缩包等二进制数据。二进制数据要始终依靠 `received` 这个返回长度处理，不能调用 `strlen()` 或用 `%s` 打印。

### 5.2 不要把 UDP 当作“大消息通道”

IPv4 UDP 头中的长度字段是 16 位，因此单个 UDP 数据报的理论总长度最多为 65,535 字节；除去 IP 和 UDP 头后，应用数据理论上最多约 65,507 字节。这个数字不是推荐的实际消息大小。

较大的 UDP 数据报常导致 IP 分片。任何一个分片丢失，整份数据报都会无法交付；不同网络路径也可能丢弃大数据报。因此应用协议应规定较小的最大数据报长度。若确实必须发送大内容，需要自行设计分块编号、重组、超时、完整性校验和丢块处理，或改用 TCP。

## 6. Windows 优先实践：打印来源地址并回显

下面的服务端绑定 `127.0.0.1:9001`。它会打印每份数据报的来源地址和长度，然后把原始字节回发。保存为 `udp_address_server_win.c`。

### 6.1 Windows 服务端

~~~c
#include <winsock2.h>
#include <ws2tcpip.h>
#include <stdio.h>

#pragma comment(lib, "Ws2_32.lib")

#define SERVER_PORT 9001
#define BUFFER_SIZE 1024

int main(void) {
    WSADATA wsa_data;
    SOCKET server_sock = INVALID_SOCKET;
    struct sockaddr_in server_addr = {0};

    /* Windows 中，任何 Socket 调用前都必须先初始化 Winsock。 */
    if (WSAStartup(MAKEWORD(2, 2), &wsa_data) != 0) {
        printf("WSAStartup failed: %d\n", WSAGetLastError());
        return 1;
    }

    server_sock = socket(AF_INET, SOCK_DGRAM, IPPROTO_UDP);
    if (server_sock == INVALID_SOCKET) {
        printf("socket failed: %d\n", WSAGetLastError());
        WSACleanup();
        return 1;
    }

    server_addr.sin_family = AF_INET;
    server_addr.sin_port = htons(SERVER_PORT);
    server_addr.sin_addr.s_addr = htonl(INADDR_LOOPBACK); /* 仅本机可访问 */
    if (bind(server_sock, (const struct sockaddr *)&server_addr,
             sizeof(server_addr)) == SOCKET_ERROR) {
        printf("bind failed: %d\n", WSAGetLastError());
        closesocket(server_sock);
        WSACleanup();
        return 1;
    }

    printf("Listening for UDP datagrams on 127.0.0.1:%d\n", SERVER_PORT);
    for (;;) {
        char buffer[BUFFER_SIZE];
        char client_ip[INET_ADDRSTRLEN];
        struct sockaddr_in client_addr = {0};
        int client_addr_length = sizeof(client_addr); /* recvfrom() 的输入容量 */

        int received = recvfrom(server_sock, buffer, sizeof(buffer), 0,
                                (struct sockaddr *)&client_addr,
                                &client_addr_length);
        if (received == SOCKET_ERROR) {
            printf("recvfrom failed: %d\n", WSAGetLastError());
            continue;
        }

        /* 二进制 IP 不能直接打印，先转换为文本。 */
        if (inet_ntop(AF_INET, &client_addr.sin_addr,
                      client_ip, sizeof(client_ip)) == NULL) {
            printf("inet_ntop failed: %d\n", WSAGetLastError());
            continue;
        }

        printf("received %d bytes from %s:%u\n", received, client_ip,
               (unsigned int)ntohs(client_addr.sin_port));

        /* client_addr 是 recvfrom() 写入的来源地址，直接用于回包。 */
        if (sendto(server_sock, buffer, received, 0,
                   (const struct sockaddr *)&client_addr,
                   client_addr_length) == SOCKET_ERROR) {
            printf("sendto failed: %d\n", WSAGetLastError());
        }
    }
}
~~~

这段服务端不把 `buffer` 当作字符串，因此可以回显零字节或其他二进制内容。`received == 0` 表示收到了**零长度 UDP 数据报**，不表示客户端断开；UDP 没有 TCP 中的连接关闭语义。

### 6.2 Windows 客户端

保存为 `udp_address_client_win.c`。它明确构造服务端地址，发送一段文本并等待回显：

~~~c
#include <winsock2.h>
#include <ws2tcpip.h>
#include <stdio.h>
#include <string.h>

#pragma comment(lib, "Ws2_32.lib")

#define SERVER_PORT 9001
#define BUFFER_SIZE 1024

int main(void) {
    WSADATA wsa_data;
    SOCKET client_sock = INVALID_SOCKET;
    struct sockaddr_in server_addr = {0};
    char buffer[BUFFER_SIZE];

    if (WSAStartup(MAKEWORD(2, 2), &wsa_data) != 0) {
        printf("WSAStartup failed: %d\n", WSAGetLastError());
        return 1;
    }
    client_sock = socket(AF_INET, SOCK_DGRAM, IPPROTO_UDP);
    if (client_sock == INVALID_SOCKET) {
        printf("socket failed: %d\n", WSAGetLastError());
        WSACleanup();
        return 1;
    }

    server_addr.sin_family = AF_INET;
    server_addr.sin_port = htons(SERVER_PORT);
    /* inet_pton() 适合处理用户输入或配置文件中的文本 IP。 */
    if (inet_pton(AF_INET, "127.0.0.1", &server_addr.sin_addr) != 1) {
        printf("The server IP is not a valid IPv4 address.\n");
        closesocket(client_sock);
        WSACleanup();
        return 1;
    }

    printf("Input a message: ");
    if (fgets(buffer, sizeof(buffer), stdin) == NULL) {
        closesocket(client_sock);
        WSACleanup();
        return 1;
    }
    buffer[strcspn(buffer, "\r\n")] = '\0'; /* 删除 fgets() 保留的换行 */

    int sent = sendto(client_sock, buffer, (int)strlen(buffer), 0,
                      (const struct sockaddr *)&server_addr,
                      sizeof(server_addr));
    if (sent == SOCKET_ERROR) {
        printf("sendto failed: %d\n", WSAGetLastError());
        closesocket(client_sock);
        WSACleanup();
        return 1;
    }

    /* 避免服务端未启动时永远阻塞在 recvfrom()。 */
    {
        DWORD timeout_ms = 3000;
        if (setsockopt(client_sock, SOL_SOCKET, SO_RCVTIMEO,
                       (const char *)&timeout_ms, sizeof(timeout_ms)) == SOCKET_ERROR) {
            printf("setsockopt failed: %d\n", WSAGetLastError());
            closesocket(client_sock);
            WSACleanup();
            return 1;
        }
    }

    int received = recvfrom(client_sock, buffer, sizeof(buffer) - 1, 0,
                            NULL, NULL);
    if (received == SOCKET_ERROR) {
        int error = WSAGetLastError();
        if (error == WSAETIMEDOUT) {
            printf("Timed out waiting for reply.\n");
        } else {
            printf("recvfrom failed: %d\n", error);
        }
        closesocket(client_sock);
        WSACleanup();
        return 1;
    }

    buffer[received] = '\0'; /* 本客户端只发送文本，所以可这样显示回包。 */
    printf("echoed %d bytes: %s\n", received, buffer);
    closesocket(client_sock);
    WSACleanup();
    return 0;
}
~~~

### 6.3 Windows 编译与运行

在两个 PowerShell 窗口中进入保存源文件的目录。MinGW-w64：

~~~powershell
gcc -Wall -Wextra -g udp_address_server_win.c -o udp_address_server_win.exe -lws2_32
gcc -Wall -Wextra -g udp_address_client_win.c -o udp_address_client_win.exe -lws2_32

# 窗口 A
.\udp_address_server_win.exe

# 窗口 B
.\udp_address_client_win.exe
~~~

Visual Studio Developer PowerShell 也可以使用：

~~~powershell
cl /W4 /Zi udp_address_server_win.c ws2_32.lib
cl /W4 /Zi udp_address_client_win.c ws2_32.lib
~~~

客户端输入 `hello` 后，客户端应输出 `echoed 5 bytes: hello`；服务端会输出类似 `received 5 bytes from 127.0.0.1:51001`。其中 `51001` 是系统自动分配的临时端口，数值会变化。

## 7. Linux/WSL2 等价示例

网络流程和地址含义完全相同。主要差异是 Linux/WSL2 不调用 `WSAStartup()`，Socket 类型为 `int`，错误通过 `perror()` 查看，关闭时调用 `close()`。

### 7.1 Linux 服务端：`udp_address_server_linux.c`

~~~c
#include <arpa/inet.h>
#include <netinet/in.h>
#include <stdio.h>
#include <sys/socket.h>
#include <unistd.h>

#define SERVER_PORT 9001
#define BUFFER_SIZE 1024

int main(void) {
    int server_fd = socket(AF_INET, SOCK_DGRAM, IPPROTO_UDP);
    if (server_fd < 0) {
        perror("socket");
        return 1;
    }

    struct sockaddr_in server_addr = {0};
    server_addr.sin_family = AF_INET;
    server_addr.sin_port = htons(SERVER_PORT);
    server_addr.sin_addr.s_addr = htonl(INADDR_LOOPBACK);
    if (bind(server_fd, (struct sockaddr *)&server_addr, sizeof(server_addr)) < 0) {
        perror("bind");
        close(server_fd);
        return 1;
    }

    printf("Listening for UDP datagrams on 127.0.0.1:%d\n", SERVER_PORT);
    for (;;) {
        char buffer[BUFFER_SIZE];
        char client_ip[INET_ADDRSTRLEN];
        struct sockaddr_in client_addr = {0};
        socklen_t client_addr_length = sizeof(client_addr);

        ssize_t received = recvfrom(server_fd, buffer, sizeof(buffer), 0,
                                    (struct sockaddr *)&client_addr,
                                    &client_addr_length);
        if (received < 0) {
            perror("recvfrom");
            continue;
        }
        if (inet_ntop(AF_INET, &client_addr.sin_addr,
                      client_ip, sizeof(client_ip)) == NULL) {
            perror("inet_ntop");
            continue;
        }

        printf("received %zd bytes from %s:%u\n", received, client_ip,
               (unsigned int)ntohs(client_addr.sin_port));
        if (sendto(server_fd, buffer, (size_t)received, 0,
                   (struct sockaddr *)&client_addr, client_addr_length) < 0) {
            perror("sendto");
        }
    }
}
~~~

### 7.2 Linux 客户端：`udp_address_client_linux.c`

~~~c
#include <arpa/inet.h>
#include <errno.h>
#include <netinet/in.h>
#include <stdio.h>
#include <string.h>
#include <sys/socket.h>
#include <sys/time.h>
#include <unistd.h>

#define SERVER_PORT 9001
#define BUFFER_SIZE 1024

int main(void) {
    int client_fd = socket(AF_INET, SOCK_DGRAM, IPPROTO_UDP);
    if (client_fd < 0) {
        perror("socket");
        return 1;
    }

    struct sockaddr_in server_addr = {0};
    server_addr.sin_family = AF_INET;
    server_addr.sin_port = htons(SERVER_PORT);
    if (inet_pton(AF_INET, "127.0.0.1", &server_addr.sin_addr) != 1) {
        fprintf(stderr, "The server IP is not a valid IPv4 address.\n");
        close(client_fd);
        return 1;
    }

    char buffer[BUFFER_SIZE];
    printf("Input a message: ");
    if (fgets(buffer, sizeof(buffer), stdin) == NULL) {
        close(client_fd);
        return 1;
    }
    buffer[strcspn(buffer, "\r\n")] = '\0';

    if (sendto(client_fd, buffer, strlen(buffer), 0,
               (struct sockaddr *)&server_addr, sizeof(server_addr)) < 0) {
        perror("sendto");
        close(client_fd);
        return 1;
    }

    {
        struct timeval timeout = {3, 0}; /* Linux 的超时单位是秒和微秒。 */
        if (setsockopt(client_fd, SOL_SOCKET, SO_RCVTIMEO,
                       &timeout, sizeof(timeout)) < 0) {
            perror("setsockopt");
            close(client_fd);
            return 1;
        }
    }

    ssize_t received = recvfrom(client_fd, buffer, sizeof(buffer) - 1, 0,
                                NULL, NULL);
    if (received < 0) {
        if (errno == EAGAIN || errno == EWOULDBLOCK) {
            printf("Timed out waiting for reply.\n");
        } else {
            perror("recvfrom");
        }
        close(client_fd);
        return 1;
    }

    buffer[received] = '\0';
    printf("echoed %zd bytes: %s\n", received, buffer);
    close(client_fd);
    return 0;
}
~~~

编译并在两个终端运行：

~~~bash
gcc -Wall -Wextra -g udp_address_server_linux.c -o udp_address_server_linux
gcc -Wall -Wextra -g udp_address_client_linux.c -o udp_address_client_linux

# 终端 A
./udp_address_server_linux

# 终端 B
./udp_address_client_linux
~~~

WSL2 使用的是 Linux 头文件和工具链，应编译 Linux 版本；Windows 原生 MinGW 或 Visual Studio 则编译 Windows 版本。两套头文件和关闭函数不能混用。

## 8. Windows 与 Linux/WSL2 对照

| 项目 | Windows 原生 Winsock | Linux/WSL2 |
| --- | --- | --- |
| 使用前初始化 | `WSAStartup()` | 不需要 |
| Socket 类型 | `SOCKET` | `int` |
| 创建失败 | `INVALID_SOCKET` | 小于 0 |
| 一般调用失败 | `SOCKET_ERROR` | 通常小于 0 |
| 地址长度类型 | `int` | `socklen_t` |
| 错误信息 | `WSAGetLastError()` | `errno` 与 `perror()` |
| 关闭 Socket | `closesocket()` | `close()` |
| 接收超时 | `DWORD` 毫秒数 | `struct timeval`（秒、微秒） |
| 链接 | `-lws2_32` 或 `ws2_32.lib` | 基础 Socket 通常无需额外库 |

`AF_INET`、`sockaddr_in`、`htons()`、`ntohs()`、`inet_pton()`、`inet_ntop()`、`sendto()` 和 `recvfrom()` 的核心含义在两个平台上一致。这正是先理解地址与数据流向比死记平台函数更重要的原因。

## 9. 常见错误与排查

| 现象 | 原因与处理 |
| --- | --- |
| `bind()` 失败 | 端口已被其他程序占用；关闭旧服务端，或同时修改两端端口。 |
| 客户端超时 | 服务端未启动、目标 IP/端口写错、服务端未回包，或跨机器时被防火墙拦截。超时本身不能证明是哪一种原因。 |
| 端口打印成奇怪数字 | 读取 `sin_port` 后漏掉了 `ntohs()`。 |
| `inet_pton()` 失败 | IP 文本格式不合法；检查是否误填了域名、端口或多余空格。 |
| 服务端似乎“卡住” | 它正在阻塞等待 `recvfrom()`，没有数据报时这是正常行为。 |
| 文本显示不完整或乱码 | 未预留 `\0`，或者收到的数据本来就是二进制；应按返回长度处理。 |
| 发送大消息后内容不完整 | 接收缓冲区太小，UDP 不支持下一次补读同一数据报的剩余部分。 |

Windows PowerShell 可检查本机 UDP 端口：

~~~powershell
Get-NetUDPEndpoint -LocalPort 9001
netstat -ano -p udp
~~~

Linux/WSL2 可使用：

~~~bash
ss -u -a -n | grep 9001
~~~

## 实践

1. 按 Windows 示例启动服务端和客户端三次，记录服务端输出的三个临时端口，说明为什么它们可能不同。
2. 将客户端的目标端口从 `9001` 改为 `9002`，观察超时；再改回 `9001`，解释为什么恢复正常。
3. 将服务端的 `INADDR_LOOPBACK` 改成 `INADDR_ANY` 前，先说明它会扩大到哪些网卡；只在授权的网络中测试。
4. 发送空行，观察服务端的 `received 0 bytes`，并解释为什么它不是“客户端断开”。
5. 给客户端传入非法 IP，例如 `127.0.0.999`，观察 `inet_pton()` 的检查结果。
6. 在 Linux/WSL2 重复一次实验，写出初始化、关闭 Socket、地址长度类型与错误处理的四项差异。
