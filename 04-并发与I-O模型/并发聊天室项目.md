# 并发聊天室项目

> 本章面向第一次接触并发服务器的读者。你不需要先背会线程、锁、广播、事件循环这些词；我们先看具体问题，再逐步解释每个词。

## 0. 先看最终要做什么

我们要做一个最小的多人聊天室：服务器监听一个端口，多个客户端连接后，任意客户端发送一行文字，服务器把这行文字转发给其他在线客户端。

~~~text
客户端 A -- hello --> 服务器 -- [A] hello --> 客户端 B
                                  \---------> 客户端 C
~~~

这里的并发不是一句“同时处理”就结束了。它至少包含这些实际问题：

- A 一直不发消息时，服务器还能不能接受 B？
- A、B、C 的连接信息放在哪里？多个执行路线同时改它会不会弄坏？
- 一次 recv 收到半行，或者一次收到两行，服务器怎么判断消息？
- B 不读取消息时，服务器广播会不会被 B 拖住？
- 客户端断线、线程创建失败、发送失败时，谁负责清理 Socket？

本章会先实现“一个客户端一个工作线程”的学习版，再解释它的边界，并把它连接到后面的 I/O 多路复用和事件循环。

## 3. 第一个问题：串行服务器为什么不够用

最简单的服务器只有一条执行路线：

~~~text
accept 客户端 A
recv A 的消息
send A 的回复
A 断开
accept 客户端 B
~~~

假设 A 已经连接，但五分钟都不发数据。服务器就会停在 recv(A)，没有机会回到 accept()。B 虽然发起了连接，却不能及时被业务代码处理。这叫**队头阻塞**：前面的慢任务挡住了后面的任务。

有三条常见路线：

1. **一连接一线程**：每次 accept() 后创建一个线程，线程专门处理这个客户端。
2. **线程池或进程池**：预先准备固定数量的工作者，从任务队列取工作。
3. **I/O 多路复用**：一个或少量线程等待多个 Socket 哪些已经“有事情可做”。

本章先学第一种，因为它最容易把“连接”和“执行路线”对应起来。它不等于最高性能方案，只是一个清楚的教学起点。

## 4. 项目架构：每个执行路线负责什么

### 4.1 服务器结构

~~~text
服务器主线程
  socket -> bind -> listen
                     |
                     +-- accept -> 客户端 A Socket -> 工作线程 A
                     +-- accept -> 客户端 B Socket -> 工作线程 B
                     +-- accept -> 客户端 C Socket -> 工作线程 C

所有工作线程共享：在线客户端列表、客户端编号
~~~

- **主线程**：初始化监听 Socket，不断 accept()，把新 Socket 交给工作线程。
- **工作线程**：只负责一个客户端的 recv()、拆分消息和调用广播。
- **客户端列表**：记录在线客户端的 Socket 和编号，是共享数据。
- **广播函数**：找出发送者之外的客户端，向它们发送格式化后的消息。

监听 Socket 和连接 Socket 不是同一个东西。监听 Socket 只用来接受新连接；accept() 返回的新 Socket 才用来和具体客户端通信。

### 4.2 客户端为什么也需要两个执行路线

客户端同时有两个可能长时间等待的动作：等待键盘输入、等待服务器消息。

~~~text
客户端主线程       fgets 等键盘 -> send
客户端接收线程     recv 等服务器 -> printf
~~~

如果只有一个线程，程序在 fgets() 等你输入时，就无法显示 B 发来的消息。接收线程让“显示别人消息”和“输入自己的消息”互不阻塞。

### 4.3 一条消息的完整路径

以 A 输入 hello 为例：

1. A 的主线程读到 hello 和换行符。
2. A 调用 send()，TCP 把字节送往服务器。
3. A 对应的服务器工作线程不断 recv()，直到读到换行符。
4. 服务器构造带有发送者编号的消息，例如 [1] hello。
5. 服务器遍历在线列表，把消息发送给 B、C。
6. B、C 的接收线程读到换行符后显示消息。

TCP 只保证字节可靠、有序到达，不保证一次 send() 对应一次 recv()。消息边界由我们自己的协议规定。

## 5. 消息协议：规定“一行就是一条消息”

本项目使用最适合入门的换行符协议：每条消息以换行符结束。

~~~text
hello\nworld\n
~~~

接收方应解析出两条消息：hello 和 world。合法的接收结果可能是：

~~~text
第一次 recv：hel
第二次 recv：lo\nworld\n
~~~

也可能一次收到全部内容。代码必须根据内容中的换行符判断边界，而不是根据 recv() 调用次数判断。

### 5.1 消息接收函数的返回约定

为了让主循环容易读，recv_line() 可以约定如下：

| 返回值 | 含义 | 处理方式 |
| --- | --- | --- |
| 大于 0 | 读到一条完整消息，数字是消息长度 | 广播 |
| 0 | 对端有序关闭连接 | 移除客户端并结束线程 |
| -1 | Socket 出错 | 记录错误并清理 |
| -2 | 超过最大消息长度 | 丢弃到下一次换行，回复错误后继续 |

超长消息不能只读到缓冲区满就马上开始下一条，否则这一行的尾巴会被误当成下一条消息的开头。学习版可设置单行最多 1023 字节。

## 6. Windows 关键实现

知识库中的完整 Windows 程序见 [[02-TCP Socket/TCP聊天室项目]] 的“Windows 版本”。下面先看并发部分最关键的代码片段；片段需要放入完整程序的上下文中，不能单独编译。

### 6.1 Windows 客户端记录和锁

~~~c
#include <winsock2.h>
#include <windows.h>
#include <process.h>

#define MAX_CLIENTS 32

typedef struct {
    SOCKET sock;
    unsigned id;
    int active;
} Client;

static Client clients[MAX_CLIENTS];
static CRITICAL_SECTION clients_lock;
static unsigned next_id = 1;
~~~

CRITICAL_SECTION 是 Windows 进程内线程互斥工具。启动工作线程前调用 InitializeCriticalSection()，所有线程结束后调用 DeleteCriticalSection()。

### 6.2 加入和移除客户端

~~~c
static int add_client(SOCKET sock, unsigned *id_out) {
    int result = -1;
    EnterCriticalSection(&clients_lock);

    for (int i = 0; i < MAX_CLIENTS; ++i) {
        if (!clients[i].active) {
            clients[i].sock = sock;
            clients[i].id = next_id++;
            clients[i].active = 1;
            *id_out = clients[i].id;
            result = 0;
            break;
        }
    }

    LeaveCriticalSection(&clients_lock);
    return result;
}

static void remove_client(SOCKET sock) {
    EnterCriticalSection(&clients_lock);
    for (int i = 0; i < MAX_CLIENTS; ++i) {
        if (clients[i].active && clients[i].sock == sock) {
            clients[i].active = 0;
            break;
        }
    }
    LeaveCriticalSection(&clients_lock);
}
~~~

锁保护的是“查找空位、写入记录、分配编号”这一整组操作。只给 next_id 加锁，却不保护列表写入，仍可能出现不一致。

### 6.3 创建工作线程

~~~c
uintptr_t handle = _beginthreadex(
    NULL, 0, client_thread, (void *)client, 0, NULL
);
if (handle == 0) {
    remove_client(client);
    closesocket(client);
} else {
    CloseHandle((HANDLE)handle);
}
~~~

_beginthreadex() 适合会使用 C 运行库的线程函数，例如 printf()、字符串函数。CloseHandle() 只关闭主线程保存的线程句柄，不会终止工作线程；工作线程仍然运行。

工作线程主体可以先写成这样：

~~~c
static unsigned __stdcall client_thread(void *argument) {
    SOCKET sock = (SOCKET)argument;
    char line[1024];

    for (;;) {
        int n = recv_line(sock, line, sizeof line);
        if (n == 0) break;             /* 客户端正常断开 */
        if (n == -2) {                 /* 消息太长 */
            /* 发送错误提示，然后继续等下一行 */
            continue;
        }
        if (n < 0) break;              /* 真正的 Socket 错误 */
        broadcast_message(sock, line);
    }

    remove_client(sock);
    shutdown(sock, SD_BOTH);
    closesocket(sock);
    return 0;
}
~~~

### 6.4 Windows 编译和运行

使用 Visual Studio Developer Command Prompt：

~~~bat
cl /W4 /EHsc chat_server_win.c Ws2_32.lib
cl /W4 /EHsc chat_client_win.c Ws2_32.lib
~~~

使用 MinGW-w64 PowerShell：

~~~powershell
gcc -Wall -Wextra -O2 chat_server_win.c -o chat_server_win.exe -lws2_32
gcc -Wall -Wextra -O2 chat_client_win.c -o chat_client_win.exe -lws2_32
~~~

打开三个 PowerShell 窗口：

~~~powershell
.\chat_server_win.exe   # 窗口 1，客户端前先启动
.\chat_client_win.exe   # 窗口 2，客户端 A
.\chat_client_win.exe   # 窗口 3，客户端 B
~~~

A 输入 hello 后，B 应看到带有 A 编号的消息。Windows 控制台输入结束通常是 Ctrl-Z 后回车；停止服务器可按 Ctrl-C。默认使用 127.0.0.1:8080，只允许本机测试。
