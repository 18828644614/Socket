# 事件循环

> 本章面向完全新手，示例分为 Windows 原生 C++ 与 Linux C 两条路线。专业词会先解释再使用；不要求你先会 epoll、协程或异步框架。
>
> 核心问题：**一个线程怎样持续照看多个连接，处理读写、定时任务和退出，又不被一个慢客户端拖住？**

## 0. 学习地图：完整范围和顺序

### 0.1 学习目标

- 解释事件、事件源、事件分发和事件循环。
- 画出“准备关注对象 → 等待 → 分发 → 更新状态 → 继续等待”。
- 区分监听与已连接 Socket，以及可读、可写、EOF 和错误。
- 处理非阻塞调用的“暂时不能操作”，避免忙等。
- 为每个连接保存输入、输出和关闭状态，处理拆包、多条消息和部分发送。
- 使用定时器，区分等待超时、连接空闲超时和心跳超时。
- 识别会卡住循环的业务，理解公平性和背压。
- 在 Windows 或 Linux/WSL2 上运行多客户端回显服务端。

### 0.2 学习顺序

时间只是参考。建议分成 5～7 次学习，每次先预测、再运行、最后解释。

| 阶段 | 范围 | 位置 | 建议时间 | 完成标志 |
| --- | --- | --- | --- | --- |
| A：补地基 | C 语法、线程、Socket、TCP、非阻塞 | 第 1 节 | 45～90 分钟 | 能解释服务端调用顺序 |
| B：建立直觉 | 事件源、就绪、分发、并发 | 第 2～3 节 | 45～60 分钟 | 能画出一次循环 |
| C：管理读写 | accept/recv/send、缓冲区、消息边界 | 第 4～6 节 | 60～90 分钟 | 能追踪分段到达的消息 |
| D：调度和结束 | 背压、公平性、定时器、EOF、清理 | 第 7～8 节 | 60～90 分钟 | 能指出什么会拖住服务端 |
| E：动手验证 | 编译、运行客户端、观察日志 | 第 9～11 节 | 90～150 分钟 | 能完成多客户端和半关闭实验 |

**必须掌握：** 循环结构、读写就绪、非阻塞结果分类、每连接状态、消息边界、部分发送、按需关注可写、定时任务、资源清理。

**先建立认识：** Reactor/Proactor、回调、线程池、协程、水平触发/边缘触发。

**后续深入：** epoll、IOCP、io_uring、大规模压测、复杂协议、TLS。它们有用，但不需要先学完才能理解本章。

## 1. 前置知识：从零看懂网络程序

### 1.1 最少需要的 C/C++ 写法

| 写法 | 通俗解释 | 用途 |
| --- | --- | --- |
| 变量 | 给一个值起名字 | 保存收到的字节数 |
| 函数和返回值 | 请一段代码做事，再取得结果 | recv 返回实际读了多少 |
| if/else | 根据条件选择分支 | 区分数据、EOF、错误 |
| while/for | 重复执行 | 服务端持续处理事件 |
| break/continue/return | 结束循环/下一轮/退出函数 | 控制错误和等待 |
| 数组 | 一段连续存储空间 | 保存字节、保存多个连接 |
| 指针 | 指向内存的位置 | 让 recv 把字节写入数组 |
| struct | 把相关变量打包成记录 | 保存一个连接的状态 |
| size_t | 用于大小和长度的无符号整数类型 | 记录缓冲区长度 |
| sizeof | 求对象或类型占多少字节 | 计算数组容量 |
| std::array（C++） | 固定长度的数组容器 | Windows 版保存 32 个连接 |
| constexpr（C++） | 编译时已知的常量 | 定义端口和容量 |
| static_assert（C++） | 编译时检查条件 | 防止超过 Winsock 集合容量 |

还要认识两个函数：

- memcpy(目标, 来源, 长度)：复制明确数量的字节，两块内存不能重叠。
- memmove(目标, 来源, 长度)：允许重叠，适合把未处理的字节移到数组开头。

不要求你先掌握复杂指针技巧，先理解“字节放在哪里、用了多少”。

Windows C++ 版还会用到这些写法：

- std:: 表示名字来自 C++ 标准库，例如 std::array、std::printf。
- std::array<client, MAX_CLIENTS> 表示保存固定数量的 client 对象的数组，下标访问方式仍是 clients[i]。
- clients{}、address{} 使用大括号初始化，使各字段得到初始值；client{} 也可以生成一份新的空连接记录。
- using std::size_t 让后续代码可以直接写 size_t，表示大小和长度类型。
- typedef 给已有类型起别名。例如 Windows 的 socket_t 实际就是 SOCKET，Linux 的 socket_t 实际就是 int。

两份代码保持相同的字段和函数名称，便于逐项对照网络接口。

### 1.2 程序、进程、线程、内核

- **程序**：文件中的指令，例如服务器可执行文件。
- **进程**：程序运行起来的一次实例，拥有内存和资源。
- **线程**：进程中执行指令的一条路线。
- **内核**：操作系统中负责网络、内存、设备和调度的核心部分。

本章服务端用一条线程执行循环。等待时可以交出 CPU，让操作系统运行其他程序。

**并发**表示多个工作在一段时间内都能前进；**并行**表示同一时刻执行多个工作。一条线程交替照看 A、B，可以实现并发，但处理函数仍逐个执行。

### 1.3 Socket 与 TCP

- 127.0.0.1 表示本机，叫回环地址。
- 端口帮助定位机器上的服务，本章使用 19090。
- Socket 是程序使用网络能力的通信端点。
- TCP 提供有序字节流，没有应用消息边界。
- 监听 Socket 等待新连接。
- accept 返回另一个已连接 Socket，用来和某个客户端收发。

~~~text
服务端：socket → bind → listen → accept → recv/send → close
客户端：socket → connect → send/recv → close
~~~

连接成功和得到业务响应是两件事。客户端可能完成 TCP 连接，但服务端应用还没有接受或处理它。

### 1.4 缓冲区：数据暂时放在哪里

缓冲区是一块暂存字节的空间。有两类：

~~~text
客户端应用数据
  → 客户端内核发送缓冲区
  → 网络
  → 服务端内核接收缓冲区
  → recv
  → 服务端应用输入缓冲区
  → 解析/处理
  → 服务端应用输出缓冲区
  → send
  → 服务端内核发送缓冲区
  → 网络
  → 客户端
~~~

应用缓冲区由我们的程序管理；内核缓冲区由操作系统管理。

send 成功只表示相应字节交给本机网络栈，不证明对方应用已经处理。业务需要确认时，要设计响应或确认消息。

### 1.5 阻塞、非阻塞、就绪

- **阻塞**：条件不满足时，调用可能让当前线程等待。
- **非阻塞**：条件不满足时，立即返回“现在不能操作”。
- **就绪**：现在值得尝试读/写，但最终结果仍看返回值。

Linux 的 EAGAIN/EWOULDBLOCK、Windows 的 WSAEWOULDBLOCK 通常表示暂时不能操作。应保留状态，等待下次机会，而不是立即关闭。

非阻塞本身不负责等待，需要配合多路复用。

## 2. 事件循环：把等待集中起来

### 2.1 顺序服务的问题

~~~text
接受客户端 A
等待 A 发数据
给 A 回数据
A 断开后再照看 B
~~~

如果 A 只连接、不发数据，阻塞 recv 会一直等待，B 得不到及时处理。

### 2.2 三种思路

| 思路 | 做法 | 代价 |
| --- | --- | --- |
| 每连接一个线程 | A、B 分别交给不同线程 | 内存、调度、同步 |
| 不停轮询 | 反复检查所有非阻塞 Socket | 无数据时浪费 CPU |
| 事件循环 | 集中等待事件，再处理就绪对象 | 要保存状态，处理要及时返回 |

方案可以组合，例如多个线程各有一个事件循环。本章先学习一个循环。

### 2.3 前台的类比

前台照看多个窗口，没有人时等待，有人按铃后完成一小段工作，再照看其他窗口。

最重要的约束：**不能被某一个窗口占住，久久不回来。**

类比帮助理解等待和调度，真正程序还必须处理字节、错误和内存。

### 2.4 循环的五个动作

~~~mermaid
flowchart TD
    A["准备：哪些 Socket 要读、要写"] --> B["等待：select 等待就绪或超时"]
    B --> C["分发：accept、recv、send"]
    C --> D["更新：缓冲区、状态、关注事件"]
    D --> E["检查：到期任务、退出条件"]
    E --> A
~~~

伪代码，不是可直接编译的 C 程序：

~~~text
while 服务端仍要运行:
    根据连接状态准备读集合、写集合
    等待就绪事件或超时
    处理就绪对象
    更新状态、清理结束的连接
    检查到期任务和退出条件
~~~

## 3. 事件源、等待与分发

### 3.1 什么是事件

事件是“现在值得处理的一件事”，事件源是产生这件事的对象。

| 事件源 | 通知 | 下一步 |
| --- | --- | --- |
| 监听 Socket | 可读 | 尝试 accept |
| 客户端 Socket | 可读 | 尝试 recv，检查数据/EOF/错误 |
| 客户端 Socket | 可写 | 有排队输出时尝试 send |
| 计时逻辑 | 截止时间到了 | 统计、检查空闲连接等 |
| 退出信号 | Ctrl+C 等 | 设置标志，安排清理 |

可读不代表完整请求已到，可写不代表完整响应已送达。

### 3.2 select 做什么

- 返回正数：至少一个关注对象就绪。
- 返回 0：本次等待超时。
- 返回错误：检查平台错误码。

select 不替我们调用 recv/send，不解析消息，不生成响应，也不维护连接列表。

**多路复用是等待机制；事件循环是在等待之外，加上分发、状态、定时器和清理的流程。**

### 3.3 两个集合规则

1. **每轮重建集合。** select 修改传入的 fd_set，只留下本轮就绪对象。完整连接列表要另外保存。
2. **有输出才关注可写。** Socket 经常可写，永远监视它们会让 select 立即返回，CPU 空转。

下面是条件示意，完整变量见实验：

~~~c
FD_ZERO(&reads);
FD_ZERO(&writes);
FD_SET(listener, &reads);

if (connection_can_receive) FD_SET(client_socket, &reads);
if (output_used > 0) FD_SET(client_socket, &writes);
~~~

### 3.4 平台差异

| 项目 | Linux/POSIX | Windows/Winsock |
| --- | --- | --- |
| 句柄类型 | int 文件描述符 | SOCKET，不能简单当 int |
| 非阻塞 | fcntl + O_NONBLOCK | ioctlsocket + FIONBIO |
| select 首参数 | 关注的最大 fd + 1 | 被忽略，常传 0 |
| 错误码 | errno | WSAGetLastError() |
| 暂时不能操作 | EAGAIN/EWOULDBLOCK | WSAEWOULDBLOCK |
| 关闭 | close | closesocket |
| 初始化/清理 | 通常不需要 | WSAStartup/WSACleanup |
| 集合限制 | fd 数值必须小于 FD_SETSIZE | 集合项数受容量限制 |

Linux 版检查 fd 范围。Windows 的 32 个客户端加 1 个监听 Socket，在默认 64 项容量内。

### 3.5 回调、Reactor、Proactor

**回调**是登记一个函数，事件发生时由框架调用它。手写 if/else 分发也能构成循环，不必须使用回调。

**Reactor**先理解为“等待就绪，再由程序执行实际读写”的组织方式，本章采用此思路。

**Proactor**先理解为“提交异步操作，收到完成通知再处理结果”。Windows IOCP 常用于组织这种处理。

模式名称不能简单等同于某个系统调用；IOCP 也不是 Windows select 的另一个名字。

### 3.6 触发模式：会不会再次提醒

**水平触发**可以理解成“只要条件还成立，就继续提醒”。例如还有字节没读，下次等待时仍报告可读。本章 select 按这种持续报告就绪状态的思路使用，所以每轮只读一次也能继续取得进展。

**边缘触发**可以理解成“状态发生某种变化时提醒”，不能指望未处理完的数据一直让等待接口重新返回。Linux epoll 可选择这种模式，通常需要配合非阻塞并处理到 EAGAIN；若还要限制每轮工作量，需要自行安排未完成工作的后续执行。

先记住“会不会再次提醒”这个区别，具体规则留到 epoll 章节。不应直接把本章一次读取的分发代码搬到边缘触发模式。

## 4. 接受与读取：每种结果都要有去处

### 4.1 接受新连接

~~~text
监听 Socket 可读
  → accept
  → 得到已连接 Socket
  → 设置非阻塞
  → 初始化独立连接状态
  → 下一轮加入关注集合
~~~

本章每轮最多 accept 一个连接，给老客户端留下处理机会。使用 select 的通常语义时，队列还有连接，下一轮仍会通知。

### 4.2 recv 的四类结果

| 结果 | 含义 | 处理 |
| --- | --- | --- |
| n > 0 | 收到 n 字节 | 追加输入，检查完整消息 |
| n == 0 | 对端有序结束发送，EOF | 停止读，安排关闭 |
| 暂时不能读 | EAGAIN/EWOULDBLOCK 或 WSAEWOULDBLOCK | 保留状态，下轮再试 |
| 其他错误 | 如连接重置 | 记录错误，关闭该客户端 |

EINTR 表示被信号中断；本章保留状态，下一轮再试。若退出标志已设置，就结束主循环。

**0 不是暂时没数据。** 一直对 EOF 连接读取，可能每轮都读到 0，循环空转。

### 4.3 就绪后为何还要非阻塞

就绪是某个时刻的提示，状态可能变化，程序也可能继续读取更多字节。非阻塞防止调用重新把整条循环卡住。

本章每个就绪客户端每轮最多一次 recv，下次就绪继续处理。

### 4.4 状态必须属于各个连接

~~~text
A：输入 "hel"，没有换行
B：输入 "OK\n"，可以回应
~~~

A、B 要有各自的输入、输出和关闭状态。不能用一份“全局正在接收的消息”混合两个客户端。

## 5. 输入缓冲区与消息边界

### 5.1 本章的应用协议

- 一行以 \n 结束，只回显完整行。
- 同一连接可以连续发送多行。
- 一行最多 4096 字节，**包含末尾换行**。
- EOF 时丢弃未以换行结束的残留字节。
- 数据按明确字节数处理，不依靠 strlen。
- 长度超限关闭连接，避免无限占用内存。

这些是应用约定，TCP 没有“行”的概念。

### 5.2 send 次数与 recv 次数不对应

发送 hello\n，可能两次收到 he 和 llo\n；也可能一次收到 hello\nworld\n。

不能依靠 TCP 包大小或函数调用次数划分消息。

| 时刻 | 新字节 | 解析前输入 | 完整行 | 残留输入 |
| --- | --- | --- | --- | --- |
| 1 | hel | hel | 无 | hel |
| 2 | lo\nwo | hello\nwo | hello\n | wo |
| 3 | rld\n | world\n | world\n | 空 |

示例查找最后一个换行，将此前所有完整行一起排入输出，保留不完整尾部。因为只是回显，可以合并排队；若每行业务不同，则需要逐行解析。

### 5.3 字节不是 C 字符串

recv 不保证末尾有 \0，直接 printf("%s", buffer) 可能越界。UTF-8 字符也可能被拆开。

以 n 为长度复制，在消息层拼接完整后再按编码解码。深入见 [[消息边界与拆包]]。

## 6. 输出缓冲区与部分发送

### 6.1 send 可能只接受一部分

~~~text
待发送：1000 字节
send 返回：300
保留：后面 700 字节
~~~

可写通知不能代替检查返回值。成功也只代表交给本机网络栈。

### 6.2 保存进度的两种方法

- 保存偏移量，下次从未发部分开始。
- 把未发部分移到数组开头，保存剩余长度。

本章选第二种，便于观察：

~~~c
/* 仅示意 n > 0 分支，不是完整发送函数。 */
memmove(output, output + n, output_used - (size_t)n);
output_used -= (size_t)n;
~~~

大响应常使用偏移量或队列，减少内存搬运。

### 6.3 不能照搬阻塞版 send_all

循环必须“目前能发多少就发多少，然后及时返回”，不能为一个慢客户端等到全部发送完。

~~~text
成功部分发送 → 保留剩余，下次可写继续
暂时不能发   → 保留全部，回到等待
致命错误     → 清理客户端
输出发空     → 取消写关注，恢复读关注
~~~

EAGAIN 后原地无限重试也是忙等。本章每轮每客户端最多一次 send。

## 7. 背压、公平性、耗时业务

### 7.1 背压：后面堵了，前面先别进货

客户端不停发请求，却不读响应，输出可能越积越多。

**背压**是在下游处理不过来时，限制上游继续产生工作。本章策略：

~~~text
输出非空 → 暂停读该连接，只关注写
输出发空 → 恢复读
~~~

每连接输出最多占固定 4096 字节。暂停应用读取后，内核还能暂存部分数据；继续积压时，TCP 流量控制会影响发送端，不是瞬间就让发送端停止。

策略易理解，但限制同一连接吞吐量。进阶可用高/低水位：达到高阈值暂停，降到低阈值恢复。

### 7.2 公平性：每轮工作有上限

非阻塞不保证整个处理函数及时结束。如果对一个持续发送的连接无限处理，其他连接仍可能得不到机会。

本章预算：

- 每轮最多一个 accept。
- 每客户端最多一次 recv，最多 4096 字节。
- 每客户端最多一次 send。
- 消息扫描长度有上限。
- 每轮末尾检查定时任务。

### 7.3 什么会卡住循环

sleep、等待终端输入、慢数据库、同步远程 HTTP、长计算、慢磁盘、大量同步日志，都可能拖住所有连接。

Socket 非阻塞，不代表其他操作也非阻塞。

后续可把耗时业务交给工作线程，再通过线程安全队列和唤醒机制把结果交回循环。通常由循环统一修改连接状态，减少冲突。

### 7.4 异步代码和协程怎样与循环配合

**异步**先理解为：发起一项工作后，不在当前位置等待它全部结束，而是在之后处理结果。它不必然意味着另开线程，也不必然意味着使用完成通知接口。

**协程**是一种可以暂停、以后从暂停处继续的执行组织方式。许多网络框架把等待 Socket 的过程写成 await，让事件循环在数据就绪后恢复这段代码。await 背后仍需要事件等待、连接状态和调度。

本章 C/C++ 代码把进度显式保存在 struct 中；协程框架可以替你组织一部分暂停和恢复，但不会自动让普通阻塞调用或长计算变快。

## 8. 定时器、半关闭、退出清理

### 8.1 三种不同的超时

| 概念 | 问题 | 是否表示断线 |
| --- | --- | --- |
| 等待超时 | select 这次最多等多久 | 否 |
| 空闲超时 | 连接多久无业务活动 | 应用决定是否关闭 |
| 心跳超时 | 是否按期收到响应 | 按协议判断不可用 |

### 8.2 有流量时也要执行定时任务

如果永远有事件，select 可能永远不返回 0。

因此不能“只有 ready == 0 才执行 timer”。正确做法是**每轮都检查截止时间**。

多定时器程序一般计算：

~~~text
等待时间 = 最早截止时间 - 当前时间
已到期时取 0，不允许负数
~~~

本章最多等 1 秒，每 5 秒打印统计，通常有最多约 1 秒加处理耗时的误差，不是精确定时系统。

### 8.3 使用单调时钟

日历时间可能因校时或人工修改跳变。**单调时钟**用于测量经过了多久，适合超时。

Windows 用 GetTickCount64；Linux 用 clock_gettime(CLOCK_MONOTONIC)。不要直接用“几点几分”测量空闲时长。

### 8.4 EOF 不等于两个方向都结束

客户端 shutdown(SHUT_WR) 表示不再发送，但仍能接收，叫**半关闭**。

服务端原则：

~~~text
EOF → 不再关注读
    → 丢弃协议不接受的残留输入
    → 有输出就继续发送
    → 输出为空后关闭
~~~

本章背压策略先发送排队输出，再恢复读、观察 EOF，完整响应不会因半关闭直接丢失。

### 8.5 清理与优雅关闭不同

本章 Ctrl+C 设置标志，主循环最多约一秒后退出，关闭客户端和监听 Socket，再清理 Winsock。未发完的输出可能丢弃。

**业务优雅关闭**还要停止接受新连接，在总期限内完成已有响应，然后关闭剩余连接。本章不声称实现完整优雅关闭。

信号处理函数只设置标志，不打印、不释放资源、不操作网络。清理由主循环后的正常代码执行。

### 8.6 关闭客户端

记录原因 → 关闭句柄 → 标记槽位空闲 → 下一轮不再加入集合。

忘记标记，会让 select 使用已关闭句柄；句柄编号还可能被系统复用，造成更难排查的问题。

### 9.2 Windows 原生 C++ 版：event_loop_echo_windows.cpp

> 这是独立的 C++17/Winsock 示例，只在 Windows 原生环境编译。用 std::array 保存固定数量的连接，用 constexpr 定义常量，static_assert 在编译时检查集合容量。网络函数仍是 Winsock API。
>
> 下面的 Linux 示例使用 C11；两份代码采用相同的消息协议和事件循环流程，可以分别保存、编译、运行。
>
> 首次阅读先看 main 中的 while，然后看 handle_read、handle_write、prepare_output。辅助函数不再包含平台选择分支。

~~~cpp

#define _WIN32_WINNT 0x0600
#include <winsock2.h>
#include <ws2tcpip.h>
#include <windows.h>
typedef SOCKET socket_t;
typedef int io_count_t;
#define BAD_SOCKET INVALID_SOCKET
#define close_socket closesocket

#include <array>
#include <csignal>
#include <cstddef>
#include <cstdio>
#include <cstring>

using std::size_t;

constexpr int PORT = 19090;
constexpr int MAX_CLIENTS = 32;
constexpr size_t CAPACITY = 4096;

static_assert(MAX_CLIENTS + 1 <= FD_SETSIZE,
              "Too many clients for this Windows fd_set");

struct client {
    socket_t fd;                  /* BAD_SOCKET 表示槽位空闲 */
    unsigned char input[CAPACITY];
    size_t input_used;
    unsigned char output[CAPACITY];
    size_t output_used;
    int eof;                      /* 读方向是否已经结束 */
};

static volatile std::sig_atomic_t running = 1;

static void request_stop(int signal_number) {
    (void)signal_number;
    running = 0;                  /* 只设置标志，不在此清理 */
}

static int socket_error(void) {
    return WSAGetLastError();
}

static int temporary_error(int error) {
    return error == WSAEWOULDBLOCK || error == WSAEINTR;
}

static int interrupted_error(int error) {
    return error == WSAEINTR;
}

static int set_nonblocking(socket_t fd) {
    u_long enabled = 1;
    return ioctlsocket(fd, FIONBIO, &enabled) == 0 ? 0 : -1;
}

static int can_select(socket_t fd) {
    (void)fd;                     /* 集合数量上限已检查 */
    return 1;
}

static int monotonic_seconds(double *value) {
    *value = (double)GetTickCount64() / 1000.0;
    return 0;
}

static void drop_client(struct client *c, int slot, const char *reason) {
    std::printf("slot %d closed: %s\n", slot, reason);
    close_socket(c->fd);
    c->fd = BAD_SOCKET;
}

/* 调用时输出为空；将输入中的所有完整行排入输出。 */
static void prepare_output(struct client *c) {
    size_t complete = 0;
    for (size_t i = 0; i < c->input_used; ++i) {
        if (c->input[i] == '\n') complete = i + 1;
    }
    if (complete == 0) return;

    std::memcpy(c->output, c->input, complete);
    c->output_used = complete;
    c->input_used -= complete;
    std::memmove(c->input, c->input + complete, c->input_used);
}

static void handle_read(struct client *c, int slot) {
    /* 主循环只在未 EOF 且输出为空时调用。输入始终留有空间。 */
    size_t room = CAPACITY - c->input_used;
    io_count_t n = recv(c->fd, (char *)c->input + c->input_used,
                        (int)room, 0);
    if (n > 0) {
        std::printf("slot %d recv: %d bytes\n", slot, (int)n);
        c->input_used += (size_t)n;
        prepare_output(c);
        if (c->input_used == CAPACITY) {
            drop_client(c, slot, "line too long: no newline within 4096 bytes");
        }
    } else if (n == 0) {
        c->eof = 1;
        if (c->input_used > 0) {
            std::printf("slot %d: discard %zu incomplete bytes at EOF\n",
                   slot, c->input_used);
            c->input_used = 0;
        }
        if (c->output_used == 0) drop_client(c, slot, "EOF, output drained");
    } else {
        int error = socket_error();
        if (!temporary_error(error)) {
            std::fprintf(stderr, "slot %d recv error: %d\n", slot, error);
            drop_client(c, slot, "recv error");
        }
    }
}

static void handle_write(struct client *c, int slot) {
    io_count_t n = send(c->fd, (const char *)c->output,
                        (int)c->output_used, 0);
    if (n > 0) {
        std::printf("slot %d send: %d bytes\n", slot, (int)n);
        c->output_used -= (size_t)n;
        std::memmove(c->output, c->output + n, c->output_used);
        if (c->eof && c->output_used == 0)
            drop_client(c, slot, "EOF, output drained");
    } else if (n == 0) {
        drop_client(c, slot, "send made no progress");
    } else {
        int error = socket_error();
        if (!temporary_error(error)) {
            std::fprintf(stderr, "slot %d send error: %d\n", slot, error);
            drop_client(c, slot, "send error");
        }
    }
}

int main(void) {
    socket_t listener = BAD_SOCKET;
    std::array<client, MAX_CLIENTS> clients{};
    int exit_code = 1;
    double now = 0.0;
    double next_report = 0.0;
    sockaddr_in address{};
    WSADATA wsa{};
    int startup = 0;

    for (int i = 0; i < MAX_CLIENTS; ++i) clients[i].fd = BAD_SOCKET;
    std::setvbuf(stdout, NULL, _IONBF, 0); /* 实验中及时显示日志 */

    startup = WSAStartup(MAKEWORD(2, 2), &wsa);
    if (startup != 0) {
        std::fprintf(stderr, "WSAStartup failed: %d\n", startup);
        return 1;
    }
    if (std::signal(SIGINT, request_stop) == SIG_ERR) {
        std::fprintf(stderr, "cannot install Ctrl+C handler\n");
        goto cleanup;
    }

    listener = socket(AF_INET, SOCK_STREAM, IPPROTO_TCP);
    if (listener == BAD_SOCKET) {
        std::fprintf(stderr, "socket failed: %d\n", socket_error());
        goto cleanup;
    }
    if (!can_select(listener)) {
        std::fprintf(stderr, "listener fd exceeds select capacity\n");
        goto cleanup;
    }
    if (set_nonblocking(listener) < 0) {
        std::fprintf(stderr, "listener nonblocking failed: %d\n", socket_error());
        goto cleanup;
    }

    address.sin_family = AF_INET;
    address.sin_port = htons(PORT);
    address.sin_addr.s_addr = htonl(INADDR_LOOPBACK);
    if (bind(listener, (struct sockaddr *)&address, sizeof address) != 0) {
        std::fprintf(stderr, "bind failed: %d\n", socket_error());
        goto cleanup;
    }
    if (listen(listener, SOMAXCONN) != 0) {
        std::fprintf(stderr, "listen failed: %d\n", socket_error());
        goto cleanup;
    }
    if (monotonic_seconds(&now) < 0) {
        std::fprintf(stderr, "monotonic clock failed\n");
        goto cleanup;
    }
    next_report = now + 5.0;
    std::printf("listening on 127.0.0.1:%d; Ctrl+C to stop\n", PORT);
    exit_code = 0;

    while (running) {
        fd_set reads, writes;
        FD_ZERO(&reads);
        FD_ZERO(&writes);
        FD_SET(listener, &reads);
        for (int i = 0; i < MAX_CLIENTS; ++i) {
            struct client *c = &clients[i];
            if (c->fd == BAD_SOCKET) continue;
            if (!c->eof && c->output_used == 0)
                FD_SET(c->fd, &reads); /* 有输出就暂停读 */
            if (c->output_used > 0) FD_SET(c->fd, &writes);
        }

        struct timeval timeout = {1, 0}; /* 每轮重新设置 */
        int ready = select(0, &reads, &writes, NULL, &timeout);
        if (ready < 0) {
            int error = socket_error();
            if (interrupted_error(error)) continue;
            std::fprintf(stderr, "select failed: %d\n", error);
            exit_code = 1;
            break;
        }
        if (!running) break;

        if (ready > 0) {
            /* 先处理原有客户端，再接受新连接，避免混用本轮集合快照。 */
            for (int i = 0; i < MAX_CLIENTS; ++i) {
                struct client *c = &clients[i];
                if (c->fd == BAD_SOCKET) continue;
                if (FD_ISSET(c->fd, &reads)) handle_read(c, i);
                if (c->fd != BAD_SOCKET && FD_ISSET(c->fd, &writes))
                    handle_write(c, i);
            }

            if (FD_ISSET(listener, &reads)) {
                socket_t fd = accept(listener, NULL, NULL);
                if (fd == BAD_SOCKET) {
                    int error = socket_error();
                    if (!temporary_error(error))
                        std::fprintf(stderr, "accept failed: %d\n", error);
                } else {
                    int slot = -1;
                    for (int i = 0; i < MAX_CLIENTS; ++i) {
                        if (clients[i].fd == BAD_SOCKET) { slot = i; break; }
                    }
                    if (slot < 0 || !can_select(fd)) {
                        std::puts("reject: client limit or select fd limit");
                        close_socket(fd);
                    } else if (set_nonblocking(fd) < 0) {
                        std::fprintf(stderr, "client nonblocking failed: %d\n",
                                socket_error());
                        close_socket(fd);
                    } else {
                        clients[slot] = client{};
                        clients[slot].fd = fd;
                        std::printf("slot %d accepted\n", slot);
                    }
                }
            }
        }

        /* 就绪和超时都检查定时任务，持续流量不会饿死 timer。 */
        if (monotonic_seconds(&now) < 0) {
            std::fprintf(stderr, "monotonic clock failed\n");
            exit_code = 1;
            break;
        }
        if (now >= next_report) {
            int count = 0;
            for (int i = 0; i < MAX_CLIENTS; ++i)
                if (clients[i].fd != BAD_SOCKET) ++count;
            std::printf("timer: %d client(s) connected\n", count);
            next_report = now + 5.0;
        }
    }

cleanup:
    std::puts("cleanup: closing remaining sockets");
    for (int i = 0; i < MAX_CLIENTS; ++i)
        if (clients[i].fd != BAD_SOCKET) close_socket(clients[i].fd);
    if (listener != BAD_SOCKET) close_socket(listener);
    WSACleanup();
    return exit_code;
}
~~~

### 9.3 Linux 独立 C 版：event_loop_echo_linux.c

> 这是独立的 Linux/POSIX C11 示例，可以在 Linux 或 WSL2 中编译。文件描述符使用 int，非阻塞使用 fcntl，关闭使用 close，不依赖 Winsock。
>
> 这里的 _POSIX_C_SOURCE 用于声明需要的 POSIX 接口版本，不是 Windows/Linux 两个平台间的条件选择。首次阅读顺序与上面的 C++ 版相同。

~~~c

#include <signal.h>
#include <stddef.h>
#include <stdio.h>
#include <string.h>

#define PORT 19090
#define MAX_CLIENTS 32
#define CAPACITY 4096

    size_t input_used;

    running = 0;                  /* 只设置标志，不在此清理 */
}

}

    return error == EAGAIN || error == EWOULDBLOCK || error == EINTR;
}

}

static int set_nonblocking(socket_t fd) {
    int flags = fcntl(fd, F_GETFL, 0);
    if (flags < 0) return -1;
    return fcntl(fd, F_SETFL, flags | O_NONBLOCK);
}

static int can_select(socket_t fd) {
    return fd >= 0 && fd < FD_SETSIZE;
}

static int monotonic_seconds(double *value) {
    struct timespec now;
    if (clock_gettime(CLOCK_MONOTONIC, &now) < 0) return -1;
    *value = (double)now.tv_sec + (double)now.tv_nsec / 1000000000.0;
    return 0;
}

static void drop_client(struct client *c, int slot, const char *reason) {
    printf("slot %d closed: %s\n", slot, reason);
    close_socket(c->fd);

}

    memcpy(c->output, c->input, complete);
    c->output_used = complete;
    c->input_used -= complete;
    memmove(c->input, c->input + complete, c->input_used);
}

    /* 主循环只在未 EOF 且输出为空时调用。输入始终留有空间。 */

    io_count_t n = recv(c->fd, (char *)c->input + c->input_used,
                        (int)room, 0);
    if (n > 0) {

        c->input_used += (size_t)n;
        prepare_output(c);
        if (c->input_used == CAPACITY) {
            drop_client(c, slot, "line too long: no newline within 4096 bytes");
        }
    } else if (n == 0) {
        c->eof = 1;
        if (c->input_used > 0) {
            printf("slot %d: discard %zu incomplete bytes at EOF\n",
                   slot, c->input_used);
            c->input_used = 0;
        }
        if (c->output_used == 0) drop_client(c, slot, "EOF, output drained");
    } else {
        int error = socket_error();
        if (!temporary_error(error)) {

}

    io_count_t n = send(c->fd, (const char *)c->output,

        if (!temporary_error(error)) {
            fprintf(stderr, "slot %d send error: %d\n", slot, error);
            drop_client(c, slot, "send error");
        }
    }
}

int main(void) {
    socket_t listener = BAD_SOCKET;
    struct client clients[MAX_CLIENTS] = {0};
    int exit_code = 1;
    double now;

    for (int i = 0; i < MAX_CLIENTS; ++i) clients[i].fd = BAD_SOCKET;
    setvbuf(stdout, NULL, _IONBF, 0); /* 实验中及时显示日志 */

    if (signal(SIGPIPE, SIG_IGN) == SIG_ERR) {
        perror("signal SIGPIPE");
        goto cleanup;
    }
    if (signal(SIGINT, request_stop) == SIG_ERR) {
        fprintf(stderr, "cannot install Ctrl+C handler\n");
        goto cleanup;
    }

    listener = socket(AF_INET, SOCK_STREAM, IPPROTO_TCP);
    if (listener == BAD_SOCKET) {
        fprintf(stderr, "socket failed: %d\n", socket_error());
        goto cleanup;
    }
    if (!can_select(listener)) {
        fprintf(stderr, "listener fd exceeds select capacity\n");
        goto cleanup;
    }
    if (set_nonblocking(listener) < 0) {
        fprintf(stderr, "listener nonblocking failed: %d\n", socket_error());
        goto cleanup;
    }

    int reuse = 1;
    if (setsockopt(listener, SOL_SOCKET, SO_REUSEADDR,
                   &reuse, sizeof reuse) < 0) {
        perror("setsockopt SO_REUSEADDR");
        goto cleanup;
    }

    struct sockaddr_in address = {0};
    address.sin_family = AF_INET;
    address.sin_port = htons(PORT);
    address.sin_addr.s_addr = htonl(INADDR_LOOPBACK);
    if (bind(listener, (struct sockaddr *)&address, sizeof address) != 0) {
        fprintf(stderr, "bind failed: %d\n", socket_error());
        goto cleanup;
    }
    if (listen(listener, SOMAXCONN) != 0) {
        fprintf(stderr, "listen failed: %d\n", socket_error());
        goto cleanup;
    }
    if (monotonic_seconds(&now) < 0) {
        fprintf(stderr, "monotonic clock failed\n");
        goto cleanup;
    }
    double next_report = now + 5.0;
    printf("listening on 127.0.0.1:%d; Ctrl+C to stop\n", PORT);
    exit_code = 0;

    while (running) {
        fd_set reads, writes;
        FD_ZERO(&reads);
        FD_ZERO(&writes);
        FD_SET(listener, &reads);
        int max_fd = listener;
        for (int i = 0; i < MAX_CLIENTS; ++i) {
            struct client *c = &clients[i];
            if (c->fd == BAD_SOCKET) continue;
            if (!c->eof && c->output_used == 0)
                FD_SET(c->fd, &reads); /* 有输出就暂停读 */
            if (c->output_used > 0) FD_SET(c->fd, &writes);
            if (c->fd > max_fd) max_fd = c->fd;
        }

        struct timeval timeout = {1, 0}; /* 每轮重新设置 */
        int ready = select(max_fd + 1, &reads, &writes, NULL, &timeout);
        if (ready < 0) {
            int error = socket_error();
            if (interrupted_error(error)) continue;
            fprintf(stderr, "select failed: %d\n", error);
            exit_code = 1;
            break;
        }
        if (!running) break;

        if (ready > 0) {
            /* 先处理原有客户端，再接受新连接，避免混用本轮集合快照。 */
            for (int i = 0; i < MAX_CLIENTS; ++i) {
                struct client *c = &clients[i];
                if (c->fd == BAD_SOCKET) continue;
                if (FD_ISSET(c->fd, &reads)) handle_read(c, i);
                if (c->fd != BAD_SOCKET && FD_ISSET(c->fd, &writes))
                    handle_write(c, i);
            }

            if (FD_ISSET(listener, &reads)) {
                socket_t fd = accept(listener, NULL, NULL);
                if (fd == BAD_SOCKET) {
                    int error = socket_error();
                    if (!temporary_error(error))
                        fprintf(stderr, "accept failed: %d\n", error);
                } else {
                    int slot = -1;
                    for (int i = 0; i < MAX_CLIENTS; ++i) {
                        if (clients[i].fd == BAD_SOCKET) { slot = i; break; }
                    }
                    if (slot < 0 || !can_select(fd)) {
                        puts("reject: client limit or select fd limit");
                        close_socket(fd);
                    } else if (set_nonblocking(fd) < 0) {
                        fprintf(stderr, "client nonblocking failed: %d\n",
                                socket_error());
                        close_socket(fd);
                    } else {
                        memset(&clients[slot], 0, sizeof clients[slot]);
                        clients[slot].fd = fd;
                        printf("slot %d accepted\n", slot);
                    }
                }
            }
        }

        /* 就绪和超时都检查定时任务，持续流量不会饿死 timer。 */
        if (monotonic_seconds(&now) < 0) {
            fprintf(stderr, "monotonic clock failed\n");
            exit_code = 1;
            break;
        }
        if (now >= next_report) {
            int count = 0;
            for (int i = 0; i < MAX_CLIENTS; ++i)
                if (clients[i].fd != BAD_SOCKET) ++count;
            printf("timer: %d client(s) connected\n", count);
            next_report = now + 5.0;
        }
    }

cleanup:
    puts("cleanup: closing remaining sockets");
    for (int i = 0; i < MAX_CLIENTS; ++i)
        if (clients[i].fd != BAD_SOCKET) close_socket(clients[i].fd);
    if (listener != BAD_SOCKET) close_socket(listener);
    return exit_code;
}
~~~

### 9.5 共用 Python 测试客户端 event_client.py

需要 Python 3，只用标准库：

- create_connection 建立连接。
- sendall 在客户端阻塞模式下提交全部请求，不影响另一个进程的服务端循环。
- recv 也可能部分返回，客户端按期望长度循环接收。
- with 在结束时自动关闭 Socket。
- shutdown(SHUT_WR) 只结束发送方向，仍允许接收。

~~~python
import argparse
import socket
import time

parser = argparse.ArgumentParser(description="Test the C event loop server")
parser.add_argument("message", nargs="?", default="hello event loop")
parser.add_argument("--split", action="store_true", help="send in two parts")
parser.add_argument("--half-close", action="store_true", help="finish sending")
parser.add_argument("--silent", action="store_true", help="connect without sending")
parser.add_argument("--hold", type=float, default=0, help="keep open for seconds")
args = parser.parse_args()

request = (args.message + "\n").encode("utf-8")

try:
    with socket.create_connection(("127.0.0.1", 19090), timeout=5) as sock:
        sock.settimeout(10)
        print("connected", flush=True)
        if args.silent:
            print("connected but not sending", flush=True)
        else:
            if args.split:
                cut = max(1, len(request) // 2)
                sock.sendall(request[:cut])
                print("first part sent; wait 2 seconds", flush=True)
                time.sleep(2)
                sock.sendall(request[cut:])
            else:
                sock.sendall(request)

            if args.half_close:
                sock.shutdown(socket.SHUT_WR)
                print("write side closed; still receiving", flush=True)

            response = bytearray()
            while len(response) < len(request):
                part = sock.recv(len(request) - len(response))
                if not part:
                    raise RuntimeError("EOF before the complete response")
                response.extend(part)

            if bytes(response) != request:
                raise RuntimeError("response bytes differ from request")
            print("echo:", response.decode("utf-8"), end="", flush=True)

            if args.half_close:
                if sock.recv(1) != b"":
                    raise RuntimeError("expected EOF after response")
                print("server closed after response", flush=True)

        if args.hold > 0:
            time.sleep(args.hold)
except (OSError, RuntimeError) as error:
    raise SystemExit(f"client failed: {error}")
~~~

## 10. 代码导读：追踪一个连接的状态

### 10.1 固定槽位

32 个槽位，每个是 struct client。fd == BAD_SOCKET 代表空闲。

关闭时直接标记，不删除数组元素、不搬动别的客户端，所以不会出现“删除后跳过换位元素”。大型服务端会选择更合适的容器与事件映射。

### 10.2 状态与关注事件

| 状态 | 下一轮关注 | 处理 |
| --- | --- | --- |
| 空闲槽位 | 不关注 | 新连接可复用 |
| 输入不足一行，输出为空 | 读 | recv 追加，尝试解析 |
| 完整行排队输出 | 写，暂停读 | send，保留剩余 |
| 输出发空 | 读 | 下一条消息或 EOF |
| EOF 且仍有输出 | 写 | 发空后关闭 |
| 致命错误/长度超限 | 不再关注 | 关闭并标记空闲 |

本章背压策略让“EOF 且仍有输出”通常不会出现：观察 EOF 前会先排空响应。代码仍区分读方向结束和输出排空，便于扩展。

### 10.3 分段消息的完整过程

1. 客户端发送 hel，服务端 recv 得到 3 字节。
2. 输入没有换行，input_used = 3，output_used = 0。
3. 下轮仍关注读，select 等待。
4. 客户端发送 lo\n。
5. 输入变为 hello\n，完整 6 字节移到输出。
6. 下轮只关注写。
7. send 成功发出 6 字节，输出归零。
8. 下轮恢复关注读，继续服务。
9. 客户端结束发送，服务端收到 EOF，清理连接。

### 10.4 为什么下一轮才发送

本轮 select 的集合在等待前准备。recv 新产生输出时，这个连接还没加入本轮写集合。

下一轮再加入写关注，让状态更新与分发流程保持清楚，不需要另一套“收到后立即尝试发送”的分支。

### 10.5 部分发送的演算

~~~text
输出：abcdef，长度 6
send 返回 2
已经发出：ab
未发：cdef
memmove 后数组开头：cdef
长度：4
~~~

下轮继续发 cdef，不重发 ab，也不丢字节。

### 10.6 示例做了哪些保护

- 非阻塞监听与已连接 Socket；
- 每轮重建集合与超时；
- Linux fd 范围和 Windows 集合容量检查；
- 每连接独立缓冲区、消息上限和连接上限；
- 完整行解析、部分发送、简单背压；
- 每轮有限工作量，忙时仍检查 timer；
- EOF、错误和 Ctrl+C 清理；
- Linux 忽略 SIGPIPE，把对端断开后的写入当错误处理。

仍有教学限制：

- 固定数组与 memmove 易理解，但不是最高性能方案；
- 没有动态队列、认证、TLS、重连或详细协议错误响应；
- 没有空闲超时，沉默客户端可以长期占槽位；
- 同步日志在输出设备慢时也可能阻塞；
- 退出直接关闭，不等待所有响应发完；
- 第 33 个连接可能 TCP connect 成功后才被应用关闭，应看 reject 日志。

~~~python
import socket

with socket.create_connection(("127.0.0.1", 19090), timeout=5) as s:
    s.settimeout(5)
    expected = b"one\ntwo\n"
    s.sendall(expected)
    received = bytearray()

        if not part:
            raise RuntimeError("response ended early")
        received.extend(part)
~~~

预期 b'one\ntwo\n'。不要把交互终端的 >>> 提示符复制进代码。交互终端中，while/with 代码块结束后要输入空行；不熟悉时优先保存为脚本。

## 12. 常见错误与排查

先记录：系统与终端、IP/端口、当前函数、返回值/错误码、最后一条日志。“连不上”可能是编译、监听、连接或协议问题，先定位层次。

| 现象 | 常见原因 | 检查/修复 |
| --- | --- | --- |
| 找不到 g++/gcc/python | 未安装或 PATH 不含它 | Windows、WSL 分别核对环境 |
| 找不到 sys/socket.h | 在 Windows 编译 Linux C 文件 | Windows 选择 .cpp 文件，Linux 选择 .c 文件 |
| Winsock 链接错误 | 缺少网络库 | 加 -lws2_32 或 ws2_32.lib |
| Connection refused | 服务端未监听或端口错误 | 检查 listening 日志与 LISTEN |
| bind 失败 | 旧进程、端口占用、权限或重启状态 | 核对 PID、地址、错误码 |
| 连接了但不回显 | 无换行或未生成输出 | 检查 input_used、output_used |
| 一个客户端拖住所有人 | 阻塞、sleep、长计算、无限循环 | 非阻塞并限制每轮工作量 |
| CPU 持续很高 | 永远关注写、等待时间为 0、EOF 不移除 | 检查集合和关闭分支 |
| 少收到字节 | 忽略部分 send 或过早关闭 | 保存剩余输出 |
| 客户端数据混乱 | 共用消息状态 | 每连接独立缓冲区 |
| select 报坏句柄 | 已关闭句柄还在列表 | 清理后立即标记空闲 |
| Linux 写入后进程退出 | SIGPIPE | 忽略信号或使用平台发送标志，仍检查写错误 |
| 忙时 timer 不打印 | 只在等待超时检查 | 每轮检查截止时间 |
| 第 33 个连接立即关闭 | 连接上限 | 看 reject，区分 TCP 与应用接受 |

### 12.1 集合与 timeout 都重建

select 会修改集合；POSIX 实现也可能修改 timeval。不要假定返回后还是原来的一秒。本章都在 while 内重建。

### 12.2 Linux fd 数值与连接数不同

即使只有两个连接，其中一个 fd 数值达到 FD_SETSIZE，也不能安全 FD_SET。数量检查不能替代 fd 范围检查。大量连接考虑 poll/epoll。

### 12.3 异常集合不是万能错误集合

exceptfds 有平台规定的意义，例如特定带外数据或连接状态。常规 EOF/读写错误仍看 recv/send 返回值。

示例传 NULL，不代表不检查错误。

### 12.4 暂时不能操作不是致命错误

EAGAIN/EWOULDBLOCK 不关闭连接，也不原地无限重试。保留状态，回到等待。

### 12.5 多连接没有统一网络顺序

本章按槽位扫描就绪连接，不保证跨连接的业务顺序。TCP 保证同一连接内的字节顺序，不提供多连接的全局排序。

### 12.6 端口排查与 SO_REUSEADDR

先用 Get-NetTCPConnection 或 ss 找出监听者，再决定停止自己启动的旧服务端或换端口。不要随意终止陌生进程。

Linux 版已在 bind 前检查并设置 SO_REUSEADDR，帮助处理某些重启/TIME_WAIT 场景，但这不能强行抢占仍在监听的端口。

Windows 的地址复用语义与 Linux 不完全相同，本章不把 SO_REUSEADDR 无差别套用到两套平台。进阶见 [[08-C与Linux深入/Socket选项与内核参数]]。

## 13. 练习题：解释、演算、修改

先做题，再看参考要点。用日志或状态表证明结论。

### 练习 1：解释三个客户端

**题目：** 一个沉默、一个发半行、一个发完整行。分别关注什么？谁得到响应？

**参考：** 沉默连接等读；半行存输入、继续等读；完整行生成输出、转为等写。没有事件时由 select 等待，不阻塞在任何单个客户端上。

### 练习 2：手算输入

依次收到 A、B\nC\nD、E\n。假设每次输出先发完，再处理下一段。

**参考：**

- 第一步无完整行，残留 A。
- 第二步完整行 AB\n 和 C\n，残留 D。
- 第三步完整行 DE\n，残留空。

### 练习 3：手算输出

abcdefgh，send 依次返回 3、2、3，每次剩什么？第二次如果暂时不能发呢？

**参考：** 正常剩 defgh、fgh、空；暂时不能发不移动字节，仍剩 defgh。

### 练习 4：找到高 CPU 的原因

永远将所有 Socket 加入写集合，无业务时 CPU 仍高。

**参考：** Socket 经常可写，select 立即返回。只在有输出时关注写，不要用 sleep 掩盖集合设计问题。

### 练习 5：添加 30 秒空闲超时

为 client 加 double last_activity，接受连接时初始化，成功 recv/send 时更新，每轮关闭超过 30 秒无活动的连接。

提示：

- 用单调时钟。
- 明确活动包括收、发还是只包括收到请求。
- 就绪但没有进展，不算有效活动。
- 定时检查每轮执行。
- 不访问已关闭槽位。

**完成标准：** 沉默连接最终关闭，持续活动连接保留，忙时仍检查超时。

### 练习 6：ping/pong

收到 ping\n 回复 pong\n，其他行回显。

提示：逐行解析、明确字节数、检查输出容量。不能只用 strstr 查 ping，它可能只是行的一部分。

**完成标准：** ping\n、hello\n、ping\nhello\n，以及分段到达的 ping\n 都正确。

### 练习 7：演示耗时业务

在专用副本中，对特定请求 sleep 2 秒，同时另一个客户端发送。

**预测：** Socket 非阻塞也救不了正在 sleep 的主线程。

进一步区分：只是想“2 秒后回应”，可登记截止时间而不 sleep；确实要计算 2 秒，考虑工作线程，不是改成定时器就能消除计算成本。

### 练习 8：改用输出偏移量

用偏移量代替每次 send 后 memmove。

**完成标准：** 偏移量只增加成功字节数；暂时不能发时不变；发完后长度与偏移量一致复位；半关闭实验仍通过。

### 练习 9：迁移等待接口

Linux 尝试改用 poll，之后再学 epoll。

变化的是登记、等待与取得事件的接口，缓冲区、协议边界、输出进度和关闭状态仍需要。

epoll **边缘触发**通常要读/写到 EAGAIN，不能直接照搬本章每事件只调用一次的方式；若同时控制公平性，还要保存未完成工作并安排后续调度。先读 [[08-C与Linux深入/epoll深入]]。
