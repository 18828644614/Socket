# 线程与进程模型

## 本章学什么

本章回答一个实际问题：一个 TCP 服务器同时收到很多客户端连接时，怎样安排程序去处理它们？学习结束后，你应该能读懂“一连接一线程”“线程池”“多进程”等说法，能运行一个简单的并发回显服务器，知道不同办法的成本和适用场景，并能指出共享数据为什么需要保护。

本章先用一个线程版回显服务器练习并发处理。它帮助建立模型，不代表它适合直接作为高负载生产服务器。Linux 和 Windows 的线程 API 不同，因此下面分别给出可编译的程序。多进程部分也分别介绍 Linux 的 `fork` 和 Windows 的 `CreateProcess`。

## 学习路线

建议按顺序完成，每一步都先读概念，再运行对应代码或做自测。预计分 6 次学习，每次约 30-60 分钟；时间可按自己的节奏调整。

| 阶段 | 内容 | 学完后能做什么 |
|---|---|---|
| 1. 预备知识 | 程序、进程、线程、TCP 连接、阻塞等待 | 解释服务器为什么不能只处理一个客户端 |
| 2. 操作系统执行模型 | 进程与线程、并发与并行、上下文切换 | 说明进程和线程的主要区别 |
| 3. 服务器并发模型 | 串行、一连接一线程、一连接一进程、线程池 | 按连接数和工作内容判断模型的成本 |
| 4. 共享状态 | 竞态、互斥锁、原子操作、生命周期 | 找出共享计数器和客户端列表中的数据竞争 |
| 5. 平台实践 | Windows/Linux 线程回显服务器、进程创建演示 | 编译、启动、连接并观察多个客户端 |
| 6. 选型与复盘 | 模型比较、常见故障、练习和阶段检查 | 解释小型服务和大量连接服务的不同选择 |

### 开始前需要会什么

不要求预先懂操作系统术语。建议先熟悉这些最小基础：

- 能在终端里进入目录、编译一个 C 程序、运行可执行文件。
- 知道变量、函数、指针、结构体和 `if`、`while` 的基本含义。看不懂指针时，可以先把它理解成“某个数据在内存中的位置”。
- 知道 TCP 是一种让两台程序建立连接、按顺序传送字节的网络方式。
- 知道服务器通常会创建 socket、绑定端口、开始监听、接受连接，再收发数据。完整 TCP 流程见 [[TCP服务器]]。
- 知道 `recv`/`send` 是收/发字节的调用。它们可能等待；发送一次也不保证所有数据都已发完。
- 了解阻塞调用会暂时停在原处等待结果。更多内容见 [[阻塞与非阻塞]]。

如果这些内容还不熟，先读完本节最后的“术语小抄”，再按上面的路线学习即可。

## 1. 为什么服务器需要并发

想象一个前台工作人员：顾客 A 正在填写很长的表格时，顾客 B 和 C 到来。如果前台必须等 A 完全办完才能接待 B，那么 B、C 只能排队。这就像一个串行服务器：一次只处理一个客户端。

如果前台把每位顾客交给不同工作人员处理，就可以同时服务多人。这对应多个线程或多个进程。另一种方法是由一位工作人员快速轮流检查每位顾客是否有新事情，这对应事件循环；它属于后续章节 [[事件循环]] 的主题。

### 串行服务器

最简单的服务器通常这样工作：接受一个客户端，和它收发数据，直到它断开，然后才接受下一个客户端。

```text
接受客户端 A -> 服务 A 到结束 -> 接受客户端 B -> 服务 B 到结束
```

这很容易编写和调试，但 A 如果长时间不发数据，B 即使已经连接，也可能得不到服务。这个情况叫“队头阻塞”：队伍前面的一项工作拖慢了后面的工作。

### 并发与并行

- **并发**：多个任务在一段时间内都能向前推进。单核 CPU 也可以快速切换任务，形成并发。
- **并行**：多个任务在同一时刻分别运行，通常需要多个 CPU 核心。
- **任务**：这里泛指一段正在执行的工作，例如处理一个客户端。

并发不等于“每件事都同时发生”。线程可能轮流使用 CPU；I/O 等待时，操作系统还可以让别的线程运行。

## 2. 进程和线程是什么

### 程序、进程、线程

- **程序**是磁盘上的文件，例如 `server.exe`。它还没有运行。
- **进程**是程序运行起来后的一个实例。进程有自己的地址空间（可使用的内存范围）以及文件、socket 等资源。
- **线程**是进程里的执行路线。一个进程至少有一个线程；多个线程可以各自执行函数，但通常共用这个进程的大部分内存和资源。

可以把进程想成一间独立办公室，把线程想成办公室里的工作人员。每个人有自己的待办步骤和临时工作台（线程栈），但他们能看到办公室共享的文件和设备。进程之间默认隔着墙；线程之间交流方便，但也更容易同时改坏同一份共享数据。

| 对比 | 进程 | 线程 |
|---|---|---|
| 内存 | 每个进程有相互隔离的地址空间 | 同一进程内线程共享大部分地址空间 |
| 通信 | 通常要通过管道、套接字、共享内存等 IPC（进程间通信）方式 | 可直接访问共享变量，但访问需要协调 |
| 创建和切换成本 | 通常较高，隔离性强 | 通常较低，共享内容多 |
| 故障影响 | 一个进程崩溃通常不直接摧毁其他进程 | 一个线程发生严重错误可能导致整个进程退出 |
| 典型用途 | 隔离不同服务、利用进程级故障边界 | 同一服务中的多个并行任务 |

“通常较高/较低”是常见情况，不是对所有系统和负载的绝对保证。

### 上下文切换

CPU 在不同线程或进程间切换时，需要保存当前执行位置和部分状态，再恢复另一个任务的状态，这叫**上下文切换**。切换有成本：CPU 花时间管理任务，而没有直接处理业务。大量短小任务如果不断创建、结束和切换，可能比复用少量工作线程更慢。

### 线程栈和共享内存

每个线程有自己的调用栈，函数的局部变量通常放在该线程的栈上。全局变量、静态变量、动态分配的对象，以及指向这些对象的指针，可能被同进程的多个线程同时访问。

```c
int connection_count = 0; /* 全局数据：同进程线程都能访问 */

void worker(void) {
    int bytes = 0;         /* 局部数据：每次调用各有一份 */
    (void)bytes;
}
```

要注意：局部变量本身通常不共享，但如果把它的地址交给另一个线程使用，它就可能被共享。对象何时销毁也很重要，不能让线程继续使用已经失效的内存。

## 3. 常见服务器并发模型

### 一连接一线程

服务器每接受一个客户端，就创建一个线程负责它；客户端断开后，线程结束。

```text
主线程: accept A -> 创建线程 A -> accept B -> 创建线程 B -> ...
线程 A: 处理客户端 A
线程 B: 处理客户端 B
```

优点是容易理解：处理一个连接的代码可以顺序写。一个客户端阻塞等待数据时，其他客户端的线程仍可以运行。缺点是连接越多，线程数越多。线程会占用栈内存和系统调度资源；成千上万个线程往往难以管理，系统也可能被切换开销拖慢。

这种方式适合学习、小型服务、连接数量有限且每个连接处理逻辑较清楚的情况。它不等于“线程没有上限”。

### 一连接一进程

服务器每接受一个客户端，就启动一个独立进程服务它。进程隔离较强，工作进程崩溃时通常不会直接破坏父进程的数据；但创建进程和交换数据的成本一般更高。

Linux 常用 `fork()` 复制当前进程作为子进程。Windows 常用 `CreateProcess()` 启动一个程序。二者的创建方式和继承规则不同，不能把 `fork` 代码直接搬到 Windows。

创建后要明确各自该关闭哪些资源。例如 Linux 父子进程都继承了已打开文件描述符；父进程接受客户端后，父进程应关闭自己的客户端描述符，子进程应关闭不使用的监听描述符。否则引用可能一直没有释放，导致客户端看不到连接关闭。

### 线程池/进程池

池是预先创建并重复使用的一组工作线程或工作进程。主线程接受连接或任务，再把工作交给池里的空闲工作者。

```text
主线程接受连接 -> 放入任务队列 -> 空闲工作线程取出并处理
```

任务队列是等待被处理的工作列表。池的好处是限制工作者数量，避免每个新连接都创建一个新线程。需要额外设计队列容量、满载时的处理、工作者退出和共享状态保护。

如果队列无限增长，服务器可能把过载变成内存耗尽；队列达到上限后，可以拒绝新任务、暂时停止接收或返回忙碌错误。这个行为属于**背压**：系统告诉上游“我暂时处理不过来”。

### 事件循环

事件循环通常由少量线程管理许多 socket：等待“哪些连接现在可读/可写”，然后处理这些连接。连接很多且大多数时间都在等待网络时，这种方式能减少线程数量，但代码通常需要显式管理每条连接的状态和缓冲区。

本章不深入 `select`、`poll`、`epoll`、IOCP 等机制，之后按 [[I-O多路复用]]、[[事件循环]]、[[状态机与连接管理]] 的顺序学习。

### 模型快速比较

| 模型 | 工作单元 | 主要优势 | 主要代价 | 入门场景 |
|---|---|---|---|---|
| 串行 | 一个执行路线 | 最简单 | 一个慢客户端拖住其他客户端 | 理解 TCP 基本流程 |
| 一连接一线程 | 每个连接一个线程 | 写法直观，等待时互不挡住 | 连接多时线程和内存膨胀 | 学习、小型服务 |
| 一连接一进程 | 每个连接一个进程 | 故障隔离较强 | 创建和 IPC 成本较高 | 需要隔离的工作 |
| 线程池/进程池 | 固定数量工作者 | 控制并发资源，可复用工作者 | 需要队列和池的生命周期管理 | 稳定的中等规模服务 |
| 事件循环 | 少量线程管理多个连接 | 适合大量等待中的连接 | 状态管理复杂 | 大量并发连接的服务 |

没有一种模型永远最好。选择时要考虑连接数、每个连接的计算量和等待时间、内存限制、隔离要求、实现复杂度及平台能力。

## 4. 共享状态和同步

### 竞态条件

**竞态条件**是指程序结果取决于多个线程恰好以什么顺序执行。比如两个线程都把 `connection_count` 增加 1：

```text
线程 A 读取 0       线程 B 读取 0
线程 A 写回 1       线程 B 写回 1
最终结果是 1，但正确结果应该是 2
```

`count++` 看起来是一条语句，但机器可能要分成“读取、计算、写回”等多个步骤。多个线程交错执行后就可能丢失更新。

### 互斥锁

**互斥锁**（mutex）是一把同一时间只允许一个线程进入的锁。更新共享计数器时，线程先锁住，再读写，最后解锁。Linux 示例使用 POSIX mutex；Windows 可以使用 `CRITICAL_SECTION` 或互斥对象。

```c
/* 伪代码：具体函数名随平台而变 */
lock(&mutex);
connection_count++;
unlock(&mutex);
```

如果你使用 C++，可以直接使用标准库的 `std::mutex`。`std::lock_guard` 适合“进入作用域就加锁，离开作用域自动解锁”；`std::unique_lock` 更灵活，可以延迟加锁、手动解锁，也常用于条件变量。本章的 Windows 回显示例改用 C++，因此先看这个写法：

```cpp
#include <mutex>

static std::mutex count_lock;
static long connection_count = 0;

void add_connection(void) {
    std::lock_guard<std::mutex> lock(count_lock);
    ++connection_count;
} // lock 离开作用域，自动解锁
```

如果确实需要 `unique_lock`，只需替换锁的类型：

```cpp
void add_connection(void) {
    std::unique_lock<std::mutex> lock(count_lock);
    ++connection_count;
}
```

这里的 `unique_lock` 不是 C 语言功能；文件必须按 C++ 编译（例如 `.cpp`、`g++` 或 Visual Studio 的 C++ 编译模式）。如果文件仍是 `.c`，就使用下面的平台 API 版本。锁要在工作线程启动前准备好，在所有使用它的线程结束后再销毁。

Windows 原生 C 写法（`CRITICAL_SECTION`）：

```c
#include <windows.h>

static CRITICAL_SECTION count_lock;
static long connection_count;

/* 在创建工作线程前调用一次 */
void init_counter(void) {
    InitializeCriticalSection(&count_lock);
}

void add_connection(void) {
    EnterCriticalSection(&count_lock);
    connection_count++;
    LeaveCriticalSection(&count_lock);
}

/* 所有工作线程结束后调用 */
void destroy_counter(void) {
    DeleteCriticalSection(&count_lock);
}
```

Linux（POSIX `pthread_mutex_t`）：

```c
#include <pthread.h>

static pthread_mutex_t count_lock = PTHREAD_MUTEX_INITIALIZER;
static long connection_count;

void add_connection(void) {
    pthread_mutex_lock(&count_lock);
    connection_count++;
    pthread_mutex_unlock(&count_lock);
}

/* 所有工作线程结束后调用 */
void destroy_counter(void) {
    pthread_mutex_destroy(&count_lock);
}
```

上面的示例只保护“增加”操作。如果其他线程也要读取 `connection_count`，读取时也要使用同一把锁，或改用合适的原子计数器。

锁的保护范围要覆盖完整的共享操作。只保护写入而不保护读取，仍可能有问题。锁住后忘记解锁会让其他线程一直等待；多个锁以不一致的顺序获取，可能互相等待形成**死锁**。

### 原子操作

**原子操作**是一个不可被其他线程打断观察到中间状态的简单操作，常用于计数器等小范围需求。原子操作不能自动保护一组相关变量，也不能代替对复杂数据结构的完整锁定。

### 哪些东西通常需要同步

- 多个线程同时修改的计数器、链表、哈希表和客户端列表。
- 多个线程共享的日志输出（否则不同日志行可能交错）。
- 线程间传递的任务队列和停止标志。
- 一个线程可能关闭、另一个线程仍在读写的 socket 或缓冲区。

每个连接如果由一个线程独占，且连接状态没有泄漏给其他线程，连接的读写状态可以不加共享锁。但进程中的全局统计、广播客户端列表等仍是共享数据。

### socket 所有权与清理

约定每个 socket 在任意时刻由谁负责关闭。下面的示例采用“工作线程拥有已接受的客户端 socket，并在退出前关闭它”。主线程只负责监听 socket。明确所有权可以避免重复关闭，也避免关闭后其他线程继续使用。

`accept` 返回的客户端 socket 需要被传给工作线程。传递参数时要保证其内存在线程读取之前仍有效；下面用动态分配的上下文来避免把主线程循环里的临时变量地址直接交给线程。

## 5. Windows 实践：Winsock + 一连接一线程

为了先看懂“一个客户端交给一个线程”这个核心思想，下面使用 C++ 标准线程。代码把 `SOCKET client` 直接作为线程函数参数，不再额外包装成结构体。将代码保存为 `server_win.cpp`。需要支持 C++11 线程的编译器（Visual Studio 或较新的 MinGW-w64）；如果你的旧版 MinGW 没有实现 `std::thread`，请使用 Visual Studio，或先阅读 Linux 版本中的同一结构。

```cpp
#include <winsock2.h>
#include <iostream>
#include <thread>

void serve_client(SOCKET client) {
    char buffer[1024];

    while (true) {
        int received = recv(client, buffer, sizeof buffer, 0);
        if (received <= 0) {
            break; // 0 表示对方关闭；负数表示出错
        }

        int sent = 0;
        while (sent < received) {
            int n = send(client, buffer + sent, received - sent, 0);
            if (n <= 0) {
                break;
            }
            sent += n;
        }

        if (sent < received) {
            break;
        }
    }

    // 连接处理结束，由负责它的工作线程关闭客户端 socket。
    // 原 C 版本还调用 shutdown(client, SD_BOTH)，它是可选的“先停止收发”步骤。
    closesocket(client);
}

int main() {
    WSADATA data{};
    if (WSAStartup(MAKEWORD(2, 2), &data) != 0) {
        std::cerr << "WSAStartup failed\n";
        return 1;
    }

    SOCKET listener = socket(AF_INET, SOCK_STREAM, IPPROTO_TCP);
    if (listener == INVALID_SOCKET) {
        std::cerr << "socket failed: " << WSAGetLastError() << "\n";
        WSACleanup();
        return 1;
    }

    sockaddr_in address{};
    address.sin_family = AF_INET;
    address.sin_port = htons(9000);
    address.sin_addr.s_addr = htonl(INADDR_ANY);

    if (bind(listener, reinterpret_cast<sockaddr *>(&address), sizeof address) == SOCKET_ERROR ||
        listen(listener, SOMAXCONN) == SOCKET_ERROR) {
        std::cerr << "bind/listen failed: " << WSAGetLastError() << "\n";
        closesocket(listener);
        WSACleanup();
        return 1;
    }
    std::cout << "Listening on port 9000...\n";

    while (true) {
        SOCKET client = accept(listener, nullptr, nullptr);
        if (client == INVALID_SOCKET) {
            std::cerr << "accept failed: " << WSAGetLastError() << "\n";
            break;
        }

        // detach 表示线程独立运行；本例不需要等待它的返回值。
        std::thread(serve_client, client).detach();
    }

    closesocket(listener);
    WSACleanup();
}
```

这段代码刻意省略了完整错误处理，先把并发关系看清楚：主线程循环调用 `accept`，每拿到一个 `client` 就创建一个线程；工作线程只负责这个客户端。

### 这些 Windows/C++ 写法分别是什么意思

- `void serve_client(SOCKET client)`：普通函数，参数就是客户端 socket。`std::thread` 会在新线程中调用它。
- `std::thread(serve_client, client).detach()`：创建线程并传入 `client`；`detach` 后主线程不等待它结束。
- `closesocket`：释放客户端 socket。这个连接由工作线程负责，所以在线程处理结束时关闭它。`shutdown` 可以提前关闭收发方向，本例暂时省略。
- 原来的 `typedef struct { SOCKET client; } ClientContext` 不是 C++ 的“类”，而是 C 语言定义结构体类型并取名为 `ClientContext`。它是“打包参数”的办法：当线程函数只能接收一个 `void *` 指针、需要传多个参数，或需要传递更复杂的上下文时才有用。本例只有一个 `SOCKET`，因此不需要它。
- 原来的 `static unsigned __stdcall` 是 `_beginthreadex` 要求的 C 风格线程函数签名：`static` 限制函数只在当前文件使用，`unsigned` 是返回类型，`__stdcall` 是 Windows 调用约定。它不是并发概念本身，初学阶段可以先忽略。

原来的 C 版本中：

```c
done:
    shutdown(client, SD_BOTH);
    closesocket(client);
    return 0;
```

`done:` 只是一个标签，表示“所有退出路径最后都到这里做清理”。例如收不到数据、发送失败、对方断开，都需要关闭 socket；用一个统一出口可以避免重复写三遍清理代码。`goto done` 不是并发机制，只是旧 C 写法中的错误处理技巧。新手先掌握“结束前关闭自己拥有的 socket”即可。

## 6. Linux 实践：POSIX pthread + 一连接一线程

保存为 `server_linux.c`。程序结构和 Windows 版本相同，但 socket 类型、错误处理、线程创建和关闭函数来自 POSIX/Linux API。

```c
#include <arpa/inet.h>
#include <errno.h>
#include <netinet/in.h>
#include <pthread.h>
#include <signal.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/socket.h>
#include <unistd.h>

static void *serve_client(void *arg) {
    int client = *(int *)arg;
    char buffer[1024];
    free(arg);

    for (;;) {
        ssize_t received = recv(client, buffer, sizeof buffer, 0);
        if (received == 0) break;
        if (received < 0) {
            if (errno == EINTR) continue;
            break;
        }

        ssize_t sent = 0;
        while (sent < received) {
            ssize_t n = send(client, buffer + sent,
                             (size_t)(received - sent), MSG_NOSIGNAL);
            if (n < 0 && errno == EINTR) continue;
            if (n <= 0) goto done;
            sent += n;
        }
    }

done:
    shutdown(client, SHUT_RDWR);
    close(client);
    return NULL;
}

int main(void) {
    int listener = socket(AF_INET, SOCK_STREAM, 0);
    if (listener < 0) {
        perror("socket");
        return 1;
    }

    int reuse = 1;
    if (setsockopt(listener, SOL_SOCKET, SO_REUSEADDR, &reuse, sizeof reuse) < 0) {
        perror("setsockopt");
        close(listener);
        return 1;
    }

    struct sockaddr_in address;
    memset(&address, 0, sizeof address);
    address.sin_family = AF_INET;
    address.sin_port = htons(9000);
    address.sin_addr.s_addr = htonl(INADDR_ANY);

    if (bind(listener, (struct sockaddr *)&address, sizeof address) < 0 ||
        listen(listener, 128) < 0) {
        perror("bind/listen");
        close(listener);
        return 1;
    }

    /* 客户端意外断开时，让 send 返回错误而不是结束整个进程。 */
    signal(SIGPIPE, SIG_IGN);
    printf("Listening on port 9000...\n");

    for (;;) {
        int client = accept(listener, NULL, NULL);
        if (client < 0) {
            if (errno == EINTR) continue;
            perror("accept");
            continue;
        }

        int *arg = malloc(sizeof *arg);
        if (arg == NULL) {
            close(client);
            continue;
        }
        *arg = client;

        pthread_t thread;
        int error = pthread_create(&thread, NULL, serve_client, arg);
        if (error != 0) {
            fprintf(stderr, "pthread_create: %s\n", strerror(error));
            free(arg);
            close(client);
            continue;
        }
        pthread_detach(thread); /* 本例不 join；线程结束时自动回收线程资源 */
    }
}
```

### Linux 编译和运行

在终端进入源文件所在目录：

```sh
gcc -Wall -Wextra -O2 -pthread server_linux.c -o server_linux
./server_linux
```

另开一个终端，使用 `nc`（netcat）连接；部分发行版命令名是 `ncat`：

```sh
nc 127.0.0.1 9000
```

输入一行文字，回车后应收到服务器回显。再开一个终端执行同一连接命令，验证两个客户端可同时使用。按 `Ctrl+C` 结束客户端或服务器。

### 代码中值得注意的几件事

1. 主线程只负责 `accept` 新连接；工作线程负责对应客户端的 `recv`、`send` 和 `close`。
2. 每个工作者各自拥有一个客户端 socket，所以本例的连接收发状态不由多个线程共同修改。
3. `send` 可能只发送一部分字节，因此循环发送，直到本次收到的数据都已回送。
4. Linux 使用 `pthread_detach` 表示不等待 `pthread_join` 回收返回值。若不 detach 也不 join，线程结束后仍可能留下可回收资源。
5. 这是演示程序：没有最大线程数、优雅停机、超时策略、日志系统或生产级错误恢复。不要直接把它当成公网生产服务器。

## 7. 进程创建演示

这两个短程序展示各平台怎样创建另一个执行单元。它们不提供 socket 服务，目的是让你观察“创建后是另一个进程”，并练习等待子任务结束。

### Linux：`fork` 创建子进程

保存为 `process_linux.c`：

```c
#include <stdio.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <unistd.h>

int main(void) {
    pid_t child = fork();
    if (child < 0) {
        perror("fork");
        return 1;
    }
    if (child == 0) {
        printf("child: pid=%ld, parent=%ld\n",
               (long)getpid(), (long)getppid());
        return 0;
    }

    printf("parent: pid=%ld, child=%ld\n", (long)getpid(), (long)child);
    if (waitpid(child, NULL, 0) < 0) {
        perror("waitpid");
        return 1;
    }
    return 0;
}
```

运行：

```sh
gcc -Wall -Wextra process_linux.c -o process_linux
./process_linux
```

`fork()` 成功后，父进程得到子进程的 PID；子进程得到 `0`。两个进程都会从 `fork()` 后面继续运行。`waitpid` 让父进程等待子进程结束并回收其退出状态，避免留下僵尸进程记录。

### Windows：`CreateProcess` 启动子进程

保存为 `process_win.c`：

```c
#include <windows.h>
#include <stdio.h>

int main(void) {
    STARTUPINFOA startup = {0};
    PROCESS_INFORMATION process = {0};
    startup.cb = sizeof startup;
    char command[] = "cmd.exe /c echo child process";

    if (!CreateProcessA(NULL, command, NULL, NULL, FALSE, 0,
                        NULL, NULL, &startup, &process)) {
        fprintf(stderr, "CreateProcess failed: %lu\n", GetLastError());
        return 1;
    }

    WaitForSingleObject(process.hProcess, INFINITE);
    DWORD exit_code = 0;
    GetExitCodeProcess(process.hProcess, &exit_code);
    printf("child exit code: %lu\n", (unsigned long)exit_code);
    CloseHandle(process.hThread);
    CloseHandle(process.hProcess);
    return 0;
}
```

在 Visual Studio 开发者命令提示符中编译并运行：

```bat
cl /W4 process_win.c
process_win.exe
```

使用 MinGW-w64 GCC 时可改为：

```powershell
gcc -Wall -Wextra process_win.c -o process_win.exe
.\process_win.exe
```

Windows 的 `CreateProcess` 启动一个指定程序，父进程通过进程句柄等待并读取退出码，最后关闭句柄。它不像 Linux `fork` 那样复制当前执行位置并让父子分支从同一行继续。

## 8. 常见错误与排查

| 现象 | 常见原因 | 检查办法 |
|---|---|---|
| 第二个客户端连上后没响应 | 实际运行的是串行服务器，或工作线程启动失败 | 确认每次成功 `accept` 都创建了工作者；查看创建失败错误 |
| 客户端发消息但没有完整回显 | 把一次 `send` 当成必定发送全部数据 | 记录 `send` 返回值，并循环发送剩余字节 |
| Linux 程序收到客户端断开后直接退出 | 向已关闭连接 `send`，触发默认 `SIGPIPE` | 忽略 `SIGPIPE` 或采用适当的 `MSG_NOSIGNAL` 策略 |
| Linux 编译出现 pthread 未定义引用 | 编译时没有启用 pthread 支持 | 添加 `-pthread` 编译选项 |
| Windows 编译时报 Winsock 符号未定义 | 没链接 Winsock 库或头文件顺序错误 | 先包含 `winsock2.h`；链接 `Ws2_32.lib` |
| 报端口已被占用 | 上一次服务器还在运行，或其他程序占用 9000 | 结束旧服务器，或同时改服务器和客户端使用的端口 |
| 修改某个全局变量后结果偶尔不对 | 多线程无保护地读写共享数据 | 找出所有访问点，为完整操作加锁或改用原子操作 |
| 线程一多，速度反而下降 | 创建线程过多、栈和调度开销变大，或争锁严重 | 限制并发数；评估线程池或事件循环；测量而不是猜测 |
| Linux 父进程退出后仍看到子进程记录 | 父进程没有等待回收子进程 | 使用 `wait`/`waitpid`，或设计明确的子进程回收机制 |
| 线程偶发崩溃或读到乱码 | 传给线程的指针指向已失效/被改写的内存 | 检查参数对象的分配、所有权和释放时机 |

## 9. 如何选择模型

初学时可以按下面的问题逐项判断：

1. 同时只有少量客户端，主要目标是弄清 socket 流程吗？可以先用串行服务端，再改成一连接一线程对比。
2. 连接数量有限，且一个连接的处理逻辑需要顺序等待多个阻塞调用吗？一连接一线程通常容易实现。
3. 每个请求都是短任务，想控制同时执行的任务数吗？考虑线程池，并为任务队列设置容量。
4. 需要把不可信任务隔离，避免一个任务破坏其他任务的内存吗？可以评估多进程，但要考虑 IPC 和进程回收。
5. 需要维持很多长连接，而且连接大部分时间在等待网络吗？学习 I/O 多路复用和事件循环。
6. 工作主要是大量计算吗？线程数通常要结合 CPU 核数、计算量、锁竞争和实测调整；不要只按连接数创建线程。

即使选择了线程池或事件循环，理解线程、进程、所有权和竞态仍然必要，因为服务内部可能同时使用它们。

## 术语小抄

| 术语 | 简明解释 |
|---|---|
| 地址空间 | 一个进程可以使用的内存范围及其映射 |
| 栈（线程栈） | 保存函数调用和局部变量等临时执行信息的内存区域 |
| 文件描述符 | Linux 用小整数代表打开的文件、socket 等资源 |
| socket 句柄 | Windows 用来操作 socket 的标识；Windows socket 类型是 `SOCKET` |
| IPC | Inter-Process Communication，进程间通信 |
| 竞态条件 | 多个任务的执行顺序影响最终结果的错误风险 |
| 互斥锁 | 同一时间只允许一个线程进入某段临界代码的锁 |
| 临界区 | 访问共享数据、必须避免并发冲突的代码部分 |
| 僵尸进程 | 子进程已退出但父进程尚未读取退出状态，系统暂留其记录 |
| 背压 | 下游处理不过来时，限制或拒绝上游继续提交工作 |
