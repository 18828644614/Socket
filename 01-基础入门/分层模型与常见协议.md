# 分层模型与常见协议

## 学习目标

- [ ] 理解网络为什么要采用分层设计
- [ ] 能够说出 OSI 七层模型与 TCP/IP 模型的大致对应关系
- [ ] 知道 Ethernet、ARP、IP、ICMP、TCP、UDP、DNS、HTTP、TLS 等协议分别解决什么问题
- [ ] 理解一次网络通信中数据如何逐层封装、发送和解封装
- [ ] 能够把 Socket 编程放到整个网络协议栈中定位

## 章节

### 分层思想

网络通信不是由一个协议独立完成的，而是由许多职责不同的协议共同协作。例如，程序只关心“发送一条消息”，但系统还需要解决以下问题：

- 消息应该交给哪台主机
- 局域网中下一跳设备是谁
- 数据如何在不可靠的网络中到达目标
- 数据到达后应该交给哪个程序
- 不同程序发送的内容如何区分格式

分层就是把这些问题拆开。每一层只负责一组相对独立的工作，并通过约定好的接口为上层提供服务。

可以把它类比成寄快递：应用层决定包裹里装什么，传输层负责一次寄送的可靠性，网络层填写目的地，链路层负责在当前道路上把包裹交给下一站。每一层都会增加自己需要的“说明信息”，接收端再按相反顺序去掉这些说明。

分层带来三个重要好处：

1. **降低复杂度**：应用程序不需要自己实现网线传输、路由选择和重传机制。
2. **便于替换**：例如 TCP 和 UDP 都可以为同一个应用提供传输服务，应用层不必理解网卡的具体工作方式。
3. **便于排查问题**：可以分别判断是应用协议、传输连接、IP 路由，还是物理链路出了问题。

分层并不表示每层完全隔离。上层会使用下层提供的服务，下层通常不知道上层具体传输了什么业务内容。

### 常见协议的位置

学习 Socket 时，最常接触的是 TCP/IP 协议栈。不同教材的名称略有差异，实际工程中可以先使用下面这套简化模型：

| TCP/IP 常用分层 | 常见职责 | 常见协议或技术 | Socket 编程中的关系 |
|---|---|---|---|
| 应用层 | 定义业务消息的含义和格式 | HTTP、HTTPS、DNS、DHCP、SSH、FTP | 你编写的请求、响应和自定义协议通常属于这一层 |
| 传输层 | 端到端传输、端口、可靠性或低延迟 | TCP、UDP | `socket()` 的 `SOCK_STREAM` 和 `SOCK_DGRAM` 分别对应常见的 TCP、UDP 用法 |
| 网际层 | 使用 IP 地址进行跨网络寻址和路由 | IPv4、IPv6、ICMP | 操作系统根据 IP 路由表决定数据向哪里转发 |
| 网络接口层 | 在同一链路上传输帧，处理网卡和局域网寻址 | Ethernet、Wi-Fi、ARP | 通常由网卡、驱动和内核处理，应用程序一般不直接操作 |

有些资料把网络接口层拆成“数据链路层”和“物理层”，有些资料把应用层继续拆成会话层、表示层和应用层。这些划分方式不同，但解决的问题大体相同。

#### OSI 七层模型与 TCP/IP 模型

OSI 模型是一种帮助理解网络的理论模型，共七层：

1. 物理层：传输比特，关注电信号、光信号、无线信号和接口规范。
2. 数据链路层：在同一网络链路上传输帧，使用 MAC 地址等概念。
3. 网络层：使用逻辑地址跨网络传输数据，典型协议是 IP。
4. 传输层：为两个主机上的程序提供端到端通信，典型协议是 TCP、UDP。
5. 会话层：管理会话的建立、维持和结束。
6. 表示层：处理编码、压缩、加密和数据表示。
7. 应用层：直接服务于应用程序，定义业务协议。

实际编程时，TCP/IP 模型更实用。它通常把 OSI 的会话层、表示层和应用层合并为应用层，把物理层和数据链路层合并为网络接口层：

| OSI | TCP/IP 简化模型 | 例子 |
|---|---|---|
| 应用层、表示层、会话层 | 应用层 | HTTP、DNS、TLS、SSH |
| 传输层 | 传输层 | TCP、UDP |
| 网络层 | 网际层 | IPv4、IPv6、ICMP |
| 数据链路层、物理层 | 网络接口层 | Ethernet、Wi-Fi、ARP |

不要把模型层数当成必须背诵的分类。更重要的是，当看到一个协议时，能够回答“它解决什么问题、使用什么地址、它的上层和下层是谁”。

#### 常见协议分别解决什么问题

##### 网络接口层：Ethernet、Wi-Fi、ARP

- **Ethernet（以太网）**：规定局域网中如何组织数据帧，以及网卡如何在有线网络上传输数据。
- **Wi-Fi**：提供无线局域网通信方式，可以把它看成与以太网处于相近层次的另一种链路技术。
- **MAC 地址**：网卡在局域网链路上的硬件地址，主要用于当前链路中的设备识别。
- **ARP**：把同一局域网内的 IPv4 地址转换为 MAC 地址。例如主机知道网关 IP，却不知道网关网卡地址时，会通过 ARP 查询。

这里容易混淆的一点是：IP 地址用于跨网络定位，MAC 地址用于当前一跳的链路传输。数据经过路由器时，IP 数据包通常继续指向最终目标，但链路层帧的源 MAC 和目的 MAC 会随着每一跳改变。

##### 网际层：IP 与 ICMP

- **IPv4/IPv6**：为数据包提供逻辑地址和跨网络转发能力。IP 本身尽力而为，不保证数据一定到达、不重复，也不保证顺序。
- **ICMP**：传递网络控制和错误信息。`ping` 常使用 ICMP Echo 请求和响应测试可达性；`traceroute` 也会利用 ICMP 或 UDP 与 TTL 的配合观察路径。

IP 不负责“这个数据包属于哪个程序”。到达目标主机后，还需要传输层的端口把数据交给具体进程。

##### 传输层：TCP 与 UDP

- **TCP**：面向连接，提供可靠、有序、无重复的字节流。它会处理确认、重传、流量控制和拥塞控制，但不会保留应用层的消息边界。
- **UDP**：无连接、尽力而为，以数据报为单位发送。它开销较小、延迟通常较低，但不保证到达、顺序和唯一性。

TCP 和 UDP 都使用端口区分进程。例如 `192.168.1.10:8080` 中，IP 地址定位主机，`8080` 定位主机上的服务。

“TCP 可靠”不等于“业务一定成功”。TCP 只能保证已经交给它的字节在连接语义下尽力可靠地到达；服务器是否正确处理请求、是否完成数据库写入，仍然需要应用层确认。

##### 应用层：DNS、HTTP、HTTPS、DHCP、SSH

- **DNS**：把域名解析为 IP 地址，例如把 `example.com` 查询为 IPv4 或 IPv6 地址。DNS 通常使用 UDP，也可能使用 TCP 或加密传输方式。
- **HTTP**：定义 Web 客户端与服务器之间的请求、响应、方法、状态码和头部等规则。HTTP 本身可以运行在 TCP 之上。
- **HTTPS**：通常表示 HTTP over TLS。TLS 负责加密、完整性校验和服务器身份认证，HTTP 负责业务消息格式。
- **DHCP**：帮助主机自动获取 IP 地址、子网掩码、默认网关和 DNS 服务器等网络配置。
- **SSH**：提供加密的远程登录和命令执行能力。

应用层协议不一定必须是标准协议。你也可以在 TCP 或 UDP 之上设计自己的协议，例如“4 字节长度 + 消息类型 + JSON 内容”。

### 数据封装与解封装

发送端从上到下封装，接收端从下到上解封装。以“浏览器通过 HTTPS 请求服务器”为例：

```text
应用层：HTTP 请求
        ↓ 加入 TLS 加密和校验信息
表示/安全相关处理：TLS 数据
        ↓ 加入 TCP 头部（源端口、目的端口、序号等）
传输层：TCP 段
        ↓ 加入 IP 头部（源 IP、目的 IP、TTL 等）
网际层：IP 数据包
        ↓ 加入 Ethernet/Wi-Fi 头部和尾部（源 MAC、目的 MAC 等）
网络接口层：链路帧
        ↓ 转换为信号，经网卡和网络设备发送
```

接收端会执行相反过程：网卡收到帧后交给内核，内核检查链路层信息和 IP 信息，再根据 TCP 端口找到对应 Socket，最后把应用数据交给程序。

#### “数据、段、包、帧”分别是什么

这些名称主要是从不同层观察同一份数据：

| 观察层次 | 常见称呼 | 说明 |
|---|---|---|
| 应用层 | 消息或数据 | 例如一条 HTTP 请求或自定义命令 |
| TCP | TCP 段（segment） | TCP 头部加上应用数据 |
| UDP | UDP 数据报（datagram） | UDP 头部加上一次发送的数据 |
| IP | IP 包/数据报（packet） | IP 头部加上传输层内容 |
| 链路层 | 帧（frame） | 链路层头部、IP 包和链路层尾部 |

不要因为名字不同就认为它们一定是完全不同的内容。通常是“上一层的数据”被下一层当作负载，再加上当前层的头部。

#### 一个请求的完整路径

访问 `https://example.com` 时，可以按下面的顺序理解：

1. 应用先询问 DNS，获得服务器 IP 地址。
2. 客户端与服务器的 IP 和端口建立 TCP 连接。
3. 在 TCP 连接上进行 TLS 握手，协商加密参数并验证证书。
4. 客户端发送 HTTP 请求，服务器返回 HTTP 响应。
5. 每一次发送都会经过 TCP、IP 和链路层的封装；服务器收到后逐层解封装。
6. 如果目标地址不在本地局域网，客户端会先把链路帧交给默认网关，路由器再转发 IP 包。

这里的 DNS、TCP、TLS、HTTP 是多个不同层次的协议，它们不是互相替代的关系，而是上下叠加的关系：DNS 解决“找到谁”，TCP 解决“如何可靠传输”，TLS 解决“如何安全传输”，HTTP 解决“传输什么业务内容”。

### Socket 在协议栈中的位置

Socket 是操作系统向应用程序提供的通信接口，不是一个独立的网络协议。程序通过 Socket 调用内核，例如创建 Socket、绑定地址、监听、连接、发送和接收。内核再负责调用 TCP/UDP、IP 以及网卡驱动完成实际通信。

可以用下面的关系定位 Socket：

```text
你的程序
  ↓ read/write、send/recv
Socket API
  ↓
操作系统网络协议栈
  ↓
TCP 或 UDP
  ↓
IP
  ↓
Ethernet / Wi-Fi / 网卡
```

因此，学习 Socket 时既要学习 API 的调用顺序，也要理解 API 背后的协议行为。例如：

- TCP Socket 的 `recv()` 返回 0，通常表示对端已经有序关闭连接，而不是收到一条空消息。
- TCP 的一次 `send()` 不一定对应对端的一次 `recv()`，因为 TCP 提供的是字节流，不保留消息边界。
- UDP 的一次发送通常对应一个数据报，但数据报可能丢失、重复或乱序。
- `connect()` 对 TCP 通常意味着建立连接；对 UDP 则可以只记录默认对端地址，并不代表完成握手。
