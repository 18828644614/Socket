# 连接生命周期

## 学习目标

学完本章后，你应该能够：

- 说出 TCP 连接从创建、建立、通信到关闭的大致过程。
- 区分服务器的监听 Socket 和 `accept()` 返回的客户端 Socket。
- 看懂 TCP 三次握手、四次挥手，以及 `recv()` 返回 `0` 的含义。
- 区分正常关闭、复位（RST）、超时和进程崩溃等不同断开方式。
- 在 Linux 和 Windows 上正确关闭 Socket，并在错误路径中释放资源。
- 设计一个不会快速空转、不会泄漏旧连接的简单重连流程。

## 1. 先建立一个整体模型

TCP Socket 的生命周期可以先记成下面这条主线：

~~~text
socket() 创建通信对象
        ↓
客户端 connect()       服务器 bind() → listen()
        ↓                         ↓
      已连接 ←────────────── accept()
        ↓
      send()/recv() 交换字节
        ↓
      close() 或 shutdown()
        ↓
      连接结束，释放本地资源
~~~

这里有一个初学者最容易混淆的地方：服务器通常有两类 Socket。

| Socket | 来源 | 作用 | 是否用于 `recv()` 客户端数据 |
| --- | --- | --- | --- |
| 监听 Socket | `socket()` → `bind()` → `listen()` | 等待新的连接 | 否 |
| 连接 Socket | `accept()` 返回 | 与某一个客户端通信 | 是 |

`accept()` 成功一次，就会得到一个新的连接 Socket。监听 Socket 继续保留，等待下一位客户端；连接 Socket 则只属于当前客户端。服务器关闭客户端连接时，关闭的是连接 Socket，而不是监听 Socket。

客户端通常只有一个主要 Socket：`socket()` 创建它，`connect()` 让它连接服务器，之后使用它收发数据。

## 2. 生命周期中的几个状态

可以把一个连接想象成一个状态机：

~~~text
                connect 成功
     CREATED ─────────────────→ ESTABLISHED
        │                              │
        │ connect 失败                 │ close / 对端关闭
        ↓                              ↓
      CLOSED ←────── FIN/RST/错误 ─── CLOSING
~~~

这些名称是帮助理解的抽象，不要求程序自己保存一个完全相同的枚举。真正的 TCP 状态由操作系统内核维护，程序通过 API 返回值和事件观察它。

常见状态可以这样理解：

- `CREATED`：`socket()` 已成功，但还没有建立 TCP 连接。
- `LISTENING`：服务器监听 Socket 已经 `bind()`、`listen()`，正在等待客户端。
- `ESTABLISHED`：TCP 握手成功，双方都可以传输字节。
- `HALF-CLOSED`：一方已经不再发送，但仍可能接收对方的数据。
- `CLOSING`：某一方正在完成关闭过程。
- `CLOSED`：应用不再使用这个 Socket；本地句柄可以释放。

不要把“程序调用了 `close()`”和“网络上的所有数据瞬间消失”画等号。关闭涉及内核发送缓冲区、FIN/RST、对端处理以及一段时间的 TCP 状态维护。

## 3. 建立连接：从 `socket()` 到 `ESTABLISHED`

### 3.1 创建 Socket 还不等于连接成功

Linux：

~~~c
int fd = socket(AF_INET, SOCK_STREAM, 0);
if (fd == -1) {
    perror("socket");
    return 1;
}
~~~

Windows Winsock：

~~~c
SOCKET sock = socket(AF_INET, SOCK_STREAM, IPPROTO_TCP);
if (sock == INVALID_SOCKET) {
    printf("socket failed: %d\n", WSAGetLastError());
    return 1;
}
~~~

`socket()` 只是向操作系统申请一个通信对象。此时它还没有和具体服务器建立 TCP 连接，因此不能认为“已经在线”。

Windows 还必须先调用一次 `WSAStartup()`：

~~~c
WSADATA data;
int result = WSAStartup(MAKEWORD(2, 2), &data);
if (result != 0) {
    printf("WSAStartup failed: %d\n", result);
    return 1;
}
~~~

### 3.2 服务器的准备过程

服务器要先把一个本地地址交给内核，并进入监听状态：

~~~text
socket()
   ↓ 创建监听 Socket
bind()
   ↓ 绑定本地 IP 和端口，例如 127.0.0.1:8080
listen()
   ↓ 进入监听状态
accept()
   ↓ 得到某一个客户端专属的连接 Socket
recv()/send()
~~~

`listen()` 成功后，服务器才真正准备好接受 TCP 连接。只调用 `socket()` 或 `bind()`，客户端仍然可能无法连接。

### 3.3 客户端的连接过程

客户端准备好服务器地址后调用：

~~~c
connect(fd,
        (const struct sockaddr *)&server_addr,
        sizeof server_addr);
~~~

阻塞模式下，`connect()` 通常会等待握手结果：成功返回 `0`，失败返回错误。成功之后，才进入可以正常收发的 `ESTABLISHED` 状态。

### 3.4 TCP 三次握手到底做了什么

TCP 连接建立通常包含三个关键报文：

~~~text
客户端                                      服务器
   | -------- SYN：我想建立连接 ----------> |
   | <--- SYN + ACK：我收到，也同意 ------- |
   | -------- ACK：我确认收到 ------------> |
   |                                        |
   |          连接进入 ESTABLISHED          |
~~~

初学者可以把它理解为一次“双方确认”：

1. 客户端表示自己想连接，并给出初始序列号。
2. 服务器确认客户端的请求，同时告诉客户端服务器自己的初始序列号。
3. 客户端确认服务器的序列号。

序列号用于后续的可靠传输和数据排序。程序通常不需要自己构造这三个报文，内核 TCP 协议栈会完成它们；程序只负责调用 `connect()`、`listen()` 和 `accept()`。

如果服务器端口没有监听，系统可能很快返回“连接被拒绝”；如果数据包被防火墙丢弃或路由不可达，`connect()` 可能等待较久后才超时。两者都属于“建立阶段失败”，不要把它们都简单归结为“代码有问题”。

## 4. 建立后通信：`send()` 和 `recv()`

连接进入 `ESTABLISHED` 后，双方通过连接 Socket 交换字节：

~~~text
客户端 send() → TCP 发送缓冲区 → 网络 → TCP 接收缓冲区 → 服务器 recv()
服务器 send() → TCP 发送缓冲区 → 网络 → TCP 接收缓冲区 → 客户端 recv()
~~~

有三条规则必须牢记：

### 4.1 `send()` 成功不等于对方已经处理

`send()` 返回正数，通常只表示本机内核已经接受了这些字节。它不保证：

- 对方应用程序已经调用 `recv()`；
- 对方已经读取了完整数据；
- 对方已经完成业务处理。

如果业务需要确认，应设计应用层响应，例如客户端发送请求后，服务器返回 `OK` 或带请求编号的结果。

### 4.2 一次 `send()` 不对应一次 `recv()`

TCP 是字节流，不保存应用层调用边界：

~~~c
send(fd, "HELLO", 5, 0);
send(fd, "WORLD", 5, 0);
~~~

对方可能读到：

~~~text
HELLOWORLD
HEL / LOWO / RLD
HELLO / WORLD
~~~

这些结果都可能是正确的。应用层必须规定消息边界，例如换行符、固定长度或“长度前缀 + 内容”。

### 4.3 `recv()` 的返回值表示什么

~~~text
返回值 > 0   读到了这么多个字节
返回值 == 0  对端有序关闭了发送方向
返回值 < 0   发生错误（Windows 通常是 SOCKET_ERROR）
~~~

`recv() == 0` 不是“暂时没有数据”。阻塞模式下，暂时没有数据时 `recv()` 会继续等待；返回 `0` 表示对端已经发送 FIN，按照 TCP 语义，对端不会再发送新的字节。

## 5. 正常关闭：FIN、`close()` 和 `recv() == 0`

### 5.1 四次挥手的直观过程

TCP 是全双工连接，两个方向可以分别关闭。因此正常关闭常被画成四个步骤：

~~~text
主动关闭方                                  被动关闭方
   | -------- FIN：我不再发送 -----------> |
   | <--------------- ACK ---------------- |
   | <-------- FIN：我也不再发送 --------- |
   | ---------------- ACK ---------------> |
~~~

实际抓包时，ACK 和 FIN 在某些情况下可能合并，时间顺序也可能因延迟而不同，但“两个方向分别结束”这个核心概念不变。

当对端关闭发送方向后，本端的 `recv()` 会返回 `0`。服务器通常应该结束当前会话并关闭对应的连接 Socket：

~~~c
int n = recv(client_fd, buffer, sizeof buffer, 0);
if (n == 0) {
    // 对端正常关闭；不要继续对这个方向调用 recv() 等数据
    close(client_fd);             // Linux
    // closesocket(client_sock);  // Windows
}
~~~

### 5.2 `close()` 的平台差异

| 操作 | Linux/POSIX | Windows Winsock |
| --- | --- | --- |
| Socket 类型 | `int` | `SOCKET` |
| 创建失败 | `-1` | `INVALID_SOCKET` |
| 关闭连接 | `close(fd)` | `closesocket(sock)` |
| 初始化 | 通常不需要 | `WSAStartup()` |
| 库清理 | 无对应调用 | 最后调用 `WSACleanup()` |
| 错误获取 | `errno`、`perror()` | `WSAGetLastError()` |

Windows 下，`closesocket()` 和 `WSACleanup()` 不是一回事：前者关闭某一个 Socket，后者减少 Winsock 初始化引用。程序通常按下面的顺序结束：

~~~text
closesocket(客户端或监听 Socket)
        ↓
WSACleanup()
~~~

### 5.3 `shutdown()`：只关闭一个方向

有时程序已经发送完请求，但还想继续接收服务器的响应，这时可以半关闭：

Linux：

~~~c
shutdown(fd, SHUT_WR);     // 不再发送，但仍可 recv()
~~~

Windows：

~~~c
shutdown(sock, SD_SEND);   // 不再发送，但仍可 recv()
~~~

这会让对方看到“发送方向结束”（通常最终表现为对方 `recv()` 返回 `0`），但本端仍然可以读取对方尚未发送完的数据。它适合“请求发送结束后，服务器继续返回结果”的协议。

不要把 `shutdown()` 当成资源释放函数。它只改变通信方向或连接状态；最后仍然需要 `close()`/`closesocket()`。

## 6. 异常断开：并不是所有断开都有 FIN

### 6.1 常见异常类型

| 情况 | 常见表现 | 程序应该关注什么 |
| --- | --- | --- |
| 对端正常退出 | `recv()` 返回 `0` | 释放会话资源，必要时重连 |
| 对端强制复位 | `recv()` 或 `send()` 返回错误，常见为 connection reset | 丢弃当前连接状态，不能继续使用旧 Socket |
| 网络中断 | 一段时间没有任何结果，最终超时 | 设置超时、心跳或 TCP keepalive |
| 对端进程崩溃 | 可能收到 RST，也可能暂时没有可观察事件 | 不要只依赖“进程是否还活着”判断连接 |
| 本端进程退出 | 操作系统关闭其 Socket | 服务器会观察到 FIN 或 RST |
| 本端发送到已关闭连接 | Linux 可能遇到 `SIGPIPE`/`EPIPE` | 忽略或处理 `SIGPIPE`，检查 `send()` 返回值 |

### 6.2 为什么“拔网线”不一定马上发现

TCP 只能根据它收到的报文判断状态。如果网络路径完全消失，而双方都没有新的数据或探测报文，程序可能暂时看不到错误：

~~~text
连接曾经 ESTABLISHED
        ↓
网络突然中断，但没有 FIN/RST 到达
        ↓
双方可能都暂时认为连接仍存在
        ↓
数据发送重试、应用层心跳或 TCP keepalive 触发后才发现问题
~~~

所以，“Socket 仍然打开”不等于“对端一定在线”。实时业务通常会使用应用层心跳；普通业务至少要为关键读写设置合理超时。

### 6.3 Linux 的 `SIGPIPE`

Linux 上向已经关闭的连接发送数据时，除了 `send()` 可能返回 `EPIPE`，进程还可能收到 `SIGPIPE`，默认行为是终止进程。学习示例可以这样处理：

~~~c
#include <signal.h>

signal(SIGPIPE, SIG_IGN);
~~~

然后仍然必须检查 `send()` 的返回值。忽略信号不能让已经断开的连接恢复，只是让程序有机会记录错误并关闭当前连接，而不是整个进程退出。

Windows 没有这个 Linux 默认行为，但仍必须检查 `send()` 返回值和 `WSAGetLastError()`。

## 7. Linux/POSIX：一个观察生命周期的客户端

下面的程序连接本机 `127.0.0.1:8080`，发送一行文本，读取服务器回显，然后主动关闭。它假设服务器是回显服务器；服务器不回复时，程序会停在 `recv()`，这属于协议行为，不是生命周期代码自动出错。

~~~c
#include <arpa/inet.h>
#include <errno.h>
#include <signal.h>
#include <stdio.h>
#include <string.h>
#include <sys/socket.h>
#include <unistd.h>

static int send_all(int fd, const char *data, size_t length) {
    size_t sent = 0;
    while (sent < length) {
        ssize_t n = send(fd, data + sent, length - sent, 0);
        if (n > 0) {
            sent += (size_t)n;
        } else if (n < 0 && errno == EINTR) {
            continue;
        } else {
            perror("send");
            return -1;
        }
    }
    return 0;
}

int main(void) {
    signal(SIGPIPE, SIG_IGN);

    int fd = socket(AF_INET, SOCK_STREAM, 0);
    if (fd == -1) {
        perror("socket");
        return 1;
    }
    printf("[1] socket created\n");

    struct sockaddr_in address = {0};
    address.sin_family = AF_INET;
    address.sin_port = htons(8080);
    if (inet_pton(AF_INET, "127.0.0.1", &address.sin_addr) != 1) {
        fprintf(stderr, "invalid address\n");
        close(fd);
        return 1;
    }

    if (connect(fd, (struct sockaddr *)&address, sizeof address) == -1) {
        perror("connect");
        close(fd);
        return 1;
    }
    printf("[2] connected\n");

    const char message[] = "hello from Linux\n";
    if (send_all(fd, message, strlen(message)) == -1) {
        close(fd);
        return 1;
    }
    printf("[3] request sent\n");

    char buffer[256];
    ssize_t n = recv(fd, buffer, sizeof buffer - 1, 0);
    if (n > 0) {
        buffer[n] = '\0';
        printf("[4] received: %s", buffer);
    } else if (n == 0) {
        printf("[4] server closed normally\n");
    } else {
        perror("recv");
    }

    shutdown(fd, SHUT_RDWR);     // 可选：明确结束两个方向
    close(fd);                    // 释放文件描述符
    printf("[5] client closed\n");
    return n < 0 ? 1 : 0;
}
~~~

编译和运行：

~~~bash
gcc -Wall -Wextra -Wpedantic -g lifecycle_client.c -o lifecycle_client
./lifecycle_client
~~~

逐步看这个示例：

1. `socket()` 成功只说明本地对象创建成功。
2. `connect()` 成功才说明 TCP 握手完成。
3. `send_all()` 用循环处理部分发送。
4. `recv()` 正数表示读到字节，`0` 表示服务器已关闭发送方向，负数表示错误。
5. `shutdown()` 是可选的状态操作，`close()` 才是释放本地描述符的关键步骤。

## 8. Windows Winsock：对应的生命周期客户端

下面的 Windows 版本完成同样的流程。注意 `SOCKET` 不能用 `-1` 判断失败，关闭时必须使用 `closesocket()`。

~~~c
#include <winsock2.h>
#include <stdio.h>
#include <string.h>

#pragma comment(lib, "Ws2_32.lib")

static int send_all(SOCKET sock, const char *data, int length) {
    int sent = 0;
    while (sent < length) {
        int n = send(sock, data + sent, length - sent, 0);
        if (n > 0) {
            sent += n;
        } else {
            printf("send failed: %d\n", WSAGetLastError());
            return -1;
        }
    }
    return 0;
}

int main(void) {
    WSADATA wsa_data;
    int result = WSAStartup(MAKEWORD(2, 2), &wsa_data);
    if (result != 0) {
        printf("WSAStartup failed: %d\n", result);
        return 1;
    }

    SOCKET sock = socket(AF_INET, SOCK_STREAM, IPPROTO_TCP);
    if (sock == INVALID_SOCKET) {
        printf("socket failed: %d\n", WSAGetLastError());
        WSACleanup();
        return 1;
    }
    printf("[1] socket created\n");

    struct sockaddr_in address = {0};
    address.sin_family = AF_INET;
    address.sin_port = htons(8080);
    address.sin_addr.s_addr = htonl(INADDR_LOOPBACK);

    if (connect(sock, (const struct sockaddr *)&address,
                sizeof address) == SOCKET_ERROR) {
        printf("connect failed: %d\n", WSAGetLastError());
        closesocket(sock);
        WSACleanup();
        return 1;
    }
    printf("[2] connected\n");

    const char message[] = "hello from Windows\n";
    if (send_all(sock, message, (int)strlen(message)) == -1) {
        closesocket(sock);
        WSACleanup();
        return 1;
    }
    printf("[3] request sent\n");

    char buffer[256];
    int n = recv(sock, buffer, (int)sizeof buffer - 1, 0);
    if (n > 0) {
        buffer[n] = '\0';
        printf("[4] received: %s", buffer);
    } else if (n == 0) {
        printf("[4] server closed normally\n");
    } else {
        printf("recv failed: %d\n", WSAGetLastError());
    }

    shutdown(sock, SD_BOTH);     // 可选：明确结束两个方向
    closesocket(sock);           // 释放 Socket
    WSACleanup();                // 清理 Winsock
    printf("[5] client closed\n");
    return n == SOCKET_ERROR ? 1 : 0;
}
~~~

编译：

~~~powershell
# MinGW-w64
gcc -Wall -Wextra -g lifecycle_client_win.c -o lifecycle_client_win.exe -lws2_32

# Visual Studio Developer PowerShell
cl /W4 /Zi lifecycle_client_win.c
~~~

这两份客户端的流程完全相同，差异主要来自操作系统接口：

~~~text
Linux:   socket → connect → send/recv → shutdown → close
Windows: WSAStartup → socket → connect → send/recv
         → shutdown → closesocket → WSACleanup
~~~

## 9. 一个最小服务器如何观察生命周期

客户端示例需要一个回显服务器。服务器在生命周期上的核心逻辑如下。

### 9.1 Linux/POSIX 关键部分

~~~c
int listen_fd = socket(AF_INET, SOCK_STREAM, 0);
// bind(listen_fd, ...);
// listen(listen_fd, 16);

for (;;) {
    int client_fd = accept(listen_fd, NULL, NULL);
    if (client_fd == -1) {
        perror("accept");
        continue;
    }

    for (;;) {
        char buffer[1024];
        ssize_t n = recv(client_fd, buffer, sizeof buffer, 0);
        if (n > 0) {
            send(client_fd, buffer, (size_t)n, 0);
        } else if (n == 0) {
            // 客户端发送 FIN：本次会话正常结束
            break;
        } else {
            // 记录 errno；当前连接通常不能再继续使用
            break;
        }
    }
    close(client_fd);       // 只关闭当前客户端
}

close(listen_fd);           // 服务器最终退出时才关闭监听 Socket
~~~

### 9.2 Windows Winsock 关键部分

~~~c
SOCKET client_sock = accept(listen_sock, NULL, NULL);
if (client_sock == INVALID_SOCKET) {
    printf("accept failed: %d\n", WSAGetLastError());
    return 1;
}

for (;;) {
    char buffer[1024];
    int n = recv(client_sock, buffer, sizeof buffer, 0);
    if (n > 0) {
        send(client_sock, buffer, n, 0);
    } else if (n == 0) {
        // 客户端正常关闭发送方向
        break;
    } else {
        printf("recv failed: %d\n", WSAGetLastError());
        break;
    }
}

closesocket(client_sock);  // 当前客户端结束
// 监听 Socket 仍然可以继续 accept()
~~~

初学阶段建议先实现“一个客户端结束后，再处理下一个客户端”的串行服务器。等理解连接 Socket 的创建和销毁后，再学习线程、`select()`、`poll()` 或 `epoll()`。

## 10. 重连：把连接当成可重复创建的资源

网络客户端不能假设一条 TCP 连接永远有效。常见重连流程是：

~~~text
连接失败或已断开
        ↓
停止使用旧 Socket
        ↓
shutdown（如适用）+ close/closesocket
        ↓
等待一段时间
        ↓
重新 socket()
        ↓
重新 connect()
        ↓
成功：回到通信状态
失败：增加等待时间后再次尝试
~~~

### 10.1 为什么不能对同一个坏 Socket 反复 `connect()`

一个连接 Socket 一旦经历了连接失败、复位或关闭，里面可能仍然保存着旧的 TCP 状态。最容易理解、最稳妥的做法是关闭它，再创建一个新的 Socket：

~~~c
// 伪代码：Linux 使用 close，Windows 使用 closesocket
while (!connected) {
    sock = socket(...);
    if (connect(sock, ...) == success) {
        connected = 1;
        break;
    }
    close_or_closesocket(sock);
    sleep_before_retry();
}
~~~

### 10.2 重连等待时间

不要在失败后立即无限循环：

~~~c
// 不推荐：失败时可能占满一个 CPU 核
for (;;) {
    if (connect(sock, ...) == -1) {
        continue;
    }
}
~~~

可以采用逐渐增加的等待时间，例如 1 秒、2 秒、4 秒，达到上限后保持在 30 秒左右；也可以在等待时间上加入少量随机抖动，避免很多客户端同时启动时一起冲击服务器。这种策略常称为“指数退避”。

### 10.3 重连后要重新做什么

重连成功只代表 TCP 通道重新建立，不代表应用层会话已经恢复。客户端通常还要重新：

- 登录或认证；
- 发送订阅、房间加入等状态；
- 确认上一次请求是否已经处理，避免重复扣款或重复写入；
- 清理旧连接上未完成的请求。

因此，应用层请求最好有唯一编号，服务器操作尽量设计成可重试或幂等。TCP 负责可靠传输字节，不负责替你保证“业务操作只执行一次”。

## 11. 资源回收：每条路径都要有出口

Socket 是有限系统资源。常见泄漏方式包括：

- `socket()` 成功后，地址转换或 `connect()` 失败，却忘记关闭。
- `accept()` 得到的连接 Socket 关闭了，但监听 Socket 永远不关闭。
- Windows 调用了 `closesocket()`，却在程序结束时遗漏 `WSACleanup()`。
- 发生异常或提前 `return` 时跳过清理代码。
- 重连时创建新 Socket，却把旧 Socket 的句柄覆盖掉。

推荐按“谁创建，谁负责最终释放”的思路组织代码：

~~~text
创建监听 Socket ───────────────→ 服务器退出时关闭
accept() 创建连接 Socket ──────→ 当前会话结束时关闭
connect() 创建客户端 Socket ───→ 连接失败或会话结束时关闭
WSAStartup() ──────────────────→ 配对 WSACleanup()
~~~

Linux 可以使用 `close()`；Windows 必须使用 `closesocket()`。不要把有效的 Windows `SOCKET` 强制转换成 `int` 后调用 `close()`。

排查泄漏时可以观察进程打开的句柄数量：

~~~bash
# Linux：查看某个进程打开的文件描述符
ls /proc/<PID>/fd | wc -l
~~~

~~~powershell
# Windows：查看监听和连接状态
Get-NetTCPConnection -State Listen,Established
~~~

## 12. 关闭与异常处理的推荐模板

处理一个连接时，可以按下面的顺序思考：

~~~text
1. 建立成功后记录连接信息
2. 循环 recv()
3. n > 0：累计/解析/处理数据
4. n == 0：记录正常关闭，结束会话
5. n < 0：记录平台错误码，判断是否可重试
6. 发送时检查部分发送和发送错误
7. 离开会话函数前关闭连接 Socket
8. 服务器最终退出时关闭监听 Socket
~~~

不要只用一个布尔变量 `connected = true` 表示所有情况。至少要区分：

- 是否已经成功创建 Socket；
- 是否已经建立 TCP 连接；
- 是否仍允许发送；
- 是否仍允许接收；
- 是否已经完成本地资源释放。

这些状态在简单程序里可以由控制流程表达；在聊天室、代理服务器等较大程序里，通常会显式建模为连接状态机。

## 13. 常见误区

### 误区一：`connect()` 成功后连接永远不会断

TCP 只能说明握手在某一时刻成功。之后仍可能因为对端关闭、服务器崩溃、网络中断、防火墙策略或超时而失效。应用程序要处理读写错误和 `recv() == 0`。

### 误区二：`recv()` 返回 `0` 只是暂时没数据

阻塞 Socket 暂时没数据会继续等待；返回 `0` 表示对端已关闭发送方向。非阻塞模式下“暂时没数据”通常表现为 `EAGAIN`/`EWOULDBLOCK`（Windows 常见 `WSAEWOULDBLOCK`），不是 `0`。

### 误区三：关闭客户端连接就应该关闭监听 Socket

监听 Socket 属于服务器整体；连接 Socket 属于某一个客户端。前者要一直保留到服务器停止，后者在一个客户端会话结束时关闭。

### 误区四：`send()` 一次成功就发送完了

返回值可能小于请求长度。发送文件、长文本或协议帧时要循环发送剩余部分。

### 误区五：立即重连一定更快恢复

快速重试会占用 CPU、制造日志噪声，并可能让服务器或网络设备承受不必要压力。关闭旧连接、等待、退避重试通常更可靠。

## 实践

### 实践一：观察正常关闭

1. 启动一个监听 `127.0.0.1:8080` 的回显服务器。
2. 运行 Linux 或 Windows 客户端。
3. 在服务器端打印 `recv()` 的返回值。
4. 客户端退出后，观察服务器是否得到 `recv() == 0`。
5. 确认服务器关闭的是 `client_fd`/`client_sock`，而不是监听 Socket。

### 实践二：观察连接失败

依次尝试以下情况，每次只改变一个条件：

- 不启动服务器，运行客户端。
- 把端口 `8080` 改成没有监听的端口。
- 把地址改成错误地址。
- 服务器启动后立刻退出，再让客户端继续发送。

记录失败的 API、返回值和平台错误码。Linux 记录 `errno`，Windows 记录 `WSAGetLastError()`。

### 实践三：观察监听 Socket 和连接 Socket

在 `accept()` 成功后打印两个句柄。连续连接两个客户端，观察：

- 监听 Socket 一直存在；
- 每次 `accept()` 返回一个新的连接 Socket；
- 一个客户端关闭只影响它自己的连接 Socket。

### 实践四：体验半关闭

修改客户端：发送完请求后调用 `shutdown(SHUT_WR)`（Windows 使用 `SD_SEND`），但不要立即 `close()`。让服务器在收到 `recv() == 0` 后发送最终响应，客户端继续 `recv()`，最后再关闭整个 Socket。

### 实践五：实现最小重连

让服务器先停止，再启动客户端重连循环。要求：

- 每次 `connect()` 失败都关闭旧 Socket；
- 重试间隔至少从 1 秒开始；
- 连接成功后停止重试；
- 进程退出时释放当前 Socket。
