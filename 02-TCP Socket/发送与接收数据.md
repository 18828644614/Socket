# 发送与接收数据

## 学习目标

学完本章后，你应该能够：

- 解释 `send()` 和 `recv()` 实际操作的是什么数据。
- 正确处理发送或接收的部分完成。
- 根据 `recv()` 的返回值判断“收到数据”“对端关闭”和“发生错误”。
- 理解 TCP 是字节流，不能把一次 `send()` 当成一次完整的 `recv()`。
- 区分文本数据和二进制数据，知道什么时候可以补 `\0`。
- 在 Linux 和 Windows 上编译并运行一个 TCP 回显示例。

## 1. 先看数据流动方向

TCP 连接建立以后，双方都可以发送和接收数据。可以先记住这条路径：

~~~text
发送方的 send()
        ↓
本机 TCP 发送缓冲区
        ↓ 网络
对方 TCP 接收缓冲区
        ↓
接收方的 recv()
~~~

例如，客户端调用 `send()`，并不表示客户端代码直接把数据“塞进”了服务器的变量。数据要先交给客户端操作系统的 TCP 协议栈，经过网络传输后，服务器的 `recv()` 才有机会读到它。

因此，`send()` 和 `recv()` 都是“本地程序与本地操作系统之间”的操作。它们的返回值首先描述本地操作是否完成，并不直接描述对方应用程序是否已经处理了数据。

## 2. `send()`：发送字节

### 2.1 基本形式

Linux/POSIX：

~~~c
ssize_t n = send(fd, data, length, 0);
~~~

Windows Winsock：

~~~c
int n = send(sock, data, length, 0);
~~~

参数的含义如下：

| 参数 | 含义 |
| --- | --- |
| 第一个参数 | 已连接的 Socket。Linux 通常是 `int`，Windows 是 `SOCKET` |
| 第二个参数 | 要发送的内存起始地址 |
| 第三个参数 | 要发送的字节数，不是“字符数” |
| 第四个参数 | 标志位；初学示例通常传 `0` |

下面的代码发送 5 个 ASCII 字节：

~~~c
const char text[] = "hello";
send(sock, text, 5, 0);
~~~

这里没有发送字符串结尾的 `\0`。如果协议需要传输 C 字符串，也可以使用 `strlen(text)` 作为长度；但网络协议通常应该明确规定长度，而不是依赖接收方猜测 `\0` 在哪里。

### 2.2 `send()` 只保证本次调用发送了多少字节

初学者常写出：

~~~c
send(sock, data, length, 0);
~~~

然后马上认为 `length` 个字节已经全部发出。这个假设不可靠。`send()` 可能返回一个小于 `length` 的正数，这叫“部分发送”。常见原因是本机发送缓冲区暂时只能接收一部分数据。

例如：

~~~text
程序希望发送 1000 字节
send() 返回 400
实际只有前 400 字节交给了本次系统调用
剩下 600 字节需要再次 send()
~~~

TCP 会负责可靠地传输已经交给它的数据，但不会替应用程序自动把一次 `send()` 调用补齐。因此需要循环发送：

~~~c
size_t sent = 0;
while (sent < length) {
    ssize_t n = send(fd, data + sent, length - sent, 0);
    if (n > 0) {
        sent += (size_t)n;
    } else {
        // 处理错误
        break;
    }
}
~~~

`data + sent` 表示从尚未发送的位置继续；`length - sent` 表示还剩多少字节。这个循环只解决“本次发送还没有完成”，并不表示对方已经读取或处理了数据。

### 2.3 发送成功不代表业务成功

`send()` 返回正数，通常表示本机内核已经接受了这些字节。它不保证：

- 对方应用程序已经调用 `recv()`；
- 对方一次就读到了完整消息；
- 对方已经完成数据库写入、文件保存等业务操作。

如果客户端必须知道服务器确实处理完了请求，就要设计应用层响应，例如：

~~~text
客户端发送：CREATE user=alice\n
服务器处理成功后回复：OK\n
服务器处理失败后回复：ERROR reason=...
~~~

这个“请求和响应”的约定属于应用层协议，不是 TCP 自动提供的功能。

## 3. `recv()`：接收字节

### 3.1 基本形式

Linux/POSIX：

~~~c
char buffer[1024];
ssize_t n = recv(fd, buffer, sizeof buffer, 0);
~~~

Windows Winsock：

~~~c
char buffer[1024];
int n = recv(sock, buffer, (int)sizeof buffer, 0);
~~~

`buffer` 是本地内存，`sizeof buffer` 是这次最多允许写入的字节数。`recv()` 不会自动为 C 字符串多留一个字节，也不会自动补 `\0`。

### 3.2 三种返回结果

这是 TCP 编程中必须熟练掌握的一张表：

| 结果 | Linux | Windows | 含义 |
| --- | --- | --- | --- |
| 正数 | `n > 0` | `n > 0` | 本次读到了 `n` 个字节 |
| 零 | `n == 0` | `n == 0` | 对端有序关闭了发送方向，没有更多字节可读 |
| 失败 | `n < 0` | `n == SOCKET_ERROR` | 发生错误，需要查看 `errno` 或 `WSAGetLastError()` |

在阻塞模式下，如果当前没有数据，`recv()` 通常会等待，而不是返回 `0`。所以：

- “暂时还没有数据”通常表现为函数阻塞等待；
- `recv() == 0` 表示对端已经明确结束发送；
- `recv()` 出错表示当前读取没有成功，不能把错误当成普通数据。

Linux 示例：

~~~c
ssize_t n = recv(fd, buffer, sizeof buffer, 0);
if (n > 0) {
    // 只使用 buffer[0] 到 buffer[n - 1]
} else if (n == 0) {
    // 对端正常关闭
} else {
    perror("recv");
}
~~~

Windows 示例：

~~~c
int n = recv(sock, buffer, (int)sizeof buffer, 0);
if (n > 0) {
    // 只使用 buffer[0] 到 buffer[n - 1]
} else if (n == 0) {
    // 对端正常关闭
} else {
    printf("recv failed: %d\n", WSAGetLastError());
}
~~~

### 3.3 `recv()` 返回正数也不代表收到完整消息

假设客户端发送：

~~~c
send(sock, "HELLO", 5, 0);
send(sock, "WORLD", 5, 0);
~~~

服务器的 `recv()` 可能出现任何一种结果：

~~~text
HELLOWORLD
HEL / LOWO / RLD
HELLO / WORLD
~~~

这三种都符合 TCP 的行为。TCP 只保证字节按顺序、可靠地形成一个连续字节流，不保存应用程序调用 `send()` 时的消息分组。

因此，接收方必须知道“什么时候一条消息结束”。常见方案有：

| 方案 | 例子 | 适合场景 |
| --- | --- | --- |
| 分隔符 | 每条文本以 `\n` 结尾 | 命令、聊天文本、日志 |
| 固定长度 | 每条消息恰好 32 字节 | 结构固定的简单协议 |
| 长度前缀 | 先发送 4 字节长度，再发送正文 | 二进制或正文可包含任意字节 |
| 关闭连接 | 读到 `recv() == 0` 才结束 | 一次请求对应一次连接 |

本章的完整示例使用第一种方法：一行以 `\n` 结尾。服务器不断读取，直到看到换行符，才把这行当作一条完整消息。

更完整的拆包方法见 [[消息边界与拆包]]。

## 4. 缓冲区、长度和 `\0`

### 4.1 接收到的内容不是自动结束的字符串

假设 `recv()` 返回 `n = 5`，这只说明 `buffer[0]` 到 `buffer[4]` 有效：

~~~text
buffer: [H][e][l][l][o][?][?]...
有效范围:  <--------- n=5 --------->
~~~

它没有承诺 `buffer[5]` 是 `\0`。如果直接这样打印：

~~~c
printf("%s", buffer);  // 错误：buffer 不一定是以 \0 结尾的字符串
~~~

`printf` 可能继续读取有效数据之外的内存，造成乱码，甚至引发未定义行为。

对于确定是文本、并且缓冲区预留了一个字节的情况，可以这样做：

~~~c
char buffer[1024];
ssize_t n = recv(fd, buffer, sizeof buffer - 1, 0);
if (n > 0) {
    buffer[n] = '\0';
    printf("%s", buffer);
}
~~~

`sizeof buffer - 1` 的原因是给 `\0` 留位置。如果允许 `recv()` 写满 1024 字节，再写 `buffer[1024]` 就越界了。

### 4.2 二进制数据不能依赖 `strlen()` 和 `\0`

图片、压缩包、序列化结构等二进制数据可能本来就包含字节 `0`：

~~~text
[0x10][0x00][0x7F][0x00][0x22]
~~~

这时不能用 `strlen()` 判断长度，也不能用 `%s` 打印。应始终使用 `recv()` 返回的长度：

~~~c
fwrite(buffer, 1, (size_t)n, stdout);
~~~

发送二进制数据时也应使用已知长度：

~~~c
send_all(fd, binary_data, binary_length);
~~~

### 4.3 字符数不一定等于字节数

网络 API 的长度参数是字节数。例如 UTF-8 编码的中文通常占多个字节：

~~~c
const char text[] = "你好";
size_t bytes = strlen(text);  // UTF-8 下通常是 6，不是 2
send(fd, text, bytes, 0);
~~~

发送前和接收后必须约定编码。TCP 不理解 UTF-8、GBK 或中文，它只负责传输字节。

## 5. 阻塞模式和“程序卡住”

默认创建的 Socket 通常是阻塞模式。阻塞意味着：在条件满足前，函数可以暂时不返回。

~~~text
服务器调用 recv()
        ↓
当前没有数据
        ↓
线程等待，不是死循环
        ↓
数据到达或对端关闭后，recv() 返回
~~~

例如，服务器等待客户端输入时停在 `recv()` 是正常现象。若客户端也在等待服务器响应，而没有先发送请求，两边就可能互相等待，形成应用层死锁：

~~~text
客户端：等服务器回复
服务器：等客户端请求
~~~

协议必须规定先后顺序，例如“客户端先发送一行，服务器收到后再回复一行”。

非阻塞模式下，没有数据时通常会立即返回错误：

- Linux 常见为 `EAGAIN` 或 `EWOULDBLOCK`；
- Windows 常见为 `WSAEWOULDBLOCK`。

这表示“现在没有数据”，不一定表示连接断开。非阻塞、`select()`、`poll()`、`epoll` 等内容会在后面的 I/O 模型章节展开；初学阶段先掌握阻塞模式和返回值即可。

## 6. Linux 示例：一问一答的 TCP 回显

这个示例约定：

1. 客户端连接 `127.0.0.1:8080`。
2. 客户端发送一行，以换行符 `\n` 结束。
3. 服务端读到换行符后原样回显。
4. 客户端读到回显行后退出。

服务端只处理一个客户端，便于观察流程。它不是并发服务器。

### 6.1 Linux 服务端

保存为 `send_recv_server_linux.c`：

~~~c
#include <arpa/inet.h>
#include <errno.h>
#include <signal.h>
#include <stdio.h>
#include <sys/socket.h>
#include <unistd.h>

static int send_all(int fd, const char *data, size_t length) {
    size_t sent = 0;

    while (sent < length) {
        ssize_t n = send(fd, data + sent, length - sent, 0);
        if (n > 0) {
            sent += (size_t)n;
        } else if (n < 0 && errno == EINTR) {
            continue;
        } else if (n == 0) {
            fprintf(stderr, "send returned 0\n");
            return -1;
        } else {
            perror("send");
            return -1;
        }
    }

    return 0;
}

// 为了便于学习，这里每次读取一个字节，直到读到换行符。
static ssize_t recv_line(int fd, char *buffer, size_t capacity) {
    size_t used = 0;

    while (used + 1 < capacity) {
        char ch;
        ssize_t n = recv(fd, &ch, 1, 0);

        if (n > 0) {
            buffer[used++] = ch;
            if (ch == '\n') {
                break;
            }
        } else if (n == 0) {
            break;
        } else if (errno == EINTR) {
            continue;
        } else {
            perror("recv");
            return -1;
        }
    }

    buffer[used] = '\0';
    return (ssize_t)used;
}

int main(void) {
    // Linux 向已关闭连接 send 时可能触发 SIGPIPE，先让程序自行处理错误。
    signal(SIGPIPE, SIG_IGN);

    int listen_fd = socket(AF_INET, SOCK_STREAM, 0);
    if (listen_fd < 0) {
        perror("socket");
        return 1;
    }

    int reuse = 1;
    setsockopt(listen_fd, SOL_SOCKET, SO_REUSEADDR,
               &reuse, sizeof reuse);

    struct sockaddr_in address = {0};
    address.sin_family = AF_INET;
    address.sin_port = htons(8080);
    address.sin_addr.s_addr = htonl(INADDR_LOOPBACK);

    if (bind(listen_fd, (struct sockaddr *)&address,
             sizeof address) < 0) {
        perror("bind");
        close(listen_fd);
        return 1;
    }

    if (listen(listen_fd, 10) < 0) {
        perror("listen");
        close(listen_fd);
        return 1;
    }

    printf("listening on 127.0.0.1:8080\n");

    int client_fd = accept(listen_fd, NULL, NULL);
    if (client_fd < 0) {
        perror("accept");
        close(listen_fd);
        return 1;
    }

    char buffer[1024];
    ssize_t n = recv_line(client_fd, buffer, sizeof buffer);
    if (n > 0) {
        printf("received: %s", buffer);
        if (send_all(client_fd, buffer, (size_t)n) < 0) {
            close(client_fd);
            close(listen_fd);
            return 1;
        }
    } else if (n == 0) {
        printf("client closed before sending a line\n");
    }

    shutdown(client_fd, SHUT_RDWR);
    close(client_fd);
    close(listen_fd);
    return n < 0 ? 1 : 0;
}
~~~

### 6.2 Linux 客户端

保存为 `send_recv_client_linux.c`：

~~~c
#include <arpa/inet.h>
#include <errno.h>
#include <stdio.h>
#include <sys/socket.h>
#include <unistd.h>

static int send_all(int fd, const char *data, size_t length) {
    size_t sent = 0;

    while (sent < length) {
        ssize_t n = send(fd, data + sent, length - sent, 0);
        if (n > 0) {
            sent += (size_t)n;
        } else if (n < 0 && errno == EINTR) {
            continue;
        } else if (n == 0) {
            fprintf(stderr, "send returned 0\n");
            return -1;
        } else {
            perror("send");
            return -1;
        }
    }

    return 0;
}

static ssize_t recv_line(int fd, char *buffer, size_t capacity) {
    size_t used = 0;

    while (used + 1 < capacity) {
        char ch;
        ssize_t n = recv(fd, &ch, 1, 0);

        if (n > 0) {
            buffer[used++] = ch;
            if (ch == '\n') {
                break;
            }
        } else if (n == 0) {
            break;
        } else if (errno == EINTR) {
            continue;
        } else {
            perror("recv");
            return -1;
        }
    }

    buffer[used] = '\0';
    return (ssize_t)used;
}

int main(void) {
    int fd = socket(AF_INET, SOCK_STREAM, 0);
    if (fd < 0) {
        perror("socket");
        return 1;
    }

    struct sockaddr_in server = {0};
    server.sin_family = AF_INET;
    server.sin_port = htons(8080);
    if (inet_pton(AF_INET, "127.0.0.1", &server.sin_addr) != 1) {
        fprintf(stderr, "invalid server address\n");
        close(fd);
        return 1;
    }

    if (connect(fd, (struct sockaddr *)&server, sizeof server) < 0) {
        perror("connect");
        close(fd);
        return 1;
    }

    const char message[] = "hello from Linux\n";
    if (send_all(fd, message, sizeof message - 1) < 0) {
        close(fd);
        return 1;
    }
    printf("sent: %s", message);

    char buffer[1024];
    ssize_t n = recv_line(fd, buffer, sizeof buffer);
    if (n > 0) {
        printf("received: %s", buffer);
    } else if (n == 0) {
        printf("server closed without a response\n");
    }

    shutdown(fd, SHUT_RDWR);
    close(fd);
    return n < 0 ? 1 : 0;
}
~~~

### 6.3 编译和运行

需要先安装 GCC。Ubuntu/Debian 可以使用：

~~~bash
sudo apt update
sudo apt install build-essential
~~~

在两个终端中执行：

~~~bash
# 终端一：编译并启动服务端
gcc -Wall -Wextra -Wpedantic -std=c11 \
    send_recv_server_linux.c -o send_recv_server_linux
./send_recv_server_linux
~~~

看到下面的输出后，服务端正在 `accept()` 等待客户端，这是正常的：

~~~text
listening on 127.0.0.1:8080
~~~

再打开终端二：

~~~bash
gcc -Wall -Wextra -Wpedantic -std=c11 \
    send_recv_client_linux.c -o send_recv_client_linux
./send_recv_client_linux
~~~

客户端预期输出：

~~~text
sent: hello from Linux
received: hello from Linux
~~~

服务端输出：

~~~text
received: hello from Linux
~~~

这次通信经过了：

~~~text
client socket
    → connect()
    → send_all("hello from Linux\n")
    → server recv_line()
    → server send_all()
    → client recv_line()
    → close()
~~~

服务端只接收一个客户端，所以测试完成后它会退出。再次测试时需要重新启动服务端。

## 7. Windows 示例：Winsock 版 TCP 回显

Windows 的通信逻辑相同，但 API 类型和初始化/清理方式不同：

| Linux/POSIX | Windows Winsock |
| --- | --- |
| `int` 文件描述符 | `SOCKET` |
| 创建失败为 `-1` | 创建失败为 `INVALID_SOCKET` |
| 失败通常返回 `-1` | 失败通常返回 `SOCKET_ERROR` |
| `errno`、`perror()` | `WSAGetLastError()` |
| `close()` | `closesocket()` |
| 通常不需要全局初始化 | 先 `WSAStartup()`，最后 `WSACleanup()` |
| `SHUT_RDWR` | `SD_BOTH` |

Windows 中 `SOCKET` 不是普通的 Linux 文件描述符，所以不能写 `close(sock)`，也不能用 `sock < 0` 检查失败。

### 7.1 Windows 服务端

保存为 `send_recv_server_windows.c`：

~~~c
#include <winsock2.h>
#include <stdio.h>

#pragma comment(lib, "Ws2_32.lib")

static int send_all(SOCKET sock, const char *data, int length) {
    int sent = 0;

    while (sent < length) {
        int n = send(sock, data + sent, length - sent, 0);
        if (n > 0) {
            sent += n;
        } else if (n == 0) {
            printf("send returned 0\n");
            return -1;
        } else {
            printf("send failed: %d\n", WSAGetLastError());
            return -1;
        }
    }

    return 0;
}

// 为了便于学习，这里每次读取一个字节，直到读到换行符。
static int recv_line(SOCKET sock, char *buffer, int capacity) {
    int used = 0;

    while (used + 1 < capacity) {
        char ch;
        int n = recv(sock, &ch, 1, 0);

        if (n > 0) {
            buffer[used++] = ch;
            if (ch == '\n') {
                break;
            }
        } else if (n == 0) {
            break;
        } else if (WSAGetLastError() == WSAEINTR) {
            continue;
        } else {
            printf("recv failed: %d\n", WSAGetLastError());
            return -1;
        }
    }

    buffer[used] = '\0';
    return used;
}

int main(void) {
    WSADATA wsa_data;
    int result = WSAStartup(MAKEWORD(2, 2), &wsa_data);
    if (result != 0) {
        printf("WSAStartup failed: %d\n", result);
        return 1;
    }

    SOCKET listen_sock = socket(AF_INET, SOCK_STREAM, IPPROTO_TCP);
    if (listen_sock == INVALID_SOCKET) {
        printf("socket failed: %d\n", WSAGetLastError());
        WSACleanup();
        return 1;
    }

    BOOL reuse = TRUE;
    setsockopt(listen_sock, SOL_SOCKET, SO_REUSEADDR,
               (const char *)&reuse, sizeof reuse);

    struct sockaddr_in address = {0};
    address.sin_family = AF_INET;
    address.sin_port = htons(8080);
    address.sin_addr.s_addr = htonl(INADDR_LOOPBACK);

    if (bind(listen_sock, (const struct sockaddr *)&address,
             sizeof address) == SOCKET_ERROR) {
        printf("bind failed: %d\n", WSAGetLastError());
        closesocket(listen_sock);
        WSACleanup();
        return 1;
    }

    if (listen(listen_sock, 10) == SOCKET_ERROR) {
        printf("listen failed: %d\n", WSAGetLastError());
        closesocket(listen_sock);
        WSACleanup();
        return 1;
    }

    printf("listening on 127.0.0.1:8080\n");

    SOCKET client_sock = accept(listen_sock, NULL, NULL);
    if (client_sock == INVALID_SOCKET) {
        printf("accept failed: %d\n", WSAGetLastError());
        closesocket(listen_sock);
        WSACleanup();
        return 1;
    }

    char buffer[1024];
    int n = recv_line(client_sock, buffer, (int)sizeof buffer);
    if (n > 0) {
        printf("received: %s", buffer);
        if (send_all(client_sock, buffer, n) < 0) {
            closesocket(client_sock);
            closesocket(listen_sock);
            WSACleanup();
            return 1;
        }
    } else if (n == 0) {
        printf("client closed before sending a line\n");
    }

    shutdown(client_sock, SD_BOTH);
    closesocket(client_sock);
    closesocket(listen_sock);
    WSACleanup();
    return n < 0 ? 1 : 0;
}
~~~

### 7.2 Windows 客户端

保存为 `send_recv_client_windows.c`：

~~~c
#include <winsock2.h>
#include <stdio.h>

#pragma comment(lib, "Ws2_32.lib")

static int send_all(SOCKET sock, const char *data, int length) {
    int sent = 0;

    while (sent < length) {
        int n = send(sock, data + sent, length - sent, 0);
        if (n > 0) {
            sent += n;
        } else if (n == 0) {
            printf("send returned 0\n");
            return -1;
        } else {
            printf("send failed: %d\n", WSAGetLastError());
            return -1;
        }
    }

    return 0;
}

static int recv_line(SOCKET sock, char *buffer, int capacity) {
    int used = 0;

    while (used + 1 < capacity) {
        char ch;
        int n = recv(sock, &ch, 1, 0);

        if (n > 0) {
            buffer[used++] = ch;
            if (ch == '\n') {
                break;
            }
        } else if (n == 0) {
            break;
        } else if (WSAGetLastError() == WSAEINTR) {
            continue;
        } else {
            printf("recv failed: %d\n", WSAGetLastError());
            return -1;
        }
    }

    buffer[used] = '\0';
    return used;
}

int main(void) {
    WSADATA wsa_data;
    int result = WSAStartup(MAKEWORD(2, 2), &wsa_data);
    if (result != 0) {
        printf("WSAStartup failed: %d\n", result);
        return 1;
    }

    SOCKET sock = socket(AF_INET, SOCK_STREAM, IPPROTO_TCP);
    if (sock == INVALID_SOCKET) {
        printf("socket failed: %d\n", WSAGetLastError());
        WSACleanup();
        return 1;
    }

    struct sockaddr_in server = {0};
    server.sin_family = AF_INET;
    server.sin_port = htons(8080);
    server.sin_addr.s_addr = htonl(INADDR_LOOPBACK);

    if (connect(sock, (const struct sockaddr *)&server,
                sizeof server) == SOCKET_ERROR) {
        printf("connect failed: %d\n", WSAGetLastError());
        closesocket(sock);
        WSACleanup();
        return 1;
    }

    const char message[] = "hello from Windows\n";
    if (send_all(sock, message, (int)sizeof message - 1) < 0) {
        closesocket(sock);
        WSACleanup();
        return 1;
    }
    printf("sent: %s", message);

    char buffer[1024];
    int n = recv_line(sock, buffer, (int)sizeof buffer);
    if (n > 0) {
        printf("received: %s", buffer);
    } else if (n == 0) {
        printf("server closed without a response\n");
    }

    shutdown(sock, SD_BOTH);
    closesocket(sock);
    WSACleanup();
    return n < 0 ? 1 : 0;
}
~~~

## 8. 两个示例中最值得理解的代码

### 8.1 为什么示例要有 `send_all()`

`send_all()` 维护了一个 `sent` 变量：

~~~text
sent = 0
第一次 send：发送 data[0] 到 data[99]，返回 100
sent = 100
第二次 send：从 data[100] 继续
直到 sent == length
~~~

短消息在本机测试中经常一次就发送完成，但不能因为“测试总是成功”就省略循环。消息变大、发送缓冲区变满或改用非阻塞模式后，部分发送就可能出现。

### 8.2 为什么示例要有 `recv_line()`

示例规定换行符是消息结束标志，所以客户端发送：

~~~text
hello from Linux\n
~~~

服务端不能只调用一次 `recv()` 就假设整行已到达。`recv_line()` 反复接收，直到：

- 读到 `\n`：收到完整的一行；
- 返回 `0`：对端关闭，且没有更多数据；
- 返回错误：本次接收失败；
- 缓冲区快满：停止继续写入，避免越界。

示例为了让这个过程一眼可见，每次只收 1 个字节。这种写法会产生很多系统调用，真实程序通常一次收一大块数据，放入“接收缓存”，再在缓存中查找换行符并处理剩余字节。这里的简化只适合学习，不适合高吞吐服务。

### 8.3 为什么客户端最后也要 `recv()`

发送请求和接收响应是两个独立方向：

~~~text
客户端 send()  ─────请求─────>  服务端 recv()
客户端 recv()  <────响应─────  服务端 send()
~~~

如果客户端只调用 `send()` 就退出，操作系统可能来不及让程序观察到服务器的响应；更重要的是，应用层也无法知道服务器有没有处理成功。回显客户端调用 `recv_line()`，是因为本例协议约定服务端必须返回一行。

### 8.4 为什么用 `127.0.0.1`

`127.0.0.1` 是回环地址，只在本机内部通信。它适合第一次练习：

- 不需要局域网地址；
- 不需要让服务暴露到其他设备；
- 防火墙和网络环境带来的变量更少。

如果要让局域网其他设备连接，服务端通常要绑定本机实际网卡地址或 `0.0.0.0`，客户端也要连接服务器的局域网 IP；同时还要配置防火墙。只在自己拥有或明确获准测试的设备上这样做。

## 9. 常见问题排查

### `connect()` 失败

先确认服务端已经启动并显示 `listening on 127.0.0.1:8080`。再检查：

- 客户端和服务端端口是否都是 `8080`；
- 客户端地址是否是 `127.0.0.1`；
- 服务端是否已经处理过一个客户端并退出；
- 端口是否被其他程序占用。

Linux 可以查看：

~~~bash
ss -ltnp | grep 8080
~~~

Windows PowerShell 可以查看：

~~~powershell
Get-NetTCPConnection -LocalPort 8080 -ErrorAction SilentlyContinue
~~~

### 程序停在 `accept()` 或 `recv()`

这通常是阻塞模式的正常表现：

- 停在 `accept()`：还没有客户端连接；
- 停在 `recv()`：连接存在，但协议规定的下一段数据还没有到达；
- 停在 `recv_line()`：还没有收到换行符，对端也没有关闭连接。

先按本章规定的顺序启动服务端和客户端，不要让两边都先等待响应。

### `recv()` 返回 `0`

这不是“收到一个空字符串”，而是对端已经有序关闭发送方向。此时应结束当前会话或根据协议执行下一步，不能继续无限调用 `recv()` 等待新数据。

### 中文显示乱码

检查发送端和接收端使用的编码是否一致。长度参数传的是编码后的字节数，不是中文字符个数。TCP 不会自动转换编码。

### 为什么服务端只处理一次连接

代码中只调用了一次 `accept()`。学习一个完整的收发流程时这样更容易观察；要连续服务多个客户端，需要把 `accept()` 放到循环中，并进一步考虑并发或 I/O 多路复用。

## 10. 实践

1. 把客户端消息改成包含中文的内容，观察字节长度和输出是否正常。
2. 把客户端发送的消息改成两行，观察当前 `recv_line()` 只读取第一行；思考第二行应保存在接收缓存中，留给下一次解析。
3. 修改服务端，让它回复 `OK: ` 加上原消息。注意回复也必须带 `\n`，否则客户端的 `recv_line()` 会继续等待。
4. 将消息改成长于 1023 字节，观察示例的最大缓冲区限制。思考真实协议为什么需要拒绝超长消息或动态管理接收缓存。
5. 故意先关闭客户端，再让服务端调用 `send()`，观察 Linux 的 `SIGPIPE` 处理以及 Windows 的错误返回。
