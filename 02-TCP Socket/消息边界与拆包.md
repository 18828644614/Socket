# 消息边界与拆包

## 学习目标

学完本章后，你应该能够：

- 解释为什么 TCP 没有“消息”概念，只有连续的字节流。
- 区分半包、粘包和正常的多次读取。
- 选择定长、分隔符或长度前缀来定义应用层消息边界。
- 写出能够处理半包和粘包的接收循环。
- 在 Linux 和 Windows 上运行一个使用换行符分隔消息的 TCP 回显示例。

## 1. 先理解：TCP 是水管，不是快递盒

可以把 TCP 想象成一根可靠的水管：发送方把字节依次倒进去，接收方从另一端按顺序取出字节。TCP 保证字节不重复、按顺序到达（连接正常时），但不会记住发送方调用 `send()` 的次数，也不会把每次 `send()` 自动变成一条独立消息。

```text
应用层：  send("ABC")     send("DEF")
                       ↓
TCP 字节流：       A B C D E F
                       ↓
接收层可能得到： recv() = "AB"，下一次 = "CDEF"
```

因此，下面三种情况都可能发生，而且都不是 TCP 出错：

| 发送方的调用 | 接收方第一次 `recv()` 可能得到 | 名称 |
| --- | --- | --- |
| 一次发送 `100` 字节 | 只得到前 `40` 字节 | 半包（一次消息被拆开） |
| 连续发送两条小消息 | 一次得到两条消息的全部字节 | 粘包（多条消息连在一起） |
| 一次发送一条消息 | 恰好得到完整消息 | 只是“碰巧”，不能依赖 |

“包”在本章中是应用层消息的简称，不要和 TCP/IP 报文段混为一谈。TCP 报文段如何切分由操作系统和网络决定，应用程序应该自己定义“这一条消息到哪里结束”。

## 2. 半包、粘包到底是什么

假设协议规定每条消息是文本并以换行符 `\n` 结束，发送方连续发送：

```text
LOGIN alice\n
PING\n
```

接收端的读取结果可能是：

```text
第 1 次 recv()：LOGIN al
第 2 次 recv()：ice\nPING
第 3 次 recv()：\n
```

- 第 1、2 次合在一起才是第一条完整消息，这就是半包。
- 第 2 次同时带着下一条消息的一部分，说明一次读取可能跨越消息边界。
- 如果一次读取直接得到 `LOGIN alice\nPING\n`，两条消息连在一起，就是粘包。

接收代码不能写成“调用一次 `recv()`，然后把缓冲区当成一条消息”。正确做法是维护一个接收缓冲区：每次把新字节追加进去，再按照协议规则不断取出完整消息；不完整的尾部要保留到下一次读取。

```text
接收缓冲区： [已经收到但尚未解析完的字节]
                  ↓ 找到边界
完整消息 1 | 完整消息 2 | 尚未完整的尾巴
                         └─ 留在缓冲区，等待下一次 recv()
```

## 3. 三种常见的消息边界方案

### 3.1 定长消息

协议规定每条消息固定为 `N` 个字节，例如每条都是 32 字节：

```text
[前 32 字节是一条] [接着 32 字节是下一条] ...
```

接收方必须循环读取，直到累计 `N` 字节。一次 `recv()` 少于 `N` 字节并不代表连接断开。

优点是解析简单、速度稳定；缺点是短消息浪费空间，长消息需要截断或另行设计。定长协议常用于简单的二进制记录、固定格式的传感器数据。

```c
/* 伪代码：读满 length 个字节；返回 0 表示对端提前关闭 */
while (received < length) {
    n = recv(sock, buffer + received, length - received, 0);
    if (n > 0) received += n;
    else if (n == 0) return 0;
    else return -1;
}
```

### 3.2 分隔符消息

协议规定某个特殊字节序列表示结束，例如：

```text
第一条消息\n第二条消息\n
```

接收方不断寻找分隔符。文本协议常用 `\n`，HTTP 头部使用 `\r\n`，CSV 常用换行。若消息内容本身也可能包含分隔符，就必须规定转义规则，或改用长度前缀。

本章的完整示例采用 `\n`，这样可以直观看到“收到换行符才算一条消息”。示例按字节读取，便于学习；生产代码通常一次读取较大的缓冲区，再在内存中查找换行符，以减少系统调用次数。

### 3.3 长度前缀消息

每条消息先放一个长度字段，再放内容：

```text
[4 字节长度][消息内容][4 字节长度][消息内容]...
```

例如内容 `hello`（5 字节）可以编码为：

```text
00 00 00 05  h e l l o
```

接收步骤必须分成两层：

1. 先循环读取满 4 字节长度字段。
2. 用网络字节序 `ntohl()` 转成本机整数。
3. 检查长度是否超过协议允许的最大值（例如 1 MiB），防止恶意长度导致超大内存分配。
4. 再循环读取满 `length` 字节内容。

长度字段本身也可能半包，不能假设一次 `recv()` 就能读满 4 字节。发送端使用 `htonl()`，接收端使用 `ntohl()`；不要直接把本机 `int` 的内存拷贝到网络上，因为不同 CPU 的字节序可能不同。

长度前缀适合二进制协议和可能包含任意换行符的 JSON/文件内容，是工程中很常见的选择。代价是协议稍复杂，并且必须严格校验长度。

### 3.4 方案选择速查

| 方案 | 适合场景 | 主要注意点 |
| --- | --- | --- |
| 定长 | 字段固定、结构简单 | 必须读满固定长度，注意空间浪费 |
| 分隔符 | 命令行、文本行协议 | 内容中的分隔符要转义；要限制单行最大长度 |
| 长度前缀 | 二进制、JSON、文件块 | 长度字段也会半包；校验最大长度和字节序 |

## 4. 一个可靠接收循环的思路

无论选择哪种协议，都可以按下面的顺序思考：

1. `recv()` 返回正数：把这批字节加入缓冲区。
2. 根据协议查找边界：固定长度、分隔符或长度字段。
3. 找到完整消息：取出来交给业务代码；缓冲区中可能还有下一条消息，继续解析。
4. 找不到完整消息：保留现有字节，回到第 1 步。
5. 返回 `0`：对端有序关闭；如果缓冲区还有不完整内容，应报告“消息被截断”。
6. 返回错误：区分可重试错误和真正的连接失败。

一个常见错误是“为了等待完整消息而反复调用 `recv()`，但忘记保存前一次收到的尾巴”。另一个错误是只在 `recv()` 返回 `0` 时才处理消息；这会把正常数据和连接关闭混在一起。

## 5. 实践：换行符分隔的 TCP 回显

下面示例的协议非常简单：客户端每输入一行，发送“这一行的字节 + `\n`”；服务器读到换行符后回复 `echo: ` 加原消息。它专门演示消息边界，不是生产级服务器：只处理一个客户端，按字节读取也不适合高吞吐场景。

### 5.1 Linux（POSIX Socket）

将下面内容保存为 `line_server.c`：

~~~c
#include <arpa/inet.h>
#include <errno.h>
#include <netinet/in.h>
#include <stdio.h>
#include <string.h>
#include <sys/socket.h>
#include <unistd.h>

static int send_all(int fd, const char *data, size_t len) {
    size_t sent = 0;
    while (sent < len) {
        ssize_t n = send(fd, data + sent, len - sent, 0);
        if (n > 0) sent += (size_t)n;
        else if (n < 0 && errno == EINTR) continue;
        else return -1;
    }
    return 0;
}

/* 返回正数=一行字节数，0=对端关闭，-1=错误，-2=超过缓冲区 */
static int recv_line(int fd, char *buf, size_t cap) {
    size_t used = 0;
    int too_long = 0;
    for (;;) {
        char ch;
        ssize_t n = recv(fd, &ch, 1, 0);
        if (n == 1) {
            if (ch == '\n') break;
            if (used + 1 < cap) buf[used++] = ch;
            else too_long = 1; /* 继续读到换行，保持协议同步 */
        } else if (n == 0) {
            if (used == 0 && !too_long) return 0;
            break; /* 最后一行没有换行，也可以作为截断行处理 */
        } else if (errno == EINTR) {
            continue;
        } else {
            return -1;
        }
    }
    buf[used] = '\0';
    return too_long ? -2 : (int)used;
}

int main(void) {
    int listen_fd = socket(AF_INET, SOCK_STREAM, 0);
    if (listen_fd < 0) { perror("socket"); return 1; }

    int yes = 1;
    setsockopt(listen_fd, SOL_SOCKET, SO_REUSEADDR, &yes, sizeof yes);
    struct sockaddr_in addr = {0};
    addr.sin_family = AF_INET;
    addr.sin_port = htons(8080);
    inet_pton(AF_INET, "127.0.0.1", &addr.sin_addr);
    if (bind(listen_fd, (struct sockaddr *)&addr, sizeof addr) < 0) {
        perror("bind"); close(listen_fd); return 1;
    }
    if (listen(listen_fd, 8) < 0) {
        perror("listen"); close(listen_fd); return 1;
    }
    puts("listening on 127.0.0.1:8080");

    int client_fd = accept(listen_fd, NULL, NULL);
    if (client_fd < 0) { perror("accept"); close(listen_fd); return 1; }
    char line[1024];
    for (;;) {
        int n = recv_line(client_fd, line, sizeof line);
        if (n == 0) break;
        if (n == -2) {
            const char error[] = "ERROR line too long\n";
            send_all(client_fd, error, sizeof error - 1);
            continue;
        }
        if (n < 0) { perror("recv"); break; }
        printf("received: %s\n", line);
        if (send_all(client_fd, "echo: ", 6) < 0 ||
            send_all(client_fd, line, (size_t)n) < 0 ||
            send_all(client_fd, "\n", 1) < 0) break;
    }
    close(client_fd);
    close(listen_fd);
    return 0;
}
~~~

保存客户端为 `line_client.c`：

~~~c
#include <arpa/inet.h>
#include <errno.h>
#include <netinet/in.h>
#include <stdio.h>
#include <string.h>
#include <sys/socket.h>
#include <unistd.h>

static int send_all(int fd, const char *data, size_t len) {
    size_t sent = 0;
    while (sent < len) {
        ssize_t n = send(fd, data + sent, len - sent, 0);
        if (n > 0) sent += (size_t)n;
        else if (n < 0 && errno == EINTR) continue;
        else return -1;
    }
    return 0;
}

static int recv_line(int fd, char *buf, size_t cap) {
    size_t used = 0;
    while (used + 1 < cap) {
        char ch;
        ssize_t n = recv(fd, &ch, 1, 0);
        if (n == 1) { if (ch == '\n') break; buf[used++] = ch; }
        else if (n == 0) return 0;
        else if (errno == EINTR) continue;
        else return -1;
    }
    buf[used] = '\0';
    return (int)used;
}

int main(void) {
    int fd = socket(AF_INET, SOCK_STREAM, 0);
    if (fd < 0) { perror("socket"); return 1; }
    struct sockaddr_in addr = {0};
    addr.sin_family = AF_INET;
    addr.sin_port = htons(8080);
    inet_pton(AF_INET, "127.0.0.1", &addr.sin_addr);
    if (connect(fd, (struct sockaddr *)&addr, sizeof addr) < 0) {
        perror("connect"); close(fd); return 1;
    }
    char line[1024], reply[2048];
    puts("输入一行并回车，Ctrl-D 结束：");
    while (fgets(line, sizeof line - 2, stdin)) {
        size_t len = strlen(line);
        if (len == 0 || line[0] == '\n') continue;
        if (line[len - 1] != '\n') { line[len++] = '\n'; line[len] = '\0'; }
        if (send_all(fd, line, len) < 0) { perror("send"); break; }
        int n = recv_line(fd, reply, sizeof reply);
        if (n <= 0) { puts("server closed or recv failed"); break; }
        printf("server: %s\n", reply);
    }
    close(fd);
    return 0;
}
~~~

编译和运行：

~~~bash
gcc -Wall -Wextra -O2 line_server.c -o line_server
gcc -Wall -Wextra -O2 line_client.c -o line_client
./line_server                 # 终端 1
./line_client                 # 终端 2
~~~

输入 `hello` 后，客户端会发送 `hello\n`，服务器读到换行才处理，并回复 `echo: hello`。如果客户端连续快速发送多行，服务器可能一次从内核读到多行，但 `recv_line()` 每次只交付其中一行，这就是拆包器的作用。

### 5.2 Windows（Winsock）

Windows 版本的协议和 Linux 完全相同，变化主要是初始化和 API：`WSAStartup()`、`SOCKET`、`closesocket()`、`WSACleanup()`，以及错误码获取方式。保存为 `line_server.c`：

~~~c
#include <winsock2.h>
#include <ws2tcpip.h>
#include <stdio.h>
#include <string.h>
#pragma comment(lib, "Ws2_32.lib")

static int send_all(SOCKET s, const char *data, int len) {
    int sent = 0;
    while (sent < len) {
        int n = send(s, data + sent, len - sent, 0);
        if (n > 0) sent += n; else return -1;
    }
    return 0;
}

static int recv_line(SOCKET s, char *buf, int cap) {
    int used = 0, too_long = 0;
    for (;;) {
        char ch;
        int n = recv(s, &ch, 1, 0);
        if (n == 1) {
            if (ch == '\n') break;
            if (used + 1 < cap) buf[used++] = ch; else too_long = 1;
        } else if (n == 0) {
            if (used == 0 && !too_long) return 0;
            break;
        } else return -1;
    }
    buf[used] = '\0';
    return too_long ? -2 : used;
}

int main(void) {
    WSADATA wsa;
    if (WSAStartup(MAKEWORD(2, 2), &wsa) != 0) return 1;
    SOCKET listen_sock = socket(AF_INET, SOCK_STREAM, IPPROTO_TCP);
    if (listen_sock == INVALID_SOCKET) { printf("socket: %d\n", WSAGetLastError()); WSACleanup(); return 1; }
    struct sockaddr_in addr = {0};
    addr.sin_family = AF_INET; addr.sin_port = htons(8080);
    inet_pton(AF_INET, "127.0.0.1", &addr.sin_addr);
    if (bind(listen_sock, (struct sockaddr *)&addr, sizeof addr) == SOCKET_ERROR ||
        listen(listen_sock, 8) == SOCKET_ERROR) {
        printf("bind/listen: %d\n", WSAGetLastError()); closesocket(listen_sock); WSACleanup(); return 1;
    }
    puts("listening on 127.0.0.1:8080");
    SOCKET client = accept(listen_sock, NULL, NULL);
    if (client == INVALID_SOCKET) { closesocket(listen_sock); WSACleanup(); return 1; }
    char line[1024];
    for (;;) {
        int n = recv_line(client, line, (int)sizeof line);
        if (n == 0) break;
        if (n == -2) {
            const char error[] = "ERROR line too long\n";
            send_all(client, error, (int)sizeof error - 1);
            continue;
        }
        if (n < 0) break;
        printf("received: %s\n", line);
        if (send_all(client, "echo: ", 6) || send_all(client, line, n) || send_all(client, "\n", 1)) break;
    }
    closesocket(client); closesocket(listen_sock); WSACleanup();
    return 0;
}
~~~

## 6. 常见错误与排错

### 把 `recv()` 返回值当成消息长度

返回值只表示“这一次拿到了多少字节”。它不是协议层消息长度。解决办法是实现 `recv_all()`、`recv_line()` 或长度前缀解析器。

### 收到半个中文就直接当字符串

UTF-8 一个汉字通常占多个字节，半包可能恰好切在汉字中间。先按协议收齐字节，再按约定编码解码；不要用 `strlen()` 猜消息边界。

### 没有给字符串补 `\0`

`recv()` 不会自动补 C 字符串结束符。只有在确认缓冲区有空间时才能写 `buf[n] = '\0'`；二进制数据更不能依赖 `\0`。

### 无限相信长度字段

长度前缀来自网络，属于不可信输入。应设置最大消息长度，检查整数溢出，长度异常时关闭连接或丢弃当前消息，避免内存耗尽。

### 以为 `sleep()` 可以解决粘包

延时只能改变出现问题的概率，不能建立消息边界。边界必须由协议字段表达。
