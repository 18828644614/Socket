# 安全与输入校验

> 从“收到的数据为什么不能直接使用”开始，先建立学习地图，再逐层讲解，最后运行实验。你不需要预先懂密码学、TLS 或安全专业术语。
>
> 本章沿用知识库的 C 语言主线，Windows Winsock 与 Linux Socket 完整代码分别列出。Python 3 仅用于发送测试数据。实验协议与前章 MiniCalc、MF 协议不同，请使用本章的端口和消息格式。

## 0. 先规划：学习范围与顺序

### 0.1 学完本章要能够回答什么

1. 客户端说“正文有 4 GB”，服务端是否应该立即分配 4 GB 内存？
2. 客户端发了一半就断开，程序会不会把残缺消息当作完整请求？
3. 每秒只发一个字节，能否永远占着一个工作线程？
4. 请求声称“我是管理员”，服务端凭什么相信？
5. 登录成功之后，是否可以读取任意用户的文件？
6. 密码如何避免被网络旁观者看到？怎样确认连接的是正确服务器？
7. 错误日志会不会泄露秘密或被输入伪造？
8. 格式正确的请求，是否仍可能耗尽内存、CPU、连接和磁盘？

最终成果是：一份明确的输入规则、一个拒绝异常数据的服务端、一张实际执行的测试表，以及一份工程检查清单。

### 0.2 推荐学习路线

| 阶段 | 阅读位置 | 内容 | 建议时间 | 通过标准 |
| --- | --- | --- | --- | --- |
| A：补齐基础 | 第 1 节 | 字节、缓冲区、TCP、返回值、截止时间 | 30～60 分钟 | 解释为什么不能对接收缓冲区直接 `strlen` |
| B：建立地图 | 第 2 节 | 不可信输入、信任边界、安全目标 | 30 分钟 | 指出一条请求经过哪些检查 |
| C：把好输入关 | 第 3～5 节 | 长度、溢出、编码、语法、业务校验、注入 | 60～90 分钟 | 给每个字段写出允许值和拒绝条件 |
| D：身份与通道 | 第 6～7 节 | 认证、授权、密码、令牌、TLS、证书 | 60～90 分钟 | 区分“已加密”“已登录”“有权限” |
| E：限制消耗 | 第 8 节 | 超时、限流、资源、日志、最小权限 | 45～60 分钟 | 分别给时间、空间和工作量设预算 |
| F：动手实践 | 第 9～13 节 | 协议、分平台 C 代码、客户端、运行排错 | 90～150 分钟 | 正常、超长、截断和慢发送结果均符合预期 |
| G：巩固扩展 | 第 14～17 节 | TLS 实验、练习、阶段清单、后续阅读 | 60～120 分钟 | 解释示例的保护范围和缺少的能力 |

可以分四次学习：A～B、C、D～E、F～G。第一次运行先完成正常测试，再尝试错误输入，不必先背完所有术语。

### 0.3 哪些现在掌握，哪些以后深入

**现在必须掌握**：按字节限制长度、完整收发、严格解析、整数范围、认证与授权、TLS 身份验证、固定截止时间、资源预算、安全日志和异常测试。

**现在理解用途即可**：密码哈希、恒定时间比较、重放、双向 TLS、模糊测试、进程权限隔离。正文会逐个解释。

**以后按需要深入**：完整账户系统、OAuth/OIDC、证书基础设施运维、密钥轮换、分布式限流、DDoS 防护、专业审计。学习 Socket 安全不需要从手写加密算法开始。

## 1. 前置知识：把地基补齐

### 1.1 建议先回顾什么

| 前置知识 | 本章用途 | 回顾入口 |
| --- | --- | --- |
| IP、端口、客户端与服务端 | 找到服务，区分本机与对外监听 | [[IP地址与端口]]、[[Socket基础]] |
| TCP 字节流和消息边界 | 处理半条消息、多条消息合并 | [[TCP与UDP概念]]、[[消息边界与拆包]] |
| 收发函数与返回值 | 判断部分读写、断开与错误 | [[发送与接收数据]] |
| 字节、编码、大端 | 限制长度，读取帧头 | [[字节、编码与数据边界]]、[[消息格式与版本]] |
| 数组、指针、函数、循环 | 阅读 C 缓冲区和解析代码 | [[C语言网络编程基础]] |
| 非阻塞、超时 | 让等待有明确边界 | [[阻塞与非阻塞]]、[[心跳、超时与重连]] |

指针可以先理解为“某块内存的位置”。函数同时接收一个指针和一个长度，就是“从这里开始，最多处理这么多字节”。

### 1.2 字节数不等于字符数

字节是网络与内存中的计数单位，本章一个字节为 8 位。ASCII 表示英文字母、数字等简单字符；UTF-8 还能表示中文，一个常见汉字通常占 3 个字节。

```text
文本        UTF-8 字节数
A           1
你好        6
```

协议必须明确长度按字节还是按字符计算。本章小协议只允许可打印 ASCII，暂不支持中文；真实业务需要中文时，要另外规定 UTF-8 解码、字符限制和显示规则。

### 1.3 C 缓冲区不是自动安全的字符串

缓冲区是一块临时存放数据的内存。`char buf[128]` 只有 128 个位置，下标范围是 0～127。**越界**就是读写了范围以外的位置，可能覆盖其他数据或泄露内存。

```c
/* 错误示意，不要用于程序 */
char buf[128];
int n = recv(sock, buf, 128, 0);
buf[n] = '\0'; /* n==128 时越界；n<0 时也危险 */
```

`\0` 是值为 0 的字符串结束字节。网络数据不保证末尾有它，也可能在内部包含它：`41 00 42` 实际有 3 字节，`strlen` 却只数到第一个 `A`。

正确顺序：检查函数返回值 → 保存实际长度 → 确保容量 → 按协议验证内容 → 必要时补结束符。二进制数据始终按“地址 + 长度”处理。

### 1.4 TCP、部分收发与返回值

一次 `send` 不等于一条完整消息；接收端可能分多次 `recv` 才拿全，也可能一次收到多条。必须按协议自行分帧。

| 返回结果 | `recv` | `send` |
| --- | --- | --- |
| 正数 | 本次收到的字节数 | 本次交给本机网络栈的字节数 |
| 0 | 对方正常关闭发送方向 | 对本章非空发送按无法继续处理 |
| 错误 | 查看错误码，区分暂时无数据与真正失败 | 查看错误码，区分暂时不能写与真正失败 |

Windows 错误返回 `SOCKET_ERROR`，用 `WSAGetLastError` 取码；Linux 通常返回 `-1`，看 `errno`。**非阻塞**指“暂时做不了就返回”，不是“永远不能做”。等待就绪后可重试。

`send` 返回成功也不代表对方业务已经执行。需要业务结果时，必须按协议等待对应响应，不能仅凭本机发送成功就认定扣款、保存文件等操作完成。

### 1.5 截止时间与单调时钟

“每次读取最多等 2 秒”和“整条消息总共最多用 2 秒”不同。前者如果每收到一点就重新计时，慢客户端可能一直拖下去。

```text
开始接收本帧：deadline = 当前时间 + 2000 毫秒
每次等待之前：remaining = deadline - 当前时间
收到部分数据：仍然使用原来的 deadline
```

用于算时长的**单调时钟**不会因为人工调整日期而倒退。Windows 示例用 `GetTickCount64`，Linux 用 `clock_gettime(CLOCK_MONOTONIC)`。

### 1.6 阅读示例时的 C 语言小抄

| 写法 | 在本章中的意思 |
| --- | --- |
| `#define MAX_BODY 128` | 给固定预算起名字，便于统一修改 |
| `typedef` | 为平台类型起统一的局部名字，例如 `net_t` |
| `size_t` | 表示本机内存大小或数组长度的无符号整数类型 |
| `uint64_t` | 固定 64 位无符号整数，本章存储毫秒时间 |
| `const char *` | 指向字符数据，当前接口不通过它修改内容 |
| `buf + used` | 从缓冲区已经处理过的部分之后继续 |
| `&value` | 把变量的位置传给函数，让函数能填写结果 |
| `a ? b : c` | 条件 a 成立取 b，否则取 c |
| `&&` / `\|\|` | 并且/或者；左边已能决定结果时，不再计算右边 |

特别注意“短路计算”：`header <= capacity && body <= capacity - header` 先判断左边，成立才计算右边，避免无符号减法下溢。

## 2. 安全地图：信什么，保护什么

### 2.1 什么是不可信输入

不可信不是指“对方一定恶意”，而是指“使用之前必须验证”。正常客户端也可能有 bug、发错长度或突然断网。

外部输入包括网络字节、客户端声明的身份、文件名、配置、其他服务响应，以及先前存入数据库的数据。保存过不等于验证过。

**信任边界**是数据从尚未验证的来源进入准备依赖它执行操作的位置：

```text
网络字节 → 帧头/长度检查 → 收齐正文 → 编码与语法检查
         → 字段/业务校验 → 身份与权限检查 → 执行 → 有限响应
```

客户端界面校验帮助用户少输错；服务端校验保护系统。别人可以绕过界面，直接编写程序发数据。

### 2.2 安全主要保护什么

| 目标 | 通俗解释 | 例子 |
| --- | --- | --- |
| 机密性 | 只让应该看的人看到内容 | 不泄露密码与私密消息 |
| 完整性 | 数据不能被悄悄改掉而不被发现 | 金额不被途中篡改 |
| 可用性 | 正常用户仍能使用服务 | 异常请求不能轻易拖垮程序 |
| 身份真实性 | 对方确实是声称的身份 | 不连接冒充的服务器 |

### 2.3 先做一张小型威胁分析表

**威胁分析**就是问“对方能做什么、有什么后果、在哪里拦住”。

| 对方可做的事 | 后果 | 保护 |
| --- | --- | --- |
| 随便填写长度、命令和数字 | 越界、溢出、逻辑错误 | 上限、严格解析、允许列表 |
| 发一半后不动 | 占用连接与线程 | 整帧期限、会话总期限 |
| 不断发合法请求 | CPU、队列耗尽 | 限流、并发与工作量预算 |
| 改请求中的用户编号 | 越权 | 服务端会话身份、逐次授权 |
| 观察或改写网络流量 | 窃听、冒充 | 正确验证身份的 TLS |
| 把输入拼进日志、SQL 或命令 | 注入 | 固定模板、参数化接口 |

每条保护都要有对象、位置和可验证行为；不能只写“这里加安全检查”。

## 3. 第一关：长度、容量和整数范围

### 3.1 分清三种长度

1. **声明长度**：对方说要发多少，尚未可信。
2. **实际长度**：目前真的收到了多少，可能不够。
3. **缓冲区容量**：本机内存能放多少，由自己的程序决定。

正确流程是“读固定帧头 → 检查声明长度上下界 → 在容量以内收齐正文 → 解析”。不要先按对方的值分配内存，等分配完才检查。

### 3.2 不要让长度运算先溢出

**整数溢出**指结果超出类型范围。有符号整数溢出在 C 中属于未定义行为，不能假定一定回绕；无符号整数虽会按模回绕，仍可能绕过校验。

```c
/* 危险：相加可能先溢出 */
if (header_size + body_size <= capacity) { /* ... */ }

/* 先确保减法有效，再比较 */
if (header_size <= capacity && body_size <= capacity - header_size) {
    /* 这里才能计算 header_size + body_size */
}
```

给 `count` 个对象分配内存时，先确保每项大小 `item_size != 0`，再检查 `count <= SIZE_MAX / item_size`。`SIZE_MAX` 是 `size_t` 类型的最大值，不是推荐业务上限；业务应另设小得多的限制。

还要防止负数转成无符号类型后变成巨大正数，或把过大的 `size_t` 强转为 Windows 收发接口要求的 `int`。

### 3.3 限制不只针对单个字符串

| 对象 | 示例预算（不是通用生产参数） | 原因 |
| --- | --- | --- |
| 单帧正文 | 128 字节 | 控制内存和解析量 |
| 数组元素 | 100 项 | 控制循环和对象总量 |
| JSON 嵌套 | 8 层 | 避免过深递归 |
| 压缩输入 | 64 KiB | 控制接收量 |
| 解压输出 | 256 KiB | 避免小输入解出海量内容 |
| 待发送队列 | 每连接 64 KiB | 避免慢接收方堆满内存 |

**压缩炸弹**是小压缩数据解出极大内容的情况。必须在解压过程中限制输出总量与时间，不能只检查压缩包长度。

## 4. 第二关：编码、格式、字段和业务

### 4.1 按什么顺序校验

```text
长度 → 完整读取 → 编码/允许字节 → 语法
     → 字段类型/范围 → 字段间关系 → 身份/权限 → 操作
```

认证和解析可能交错，例如先读固定头提取凭据，但不能在缺少基本上限时解析庞大登录消息。优先进行低成本、能尽早拒绝的检查。

### 4.2 允许列表是什么

**允许列表**先规定“只接受什么”，例如命令只有 `PING/ADD/QUIT`，年龄只允许 0～150 的整数。

**拒绝列表**列出几个坏字符串，例如 `../`、`DROP`。它容易漏掉编码、大小写、分隔符等变体，不适合做主要保护。

自由聊天文本不能粗暴地只允许英文字母。应按字段用途分别规定长度、编码和输出方式。

### 4.3 数字必须完整解析

`atoi("12xyz")` 可能得到 12；`atoi("abc")` 得到 0，难区分非法输入与合法的 0，也缺乏可靠的溢出报告。

使用 `strtol` 时需要检查：有没有数字、`errno == ERANGE`、结束指针是否位于允许位置、值是否在业务范围。它还可能接受空白和正号，协议不允许时需额外检查。

本章代码用短小函数逐位解析：仅允许可选负号和 1～4 个数字，每次乘 10 前先检查是否会超出 1000，拒绝 `+1`、`1e2`、尾随字符和超大整数。

### 4.4 格式合法不等于业务合法

```json
{"op":"withdraw","amount":-100,"account_id":42}
```

这是可解析的 JSON，但负数取款不合理，账户 42 也不一定属于当前用户。

| 层次 | 检查问题 |
| --- | --- |
| 语法 | JSON 是否完整？有没有尾随垃圾？ |
| 结构 | 是否是对象？必填项是否存在？重复键怎样处理？ |
| 类型 | 金额是否为整数？是否拒绝字符串和布尔值替代？ |
| 范围 | 金额是否大于 0，是否超过单笔上限？ |
| 关系 | 开始时间是否不晚于结束时间？ |
| 权限 | 当前身份能否操作这个账户？ |
| 状态 | 账户是否冻结？检查余额与扣款是否不可分割？ |

**原子操作**指不能被其他请求插入而破坏一致性的操作。否则两个并发请求可能都看见余额充足，再分别扣款。

JSON 还需明确未知字段、数字精度、非标准 `NaN/Infinity` 和嵌套限制。不要对网络输入使用会执行代码的机制，例如 `eval` 或不可信的 `pickle.loads`。

### 4.5 编码、解码和规范化

**规范化**是将不同表示转成约定的一种表示。URL 中 `%2e` 表示 `.`；如果检查在解码前，使用在解码后，就可能得出不同结论。

推荐：约定解码层级 → 严格解码一次 → 按业务决定是否规范化 → 校验最终表示 → 之后使用同一结果。不要为了兼容反复解码。

- 非法 UTF-8 应按协议拒绝，不能静默替换后做身份比较。
- 用户名、路径的大小写与 Unicode 相似字符需要专门规则。
- 密码不能随意去空格或改变字符，这会改变用户的秘密。
- 零字节、换行、回车和终端控制字符是否允许，要按字段用途规定。

## 5. 第三关：不要让数据变成指令

### 5.1 格式化字符串与日志注入

```c
/* 错误：用户数据成为格式模板 */
printf(user_input);

/* 模板固定，数据作为参数；仍需保证字符串有效 */
printf("message=%s\n", validated_text);
```

`%s`、`%n` 是格式语法。固定模板避免格式化字符串漏洞，但日志还需要处理换行和终端控制字符。

**日志注入**指输入伪造看似由服务端写出的日志。可使用结构化日志、字段长度上限、控制字符转义。本章只记录固定事件，不打印原始正文。

### 5.2 不同输出位置使用不同安全接口

| 场景 | 危险方式 | 正确方向 |
| --- | --- | --- |
| SQL | 拼接输入成为查询语句 | 数据库参数绑定 |
| 系统命令 | 拼接输入交给 shell/`system` | 尽量避免；必要时固定程序、参数分开并校验 |
| HTML | 直接插入页面或脚本 | 根据输出位置正确编码 |
| 日志 | 输入成为模板或多行内容 | 固定事件、结构化字段、转义 |

输入校验不能取代这些安全接口。昵称包含单引号可以是合法数据，数据库仍应把它作为参数。

### 5.3 路径穿越

**路径穿越**是用 `../` 等访问允许目录以外的文件。Windows 还需考虑反斜杠、盘符、UNC 路径，不能只搜索 `../`。

优先让客户端提交文件编号，由服务端自己的表映射到文件，不让对方直接指定本机路径。

确实需要路径时，应定义根目录、绝对路径策略、规范化和符号链接规则。简单前缀检查可能把 `C:\data2` 当成 `C:\data` 的子目录；检查后对象被替换也可能绕过保护。生产程序要使用平台提供的安全文件/目录句柄方式，约束实际打开的对象。

### 5.4 服务端代连目标地址也要限制

如果允许“服务端替我访问这个 URL/IP”，对方可能访问内部管理接口或本机服务，这称为 **SSRF（服务端请求伪造）**。需要限制目标地址、端口、协议，并检查 DNS 解析和重定向后的实际目标。能连接不代表被业务授权连接。

## 6. 第四关：认证、授权和秘密

### 6.1 分清三个问题

| 名称 | 问题 | 例子 |
| --- | --- | --- |
| 认证 Authentication | 你是谁，有什么证据？ | 验证凭据或令牌 |
| 授权 Authorization | 这个身份能做什么？ | 用户 A 只能删除自己的消息 |
| 加密传输 | 途中怎样保护数据？ | TLS 保护通道 |

`{"user_id":1,"role":"admin"}` 只是客户端声明，不是管理员凭据。已经登录也不意味着能访问任意资源。

### 6.2 最小登录流程

```text
建立经过验证的 TLS 通道
 → 限制登录长度与频率 → 验证凭据
 → 服务端创建绑定身份、有有效期的会话
 → 后续从会话取得身份 → 每次检查具体资源权限
 → 退出、过期或撤销后失效
```

授权示意：

```text
current_user = 服务端验证后的会话身份
record = 根据 resource_id 查找记录
如果未登录：拒绝
如果不是所有者且没有明确管理权限：拒绝
否则：执行操作
```

默认拒绝没有明确允许的行为。仅隐藏客户端按钮，或只判断“已经登录”，都不是完整授权。

### 6.3 密码为什么不能明文保存

**哈希**把输入映射成摘要；密码需要专门设计的慢哈希，例如成熟库提供的 Argon2id、scrypt 等方案。普通 SHA-256 很快，不适合作为唯一的密码存储保护。

**盐（salt）**是每条记录自己的随机值，使相同密码不直接得到相同记录，并增加预计算成本。盐可与结果一起存储，不等于私钥或密码。

使用成熟库负责生成盐、保存参数、验证和升级；不要自写算法，实际强度参数应结合机器性能和并发预算配置。

登录错误可以统一为“身份或凭据不正确”，减少账户枚举；还需限制失败频率，并避免简单锁定策略被用来恶意锁死他人账户。

### 6.4 令牌如何管理

**令牌 token**代表访问资格；**Bearer token** 表示持有它的人就能使用，因此泄露很危险。

- 用密码学安全随机源生成，不用当前时间或 `rand()`。
- 通过经过验证的 TLS 传输，限制有效期、用途和权限，提供撤销办法。
- 不放在源码、Git、URL 查询参数、日志和聊天记录里。
- 环境变量可避免硬编码，但不是完整秘密管理系统。
- 比较秘密时使用成熟库的恒定时间比较接口，不自行发明密码学代码。

**恒定时间比较**旨在避免遇到第一个不同字节就退出，使耗时泄露匹配位置。它不能取代 TLS、随机性和限流。

### 6.5 重放与幂等

**重放**是重复使用以前的请求或凭据。合法扣款再次执行，可能扣两次钱。

根据业务使用有效期、一次性随机数、请求编号、服务端去重和幂等设计。**幂等**指同一操作重复请求，效果仍保持一致或只发生一次。

TLS 记录有自身保护，但不会替业务处理“用户又发了一遍扣款”。TLS 1.3 的 0-RTT 提前数据还存在特殊重放风险，有副作用的操作不能随意放进去。

- [ ] 身份来自服务端会话，不信任客户端填写的角色。

## 7. 第五关：TLS、证书与服务器身份

### 7.1 TLS 保护什么

TLS 是提供加密、完整性保护和身份验证的成熟通信协议。HTTPS 就是 HTTP 经过 TLS 传输。

```text
业务：PING / 登录 / 文件请求
          ↓
TLS：握手、验证身份、加密与完整性保护
          ↓
TCP：有序字节流
```

TCP 校验和、CRC 不能抵抗有意篡改。CRC 是循环冗余校验，主要用计算出的校验值发现部分偶然错误；Base64 只是换一种表示，不是加密。TLS 也不会替你校验字段、权限、SQL 或资源预算，不会隐藏所有地址、时机和流量长度信息。

### 7.2 证书相关词语

| 词语 | 解释 |
| --- | --- |
| 公钥/私钥 | 配对的密码学材料，私钥必须保密 |
| 证书 | 将公钥与身份（如域名）绑定并带有签名的文件 |
| CA | 证书颁发机构，客户端配置决定信任哪些机构 |
| 证书链 | 沿签发关系连接到可信机构的证书集合 |
| 主机名校验 | 证书中的身份是否匹配打算访问的主机 |
| SAN | 证书中的使用者备用名称，现代主机名校验主要依赖它 |

客户端至少验证证书链、有效期、目标主机名，并使用维护中的成熟 TLS 实现。“签发者可信”与“证书属于目标主机”必须同时满足。

证书只有 `DNS:localhost`，不等于可按 IP `127.0.0.1` 验证；IP 身份需要相应的 IP SAN。网络连接地址和验证目标身份可以在明确配置时分开，不能因此跳过校验。

### 7.3 单向 TLS、双向 TLS 和登录

常见 HTTPS 是客户端验证服务器；服务器并不因此知道用户账户是谁，通常还要应用层登录。

**双向 TLS（mTLS）**要求客户端也提供证书，常用于服务间通信。验证证书后仍要把该技术身份映射到具体权限。

### 7.4 常见误区

- 为了运行成功而关闭证书或主机名校验，会失去关键身份保证。
- 自签名证书适合明确建立信任的本机实验，不能对任何陌生证书都点击接受。
- TLS 握手、读写也需要时间与资源上限。
- 非阻塞 TLS 读取可能要求等待可写，写入也可能要求等待可读，不能直接照搬原始 Socket 逻辑。
- 采用维护中的库和现代配置，通常使用 TLS 1.2/1.3，不自己设计加密协议。

第 14 节会独立实验 TLS。本章 C 服务端专注输入校验，仍是明文 TCP，不向它发送真实凭据。

## 8. 第六关：资源预算、错误和权限

### 8.1 合法输入也可能耗尽资源

**拒绝服务 DoS**是让正常用户无法顺利使用服务。大量合法请求、慢连接、昂贵查询也能造成它。

| 资源 | 应设限制 |
| --- | --- |
| 时间 | 握手、整帧接收、业务处理、发送、会话总期限 |
| 内存 | 正文、解析对象、解压输出、待发送队列 |
| CPU | 递归深度、正则复杂度、密码验证并发 |
| 连接/任务 | 活跃连接、线程池、排队任务数量 |
| 频率 | 每连接、每账号、来源与全局速率 |
| 磁盘 | 日志、上传、保留时间与总量 |

`listen` 的 backlog 是待接收连接队列相关参数，不是活跃用户总数限制。只按 IP 限流还可能误伤共享网络用户，也可能被多来源绕过。

**限流**限制单位时间内速率；**配额**限制可消耗总量；**背压**是在下游处理不动时减少上游继续输入，避免无限排队。

### 8.2 本章时间和数量预算

每帧接收总期限 2 秒，每次发送最多 1 秒，会话总期限 15 秒，每连接最多 8 条请求。数字刻意较小，方便观察，不是生产通用值。

一次只服务一个连接，只能约束该连接占用多久，不能提供高并发或抵挡大量连接。后续要结合 [[事件循环]]、[[状态机与连接管理]] 和全局预算。

### 8.3 遇错回复还是关闭

| 错误 | 本章策略 | 原因 |
| --- | --- | --- |
| 长度为 0 或大于上限 | 直接关闭 | 不读取不可信大正文 |
| 截断、接收超时 | 直接关闭 | 没有完整消息，不能猜边界 |
| 正文非法字节 | 固定 `ERR TEXT` 后关闭 | 正文有限且已收全 |
| 命令/参数错误 | 固定错误后关闭 | 简化恢复状态 |
| 系统读写错误 | 固定事件日志并关闭 | 清理资源再接待下一连接 |

其他协议可以选择恢复，但必须有清楚的同步和状态规则，不能无限扫描、无限回复或反射任意输入。

### 8.4 日志和最小权限

日志适合记录事件名、错误类别、连接编号、有限长度、耗时与授权结果；不记录密码、令牌、私钥和完整敏感正文。

**最小权限**是只给服务完成工作需要的能力。普通高端口不需要管理员/root；只读服务不应拥有整个磁盘写权限。监听 `127.0.0.1` 减少远程暴露，但本机程序仍能连接，不等于认证。

## 9. 贯穿实验：SafeCalc/1 协议

### 9.1 实现范围

程序只提供公开的 `PING`、小整数加法和退出，不含账户、私密数据。SafeCalc 是实验名称，不代表完整安全产品。

实现：固定缓冲区、长度前置检查、严格 ASCII/数字解析、部分收发、非阻塞等待、固定期限、请求数上限、有限响应、固定日志。

未实现：TLS、登录/授权、并发、跨连接限流、全局 DoS 防护。第 6～8 节说明设计位置，第 14 节独立验证 TLS，不把两套实验误称为已经集成。

### 9.2 分帧格式

监听 **`127.0.0.1:19105`**，TCP 请求和响应均采用：

```text
[2 字节无符号大端正文长度 N][N 字节正文]
1 <= N <= 128
```

大端先发高位字节，长度不包含帧头。`PING` 的完整字节为：

```text
00 04 50 49 4E 47
----- -----------
长度    P I N G
```

正文没有换行和字符串结束零字节，直接在终端输入 `PING` 不符合二进制分帧规则。

### 9.3 正文规则

| 请求 | 规则 | 响应正文 |
| --- | --- | --- |
| `PING` | 精确大写 | `PONG` |
| `ADD a b` | 精确一个空格分隔，两个整数 | `OK 结果` |
| `QUIT` | 精确大写 | `BYE` 后关闭 |

整数：可选 `-`，后接 1～4 个数字，值限于 -1000～1000；允许 `0001`、`-0`；拒绝 `+1`、额外空格、小数、指数、尾随字符。和在 -2000～2000 内，用本实验的 `int` 安全。

正文只允许 ASCII `0x20`～`0x7E`，随后仍需语法校验。两个空格都可打印，但 `ADD 1  2` 不符合命令语法。

| 非法输入 | 处理 |
| --- | --- |
| 零字节、换行、中文 UTF-8 等 | `ERR TEXT` 后关闭 |
| 以 `ADD ` 开头但参数错误 | `ERR ARG` 后关闭 |
| 其他未知命令，如 `ping` | `ERR COMMAND` 后关闭 |
| 长度错误或未收齐 | 不回复，关闭 |

每个错误响应仍有长度前缀；第 8 条请求回复后关闭连接。

### 9.4 读代码的顺序

1. 常量：预算是什么。
2. `wait_until`、`transfer`：固定期限内完整收发。
3. `number`、`command`：严格解析。
4. `serve`：检查顺序、错误策略、会话预算。
5. `main`：平台初始化、监听、接待、清理。

两份源文件各自完整，不需要其他公共头文件。


## 10. Windows：完整 Winsock 服务端

### 10.1 保存为 `safe_windows.c`

先新建一个实验目录，将下面整个代码块保存到同名文件。不要把 Linux 代码与它拼在一起。源文件中的注释使用 ASCII，减少编译器源文件编码差异。

```c
#ifndef _WIN32_WINNT
#define _WIN32_WINNT 0x0600
#endif
#define WIN32_LEAN_AND_MEAN
#include <winsock2.h>
#include <ws2tcpip.h>
#include <windows.h>
#include <stdint.h>
#include <stdio.h>
#include <string.h>

typedef SOCKET net_t;
typedef int io_t;
#define SEND_FLAGS 0
#define SELECT_NFDS(s) 0
static int net_error(void) { return WSAGetLastError(); }
static int interrupted(int e) { return e == WSAEINTR; }
static int would_block(int e) { return e == WSAEWOULDBLOCK; }
static uint64_t now_ms(void) { return (uint64_t)GetTickCount64(); }
static int nonblocking(net_t s) {
    u_long mode = 1;
    return ioctlsocket(s, (long)FIONBIO, &mode) == 0;
}

#define MAX_BODY 128
#define MAX_REQUESTS 8
#define PORT 19105

static uint64_t earlier(uint64_t a, uint64_t b) {
    return a < b ? a : b;
}

/* 1 = ready, 0 = deadline, -1 = system error. */
static int wait_until(net_t s, int writing, uint64_t end) {
    for (;;) {
        uint64_t now = now_ms();
        if (now >= end) return 0;
        uint64_t left = end - now;
        struct timeval tv;
        tv.tv_sec = (long)(left / 1000);
        tv.tv_usec = (long)((left % 1000) * 1000);
        fd_set set;
        FD_ZERO(&set);
        FD_SET(s, &set);
        int r = select(SELECT_NFDS(s), writing ? NULL : &set,
                       writing ? &set : NULL, NULL, &tv);
        if (r > 0) return 1;
        if (r == 0) return 0;
        if (interrupted(net_error())) continue;
        return -1;
    }
}

/* 1 = complete, 0 = EOF, -1 = I/O error, -2 = deadline. */
static int transfer(net_t s, unsigned char *buf, size_t len,
                    int writing, uint64_t end) {
    size_t used = 0;
    while (used < len) {
        int ready = wait_until(s, writing, end);
        if (ready <= 0) return ready == 0 ? -2 : -1;
        /* Every caller passes at most 128 bytes. */
        io_t n = writing
            ? send(s, (const char *)buf + used, (int)(len - used), SEND_FLAGS)
            : recv(s, (char *)buf + used, (int)(len - used), 0);
        if (n > 0) { used += (size_t)n; continue; }
        if (n == 0) return 0;
        int e = net_error();
        if (interrupted(e) || would_block(e)) continue;
        return -1;
    }
    return 1;
}

static int reply(net_t s, const char *text, uint64_t session_end) {
    size_t n = strlen(text); /* Only server-created strings reach here. */
    if (n == 0 || n > MAX_BODY) return 0;
    unsigned char h[2] = {(unsigned char)(n >> 8), (unsigned char)n};
    uint64_t end = earlier(now_ms() + 1000, session_end);
    if (transfer(s, h, 2, 1, end) != 1) return 0;
    return transfer(s, (unsigned char *)text, n, 1, end) == 1;
}

/* Optional '-', 1..4 digits, numeric value -1000..1000. */
static int number(const char **cursor, int *out) {
    const char *p = *cursor;
    int sign = 1, value = 0, digits = 0;
    if (*p == '-') { sign = -1; ++p; }
    while (*p >= '0' && *p <= '9') {
        int digit = *p - '0';
        if (++digits > 4 || value > (1000 - digit) / 10) return 0;
        value = value * 10 + digit;
        ++p;
    }
    if (digits == 0) return 0;
    *out = sign * value;
    *cursor = p;
    return 1;
}

/* Return 1 to continue, 0 to close after the response. */
static int command(const char *body, char out[MAX_BODY + 1]) {
    if (strcmp(body, "PING") == 0) {
        strcpy(out, "PONG"); return 1;
    }
    if (strcmp(body, "QUIT") == 0) {
        strcpy(out, "BYE"); return 0;
    }
    if (strncmp(body, "ADD ", 4) == 0) {
        const char *p = body + 4;
        int a, b;
        if (!number(&p, &a) || *p != ' ') {
            strcpy(out, "ERR ARG"); return 0;
        }
        ++p;
        if (!number(&p, &b) || *p != '\0') {
            strcpy(out, "ERR ARG"); return 0;
        }
        snprintf(out, MAX_BODY + 1, "OK %d", a + b);
        return 1;
    }
    strcpy(out, "ERR COMMAND"); return 0;
}

static void serve(net_t s) {
    uint64_t session_end = now_ms() + 15000;
    for (int count = 0; count < MAX_REQUESTS; ++count) {
        unsigned char h[2], body[MAX_BODY + 1];
        uint64_t end = earlier(now_ms() + 2000, session_end);
        int r = transfer(s, h, 2, 0, end);
        if (r != 1) {
            puts(r == -2 ? "READ_TIMEOUT" : "HEADER_EOF_OR_IO"); return;
        }
        size_t n = ((size_t)h[0] << 8) | (size_t)h[1];
        if (n == 0 || n > MAX_BODY) { puts("BAD_LENGTH"); return; }
        /* Same end for header and body: partial progress adds no time. */
        r = transfer(s, body, n, 0, end);
        if (r != 1) {
            puts(r == -2 ? "READ_TIMEOUT" : "BODY_EOF_OR_IO"); return;
        }
        for (size_t i = 0; i < n; ++i) {
            if (body[i] < 0x20 || body[i] > 0x7e) {
                if (!reply(s, "ERR TEXT", session_end)) puts("WRITE_FAILED");
                puts("BAD_TEXT"); return;
            }
        }
        body[n] = '\0';
        char out[MAX_BODY + 1];
        int keep = command((const char *)body, out);
        if (!reply(s, out, session_end)) { puts("WRITE_FAILED"); return; }
        if (!keep) {
            puts(strcmp(out, "BYE") == 0 ? "QUIT" : "BAD_COMMAND_OR_ARG");
            return;
        }
        puts("OK");
    }
    puts("REQUEST_LIMIT");
}

int main(void) {
    WSADATA data;
    int startup = WSAStartup(MAKEWORD(2, 2), &data);
    if (startup != 0) { fprintf(stderr, "WSAStartup=%d\n", startup); return 1; }
    SOCKET listener = socket(AF_INET, SOCK_STREAM, IPPROTO_TCP);
    if (listener == INVALID_SOCKET) { WSACleanup(); return 1; }
    BOOL exclusive = TRUE;
    if (setsockopt(listener, SOL_SOCKET, SO_EXCLUSIVEADDRUSE,
                   (const char *)&exclusive, sizeof exclusive) != 0) {
        closesocket(listener); WSACleanup(); return 1;
    }
    struct sockaddr_in addr;
    memset(&addr, 0, sizeof addr);
    addr.sin_family = AF_INET;
    addr.sin_port = htons(PORT);
    addr.sin_addr.s_addr = htonl(INADDR_LOOPBACK);
    if (bind(listener, (struct sockaddr *)&addr, sizeof addr) == SOCKET_ERROR ||
        listen(listener, 8) == SOCKET_ERROR) {
        fprintf(stderr, "bind/listen=%d\n", WSAGetLastError());
        closesocket(listener); WSACleanup(); return 1;
    }
    setvbuf(stdout, NULL, _IONBF, 0);
    printf("LISTEN 127.0.0.1:%d\n", PORT);
    for (;;) {
        SOCKET s = accept(listener, NULL, NULL);
        if (s == INVALID_SOCKET) {
            if (interrupted(net_error())) continue;
            fprintf(stderr, "accept=%d\n", WSAGetLastError()); break;
        }
        puts("ACCEPT");
        if (nonblocking(s)) serve(s);
        else puts("NONBLOCK_FAILED");
        closesocket(s);
        puts("CLOSE");
    }
    closesocket(listener);
    WSACleanup();
    return 1;
}
```

### 10.2 Windows 平台要点

- `WSAStartup` 初始化 Winsock；正常错误清理路径中使用 `WSACleanup`。
- `SOCKET` 不应当作 Linux 的 `int` 文件描述符；关闭使用 `closesocket`。
- `ioctlsocket(..., FIONBIO, ...)` 将已接收的连接设为非阻塞。显式转换 `(long)FIONBIO` 是匹配此接口命令参数的类型。
- Windows `select` 忽略第一个参数；本例传 0。一个集合里只有一个 Socket，不会触及集合容量上限。
- `SO_EXCLUSIVEADDRUSE` 在绑定前设置，避免随意复用监听端口；不要机械照搬 Linux 的 `SO_REUSEADDR`。
- `GetTickCount64` 计算相对经过时间；不是用来记录日期的函数。

## 11. Linux：完整 Socket 服务端

### 11.1 保存为 `safe_linux.c`

下面是独立源文件。适用于 Linux/WSL，不能直接拿去用 Windows 原生编译器编译。

```c
#define _POSIX_C_SOURCE 200809L
#include <sys/types.h>
#include <sys/socket.h>
#include <sys/select.h>
#include <netinet/in.h>
#include <unistd.h>
#include <fcntl.h>
#include <errno.h>
#include <time.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

typedef int net_t;
typedef ssize_t io_t;
#define SEND_FLAGS MSG_NOSIGNAL
#define SELECT_NFDS(s) ((s) + 1)
static int net_error(void) { return errno; }
static int interrupted(int e) { return e == EINTR; }
static int would_block(int e) { return e == EAGAIN || e == EWOULDBLOCK; }
static uint64_t now_ms(void) {
    struct timespec t;
    if (clock_gettime(CLOCK_MONOTONIC, &t) != 0) {
        perror("clock_gettime"); exit(1);
    }
    return (uint64_t)t.tv_sec * 1000 + (uint64_t)t.tv_nsec / 1000000;
}
static int nonblocking(net_t s) {
    int flags = fcntl(s, F_GETFL, 0);
    return flags >= 0 && fcntl(s, F_SETFL, flags | O_NONBLOCK) == 0;
}

#define MAX_BODY 128
#define MAX_REQUESTS 8
#define PORT 19105

static uint64_t earlier(uint64_t a, uint64_t b) {
    return a < b ? a : b;
}

/* 1 = ready, 0 = deadline, -1 = system error. */
static int wait_until(net_t s, int writing, uint64_t end) {
    for (;;) {
        uint64_t now = now_ms();
        if (now >= end) return 0;
        uint64_t left = end - now;
        struct timeval tv;
        tv.tv_sec = (long)(left / 1000);
        tv.tv_usec = (long)((left % 1000) * 1000);
        fd_set set;
        FD_ZERO(&set);
        FD_SET(s, &set);
        int r = select(SELECT_NFDS(s), writing ? NULL : &set,
                       writing ? &set : NULL, NULL, &tv);
        if (r > 0) return 1;
        if (r == 0) return 0;
        if (interrupted(net_error())) continue;
        return -1;
    }
}

/* 1 = complete, 0 = EOF, -1 = I/O error, -2 = deadline. */
static int transfer(net_t s, unsigned char *buf, size_t len,
                    int writing, uint64_t end) {
    size_t used = 0;
    while (used < len) {
        int ready = wait_until(s, writing, end);
        if (ready <= 0) return ready == 0 ? -2 : -1;
        /* Every caller passes at most 128 bytes. */
        io_t n = writing
            ? send(s, (const char *)buf + used, (int)(len - used), SEND_FLAGS)
            : recv(s, (char *)buf + used, (int)(len - used), 0);
        if (n > 0) { used += (size_t)n; continue; }
        if (n == 0) return 0;
        int e = net_error();
        if (interrupted(e) || would_block(e)) continue;
        return -1;
    }
    return 1;
}

static int reply(net_t s, const char *text, uint64_t session_end) {
    size_t n = strlen(text); /* Only server-created strings reach here. */
    if (n == 0 || n > MAX_BODY) return 0;
    unsigned char h[2] = {(unsigned char)(n >> 8), (unsigned char)n};
    uint64_t end = earlier(now_ms() + 1000, session_end);
    if (transfer(s, h, 2, 1, end) != 1) return 0;
    return transfer(s, (unsigned char *)text, n, 1, end) == 1;
}

/* Optional '-', 1..4 digits, numeric value -1000..1000. */
static int number(const char **cursor, int *out) {
    const char *p = *cursor;
    int sign = 1, value = 0, digits = 0;
    if (*p == '-') { sign = -1; ++p; }
    while (*p >= '0' && *p <= '9') {
        int digit = *p - '0';
        if (++digits > 4 || value > (1000 - digit) / 10) return 0;
        value = value * 10 + digit;
        ++p;
    }
    if (digits == 0) return 0;
    *out = sign * value;
    *cursor = p;
    return 1;
}

/* Return 1 to continue, 0 to close after the response. */
static int command(const char *body, char out[MAX_BODY + 1]) {
    if (strcmp(body, "PING") == 0) {
        strcpy(out, "PONG"); return 1;
    }
    if (strcmp(body, "QUIT") == 0) {
        strcpy(out, "BYE"); return 0;
    }
    if (strncmp(body, "ADD ", 4) == 0) {
        const char *p = body + 4;
        int a, b;
        if (!number(&p, &a) || *p != ' ') {
            strcpy(out, "ERR ARG"); return 0;
        }
        ++p;
        if (!number(&p, &b) || *p != '\0') {
            strcpy(out, "ERR ARG"); return 0;
        }
        snprintf(out, MAX_BODY + 1, "OK %d", a + b);
        return 1;
    }
    strcpy(out, "ERR COMMAND"); return 0;
}

static void serve(net_t s) {
    uint64_t session_end = now_ms() + 15000;
    for (int count = 0; count < MAX_REQUESTS; ++count) {
        unsigned char h[2], body[MAX_BODY + 1];
        uint64_t end = earlier(now_ms() + 2000, session_end);
        int r = transfer(s, h, 2, 0, end);
        if (r != 1) {
            puts(r == -2 ? "READ_TIMEOUT" : "HEADER_EOF_OR_IO"); return;
        }
        size_t n = ((size_t)h[0] << 8) | (size_t)h[1];
        if (n == 0 || n > MAX_BODY) { puts("BAD_LENGTH"); return; }
        /* Same end for header and body: partial progress adds no time. */
        r = transfer(s, body, n, 0, end);
        if (r != 1) {
            puts(r == -2 ? "READ_TIMEOUT" : "BODY_EOF_OR_IO"); return;
        }
        for (size_t i = 0; i < n; ++i) {
            if (body[i] < 0x20 || body[i] > 0x7e) {
                if (!reply(s, "ERR TEXT", session_end)) puts("WRITE_FAILED");
                puts("BAD_TEXT"); return;
            }
        }
        body[n] = '\0';
        char out[MAX_BODY + 1];
        int keep = command((const char *)body, out);
        if (!reply(s, out, session_end)) { puts("WRITE_FAILED"); return; }
        if (!keep) {
            puts(strcmp(out, "BYE") == 0 ? "QUIT" : "BAD_COMMAND_OR_ARG");
            return;
        }
        puts("OK");
    }
    puts("REQUEST_LIMIT");
}

int main(void) {
    int listener = socket(AF_INET, SOCK_STREAM, 0);
    if (listener < 0) { perror("socket"); return 1; }
    int reuse = 1;
    if (setsockopt(listener, SOL_SOCKET, SO_REUSEADDR, &reuse, sizeof reuse) < 0) {
        perror("setsockopt"); close(listener); return 1;
    }
    struct sockaddr_in addr;
    memset(&addr, 0, sizeof addr);
    addr.sin_family = AF_INET;
    addr.sin_port = htons(PORT);
    addr.sin_addr.s_addr = htonl(INADDR_LOOPBACK);
    if (bind(listener, (struct sockaddr *)&addr, sizeof addr) < 0 ||
        listen(listener, 8) < 0) {
        perror("bind/listen"); close(listener); return 1;
    }
    setvbuf(stdout, NULL, _IONBF, 0);
    printf("LISTEN 127.0.0.1:%d\n", PORT);
    for (;;) {
        int s = accept(listener, NULL, NULL);
        if (s < 0) {
            if (errno == EINTR) continue;
            perror("accept"); break;
        }
        puts("ACCEPT");
        /* FD_SET would be undefined for descriptors outside this range. */
        if (s < FD_SETSIZE && nonblocking(s)) serve(s);
        else puts("FD_LIMIT_OR_NONBLOCK_FAILED");
        close(s);
        puts("CLOSE");
    }
    close(listener);
    return 1;
}
```

### 11.2 Linux 平台要点

- Socket 是整数文件描述符，失败通常是 `-1`，关闭用 `close`。
- `fcntl` 在保留已有标志的基础上加入 `O_NONBLOCK`，不能直接丢掉原有标志。
- `select` 第一个参数是待监视最大描述符加 1；`fd_set` 和超时参数每次等待都重新构造。
- 在 Linux 上，`FD_SET` 不能接收大于等于 `FD_SETSIZE` 的描述符。本例先检查再调用，不能只认为“当前只有一个连接就肯定没问题”。
- `MSG_NOSIGNAL` 避免向已断开的连接发送时由 `SIGPIPE` 信号直接终止进程，写失败仍需根据返回值处理。这是 Linux 示例，不保证可原样移植到所有类 Unix 系统。
- `SO_REUSEADDR` 用于常见重启场景，不等于随意允许多个程序同时占用同一监听端点；端口确实被占用时仍应排查。

### 11.3 两份代码共同的关键逻辑

**第一步：先读取 2 字节帧头。** `transfer` 用 `used` 保存进度，读多少推进多少，直到读满。它不会把一次 `recv` 当作一条消息。

**第二步：先查长度，再收正文。** `n` 为 0 或大于 128 时马上返回；不会按恶意长度申请内存，也不会尝试丢弃几 GB 后继续同步。

**第三步：帧头和正文共用一个截止时间。** `end` 在一帧开始时计算，只计算一次；读到部分数据不会刷新期限。`earlier` 取两个期限中较早的那个，确保整帧预算不能越过会话预算。

**第四步：完整收到且验证允许字节后才补零。** `body` 有 129 个位置，正文最多占 128 个，`body[n]` 保留给结束符。内部零字节此前已被拒绝，因此后续字符串函数不会看到“半个正文”。

**第五步：参数解析既检查范围，也检查终点。** `number` 返回后还要检查分隔符；第二个数字后必须是字符串结束。否则 `ADD 1 2x` 可能被误接受。

**第六步：响应也要有限。** `reply` 只接收服务端自己生成的短字符串，同一发送期限覆盖帧头和正文。这里的 `strlen` 不作用于未经校验的网络缓冲区。

**第七步：任何退出路径都回到连接所有者清理。** `serve` 返回后，`main` 关闭当前连接，再接受下一个。不会仅因一条请求有错就退出整个服务端。

> 为让新手集中阅读检查流程，日志将部分 EOF/系统错误合并为同一固定事件。工程版可保存原始错误码、区分连接边界上的正常 EOF 与半帧 EOF，并增加连接编号和计数；不要因此打印秘密或未转义正文。

### 11.4 为什么这里能使用某些字符串函数

安全性取决于数据来源和边界，不能只背“某个函数安全/不安全”。

| 代码 | 本例满足的使用条件 |
| --- | --- |
| `strcpy(out, "PONG")` | 来源是固定短字面量，目标已知有 129 字节容量 |
| `strcmp(body, "PING")` | 正文已收齐、无内部零字节、末尾已在界内补零 |
| `strlen(text)` | 只处理服务端生成的有限响应，随后仍检查上限 |
| `snprintf(out, ..., "OK %d", a + b)` | 模板固定，两个数范围已限制，结果很短 |

不要把以上条件删掉，再将函数直接用在原始网络缓冲区上。`strncpy` 也不是自动安全替代品：它可能不补结束符，并且会改变截断行为，仍需明确容量与协议语义。

`transfer` 的四种返回值是本章自己约定的：1 表示完整完成，0 表示读到关闭或本次发送无法继续，-1 表示系统错误，-2 表示期限用尽。它们不是 `recv` 原生返回值，调用处必须区分。

## 12. 测试客户端、编译和运行

### 12.1 共用 Python 3 测试客户端：`probe.py`

Python 标准库的 Socket 接口在这两个平台上都能工作，因此客户端只维护一份。平台相关的 C 代码已经完全分开；下面的启动命令也按平台分别列出。

先认识四个语法：`with` 在退出代码块时关闭连接；`b"PING"` 是字节；`struct.pack("!H", n)` 将数字写成 2 字节大端；`assert` 在实际结果与预期不同的时候让测试失败。请用普通 `python` 启动，不加会关闭断言的 `-O`。

```python
import socket
import struct
import sys
import time

HOST, PORT = "127.0.0.1", 19105


def frame(body):
    return struct.pack("!H", len(body)) + body


def exact(s, n):
    data = bytearray()
    while len(data) < n:
        part = s.recv(n - len(data))
        if not part:
            raise AssertionError("response truncated")
        data.extend(part)
    return bytes(data)


def response(s):
    n = struct.unpack("!H", exact(s, 2))[0]
    assert 1 <= n <= 128, ("bad response length", n)
    return exact(s, n)


def closed(s):
    try:
        data = s.recv(1)
    except (ConnectionResetError, ConnectionAbortedError):
        return  # Reset/abort also means the connection has terminated.
    assert data == b"", ("expected close, got", data)
    # A socket.timeout is intentionally NOT accepted as a pass.


def run(mode):
    with socket.create_connection((HOST, PORT), timeout=4) as s:
        s.settimeout(4)
        if mode == "normal":
            for req, want in [(b"PING", b"PONG"),
                              (b"ADD -1000 1000", b"OK 0"),
                              (b"ADD 1000 1000", b"OK 2000"),
                              (b"ADD -0 0001", b"OK 1"),
                              (b"QUIT", b"BYE")]:
                s.sendall(frame(req))
                got = response(s)
                assert got == want, (got, want)
            closed(s)
        elif mode == "split":
            for value in frame(b"PING"):
                s.sendall(bytes([value]))
                time.sleep(0.03)
            assert response(s) == b"PONG"
        elif mode == "merged":
            s.sendall(frame(b"PING") + frame(b"ADD 1 2") + frame(b"QUIT"))
            assert [response(s) for _ in range(3)] == [b"PONG", b"OK 3", b"BYE"]
            closed(s)
        elif mode in {"zero", "oversize"}:
            s.sendall(struct.pack("!H", 0 if mode == "zero" else 129))
            closed(s)
        elif mode in {"trunc-header", "trunc-body"}:
            s.sendall(b"\x00" if mode == "trunc-header" else b"\x00\x04PI")
            s.shutdown(socket.SHUT_WR)
            closed(s)
        elif mode == "idle":
            closed(s)  # Server must terminate the idle connection, about 2 s.
        elif mode == "slow":
            for value in frame(b"PING"):
                try:
                    s.sendall(bytes([value]))
                except (BrokenPipeError, ConnectionResetError, ConnectionAbortedError):
                    break
                time.sleep(0.55)
            closed(s)
        elif mode == "limit":
            for _ in range(8):
                s.sendall(frame(b"PING"))
                assert response(s) == b"PONG"
            closed(s)
        else:
            bad = {
                "nul": (b"PING\x00", b"ERR TEXT"),
                "newline": (b"PING\n", b"ERR TEXT"),
                "utf8": ("你好".encode("utf-8"), b"ERR TEXT"),
                "unknown": (b"ping", b"ERR COMMAND"),
                "maxbody": (b"X" * 128, b"ERR COMMAND"),
                "range": (b"ADD 1001 0", b"ERR ARG"),
                "huge-int": (b"ADD " + b"9" * 80 + b" 0", b"ERR ARG"),
                "suffix": (b"ADD 1 2x", b"ERR ARG"),
                "plus": (b"ADD +1 2", b"ERR ARG"),
                "extra-space": (b"ADD 1  2", b"ERR ARG"),
                "negative-only": (b"ADD - 2", b"ERR ARG"),
            }
            body, want = bad[mode]
            s.sendall(frame(body))
            got = response(s)
            assert got == want, (got, want)
            closed(s)
    print("PASS", mode)


CASES = ["normal", "split", "merged", "zero", "oversize", "trunc-header",
         "trunc-body", "nul", "newline", "utf8", "unknown", "maxbody", "range",
         "huge-int", "suffix", "plus", "extra-space", "negative-only",
         "idle", "slow", "limit"]

if __name__ == "__main__":
    mode = sys.argv[1] if len(sys.argv) > 1 else "normal"
    if mode not in CASES + ["all"]:
        raise SystemExit("mode must be one of: " + ", ".join(CASES + ["all"]))
    started = time.monotonic()
    for case in CASES if mode == "all" else [mode]:
        run(case)
    print(f"elapsed={time.monotonic() - started:.2f}s")
```

### 12.4 第一轮成功输出怎么读

`normal` 在同一连接内依次验证：

```text
ADD 1000 1000     → OK 2000
ADD -0 0001      → OK 1
QUIT              → BYE，然后断开
```

客户端显示 `PASS normal` 与耗时；它用断言检查了真正的协议响应。服务端大致输出：

```text
ACCEPT
OK
OK

```

`OK` 日志表示一次合法非退出请求完成，不是把响应正文打印出来。仅看“服务端还没崩溃”不足以说明校验正确。

### 12.5 异常测试矩阵：先预测再运行

`all` 顺序执行 21 个用例，各用例独立连接；整组通常几秒到十几秒，取决于调度和计时。预期每项都有 `PASS`，最后服务端仍保持监听。

| 模式 | 发送内容/行为 | 预期 | 主要日志 |
| --- | --- | --- | --- |
| `normal` | 五条正常请求 | 所有响应正确，QUIT 后关 | `OK`、`QUIT` |
| `split` | 每次只发送一个字节 | `PONG` | `OK` |
| `merged` | 三帧拼在一次发送 | 三条响应顺序正确 | `OK`、`QUIT` |
| `zero` | 声明长度 0 | 不回复，关连接 | `BAD_LENGTH` |
| `oversize` | 只发长度 129 的帧头 | 不等待正文，关连接 | `BAD_LENGTH` |
| `trunc-header` | 一字节帧头后关闭发送方向 | 关闭，无响应 | `HEADER_EOF_OR_IO` |
| `trunc-body` | 声明 4 字节，只发 `PI` 后半关闭 | 关闭，无响应 | `BODY_EOF_OR_IO` |
| `nul` | `PING` 后有零字节 | `ERR TEXT` 后关 | `BAD_TEXT` |
| `newline` | `PING` 后有换行 | `ERR TEXT` 后关 | `BAD_TEXT` |
| `utf8` | 中文 UTF-8 | `ERR TEXT` 后关 | `BAD_TEXT` |
| `unknown` | 小写 `ping` | `ERR COMMAND` 后关 | `BAD_COMMAND_OR_ARG` |
| `maxbody` | 恰好 128 个 `X` | 长度通过，命令错误后关 | `BAD_COMMAND_OR_ARG` |
| `range` | `ADD 1001 0` | `ERR ARG` 后关 | `BAD_COMMAND_OR_ARG` |
| `huge-int` | 80 位整数 | `ERR ARG` 后关 | `BAD_COMMAND_OR_ARG` |
| `suffix` | `ADD 1 2x` | `ERR ARG` 后关 | `BAD_COMMAND_OR_ARG` |
| `plus` | `ADD +1 2` | `ERR ARG` 后关 | `BAD_COMMAND_OR_ARG` |
| `extra-space` | `ADD 1  2` | `ERR ARG` 后关 | `BAD_COMMAND_OR_ARG` |
| `negative-only` | `ADD - 2` | `ERR ARG` 后关 | `BAD_COMMAND_OR_ARG` |
| `idle` | 连接后不发数据 | 约 2 秒后服务端关 | `READ_TIMEOUT` |
| `slow` | 每隔 0.55 秒发一个字节 | 不能刷新期限，最终关 | `READ_TIMEOUT` |
| `limit` | 同一连接连续 8 次 PING | 8 条 PONG 后关 | `REQUEST_LIMIT` |

`maxbody` 的错误类别很重要：它证明 128 字节仍会被完整解析，而不是被错误地当成超长。`oversize` 只发帧头，不必真的构造大正文。

单项测试命令分平台如下：

```powershell

python .\probe.py oversize
python .\probe.py trunc-body
python .\probe.py slow
python .\probe.py normal
```

```bash
# Linux Bash，服务端另一个终端保持运行

python3 ./probe.py trunc-body
python3 ./probe.py slow
python3 ./probe.py normal
```

最后再运行 `normal`，验证出错连接没有破坏后续服务。

### 12.6 为什么断开有时是 EOF，有时是 reset/abort

TCP 关闭、未读数据和对端继续发送的时机不同，客户端可能看到 `recv` 返回空字节，也可能看到连接重置或 Windows 的连接中止。本脚本将这些视为“连接已终止”。

但 `socket.timeout` 不算通过，因为它只能说明客户端等得不耐烦，不能证明服务端已经释放连接。应同时对照服务端的固定事件日志。`slow` 客户端会继续睡眠和尝试发送，所以它的总用时可能大于服务端 2 秒的处理期限。

测试中的 `shutdown(SHUT_WR)` 是只关闭自己的发送方向，仍保留接收方向，用于检验服务端收到半帧后的行为；它与立刻关闭整个 Socket 不同。

### 13.1 环境和运行错误

| 现象 | 常见原因 | 排查方法 |
| --- | --- | --- |
| 找不到 `gcc` | 未安装或 PATH 未配置 | 回到 [[Socket编程环境]]；确认使用对应平台编译器 |
| `winsock2.h` 找不到 | 用了 Linux 工具链编译 Windows 文件，或开发环境不完整 | 分清平台、文件与编译器 |

| Windows 绑定错误 10013 | 端口权限、系统保留或安全软件限制 | 检查系统策略，必要时选另一个本机高端口并同步客户端 |

| 连接成功却无正常回复 | 发送的是纯文本、长度包含帧头、字节序错 | 用提供的客户端核对完整字节 |

| 修改代码后行为没变 | 忘记重新编译，或运行了其他目录里的程序 | 停旧进程、重编译、核对可执行文件路径 |

Windows 查看监听端点和进程号：

```powershell
    Select-Object LocalAddress, LocalPort, OwningProcess
```

Linux 查看监听端点：


### 13.2 代码里最容易写错的地方

| 错误思路 | 为什么错 | 改正 |
| --- | --- | --- |
| 客户端已经限制长度，服务端不用检查 | 客户端可以被替换 | 服务端独立校验 |
| `recv` 返回多少就处理多少 | 可能只有半帧 | 完整分帧后处理 |
| 接收后直接 `%s` / `strlen` | 未保证结束符，可能有内部零字节 | 保存长度，验证后再转字符串 |
| 只看转换出来的数字 | 可能留下 `xyz`，也可能溢出 | 检查完整消费和范围 |
| 收到一点数据就延长 2 秒 | 慢发送可无限拖延 | 共用整帧绝对期限 |
| 先 `select`，然后用阻塞 Socket 大量读写 | 就绪不保证整个操作全部完成 | 非阻塞 + 进度 + 截止时间 |
| 使用 `assert` 检查服务端输入 | 某些构建会关闭断言 | 外部输入用正常分支拒绝；本章客户端断言仅用于测试 |
| 错误时只 `return`，忘了关闭连接 | 连接/句柄泄漏 | 由明确所有者统一清理 |
| 加了 TLS，就不再检查权限 | TLS 不理解业务资源归属 | 每条受保护请求授权 |
| 记录完整登录请求便于调试 | 日志成为凭据泄露来源 | 只记必要元数据、脱敏和限长 |

### 13.3 怎样一步步定位问题

1. 先确认进程是否还在、端口是否正确、是不是同一个操作系统环境。
2. 运行 `normal`，排除基础连接和旧程序问题。
3. 一次运行一个异常用例，对照预期响应和固定日志。
4. 怀疑边界时打印有限的长度数值，或在调试器里查看 `n`、`used`、`end`，不要临时打印秘密。
5. 区分“协议拒绝”“网络断开”“等待超时”和“程序崩溃”。四者不应该都被叫作“连接失败”。
6. 修改后重新运行相关用例与 `normal`，确认没有破坏后续接待。

注意：`split` 的客户端拿到 `PONG` 后结束连接，服务端下轮读取可能打印 `HEADER_EOF_OR_IO`；这是教学日志合并类别的结果，不意味着上一条 PING 失败。

## 14. 独立 TLS 实验：信任证书与核对主机名

### 14.1 实验目的和范围

本实验不改动 SafeCalc，也不把明文 C 程序自动升级为 TLS。我们让 OpenSSL 提供一个本机 HTTPS 测试端点，再用 Python 客户端验证三种情况：

1. 明确信任本次生成的证书，主机名匹配：通过。
2. 没有信任这张自签名证书：拒绝。
3. 信任证书，但目标主机名不匹配：仍然拒绝。

工具要求：OpenSSL 3.x、带 `ssl` 标准库的 Python 3。OpenSSL 是成熟 TLS 工具和库；`s_server -www` 仅用于教学，会返回测试信息页，不是生产 Web 服务。

证书中的名称为 `localhost`，监听地址为 `127.0.0.1:19443`。实验私钥不加口令，是为了本机自动启动；请只放在自己的实验目录，不提交到 Git、不用于真实服务、不发送给别人。证书文件可以公开，私钥不行。

### 14.2 Windows：生成证书和启动 TLS 服务

在实验目录执行以下 PowerShell 命令。如果 `openssl` 找不到，先配置可信来源的 OpenSSL 3.x 工具，或在 WSL 按 Linux 步骤完成整组实验；Windows 自带的 PowerShell 不保证包含它。

```powershell
Set-Location "$env:USERPROFILE\socket-security-lab"
openssl version
openssl req -x509 -newkey rsa:2048 -sha256 -noenc -days 2 -keyout localhost.key -out localhost.crt -subj "/CN=localhost" -addext "subjectAltName=DNS:localhost"
openssl x509 -in localhost.crt -noout -dates -ext subjectAltName
```

`-days 2` 表示只用于短期实验；过期后重新生成，并使用同一组对应的证书和私钥。输出应包含 `DNS:localhost`。

终端 A 启动并保持运行：

```powershell
openssl s_server -accept 127.0.0.1:19443 -cert localhost.crt -key localhost.key -www -min_protocol TLSv1.2
```

### 14.3 Linux：生成证书和启动 TLS 服务

### 14.4 共用客户端：保存为 `tls_probe.py`

这份 Python 代码与操作系统无关，Windows 和 Linux 使用同一内容。`create_default_context` 保留证书和主机名校验；`cafile` 仅为这次实验显式信任自己刚生成的证书，不会修改系统的全局信任库。

`server_hostname` 指明期望验证的服务器身份，并通常用于 TLS 的 SNI（让服务端知道客户端想访问哪个名称）。它不是简单把连接地址改一下。

```python
import socket
import ssl
import sys
import time

mode = sys.argv[1] if len(sys.argv) > 1 else "trusted"
if mode not in {"trusted", "untrusted", "wrong-host"}:
    raise SystemExit("use: trusted | untrusted | wrong-host")

context = (ssl.create_default_context() if mode == "untrusted"
           else ssl.create_default_context(cafile="localhost.crt"))
context.minimum_version = ssl.TLSVersion.TLSv1_2
name = "wrong.example" if mode == "wrong-host" else "localhost"

try:
    with socket.create_connection(("127.0.0.1", 19443), timeout=3) as raw:
        with context.wrap_socket(raw, server_hostname=name) as secure:
            if mode != "trusted":
                raise AssertionError("certificate validation unexpectedly passed")
            secure.sendall(b"GET / HTTP/1.0\r\nHost: localhost\r\n\r\n")
            data = bytearray()
            end = time.monotonic() + 3
            while b"\r\n" not in data:
                left = end - time.monotonic()
                if left <= 0 or len(data) >= 1024:
                    raise AssertionError("status line timeout or too large")
                secure.settimeout(left)
                part = secure.recv(min(256, 1024 - len(data)))
                if not part:
                    raise AssertionError("HTTP status line truncated")
                data.extend(part)
            status = bytes(data).split(b"\r\n", 1)[0]
            assert status.startswith(b"HTTP/1.0 200"), status
            print("PASS trusted", secure.version(), status.decode("ascii"))
except ssl.SSLCertVerificationError as exc:
    if mode == "trusted":
        raise
    print("PASS", mode, "certificate rejected:", exc.verify_message)
```

终端 B 必须位于存放 `localhost.crt` 和 `tls_probe.py` 的目录。

```powershell

```

```bash

```

`untrusted` 和 `wrong-host` 的 PASS 表示客户端正确拒绝了证书，不表示建立了不安全连接。若连接被拒绝、文件找不到或其他网络错误，脚本仍会报错，不会伪装为验证成功。

### 14.6 TLS 错误如何理解

| 现象 | 应检查什么 |
| --- | --- |
| trusted 仍报 self-signed | 是否从正确目录读到对应证书，服务端是否还在使用旧证书 |
| hostname mismatch | 证书 SAN 与 `server_hostname` 是否一致 |
| certificate has expired / not yet valid | 实验机器时间、证书起止时间，是否需要重新生成 |
| 找不到 `localhost.crt` | 当前工作目录和文件名 |
| connection refused | OpenSSL 是否启动，是否监听 19443 |
| 旧工具不认识 `-noenc` 或协议选项 | 核对 `openssl version`，使用本节要求的 3.x 工具 |

解决办法是修正信任、名称、时间和文件配置，不是关闭验证。

### 15.1 基础理解题

1. 声明长度、实际长度、缓冲区容量分别是什么？为什么不能只检查其中一个？

5. JSON 能解析成功，是否足以允许执行取款？列出至少三项额外检查。
6. 为什么“登录了”和“能删除这条消息”不是一回事？
7. Base64、CRC、密码哈希、TLS 分别解决什么问题？
8. 为什么 TLS 证书链正确，主机名不匹配仍应拒绝？
9. 如果每次收到字节就重新给 2 秒，`slow` 会暴露什么问题？
10. 每连接最多 8 条请求，能否阻止对方不断建立新连接？还需要什么？

<details>
<summary>基础题参考答案：尝试后展开</summary>

1. 声明长度由对方填写，实际长度来自本次累计接收，容量由本机分配决定；三者分别对应合法上限、完整性和内存边界，缺一不可。
2. 数组有效下标仅 0～127，需要额外一个位置保存结束符。
3. 不能。还要根据分帧规则收齐正文，再检查语法和参数。短输入也可能只是半帧。
4. 前两项均 `ERR ARG` 后关闭；第三项 `OK 0`，连接可继续使用。
5. 字段类型、金额范围、当前身份的账户权限、余额/冻结状态及并发一致性等。
6. 登录证明身份，授权判断这个身份对这个具体对象有什么权利。
7. Base64 是表示转换；CRC 检测部分偶然错误；密码哈希用于验证密码时避免保存明文；TLS 保护传输并验证对端身份。它们不能互相取代。
8. 可信机构签发给别人的证书不能证明它是你想连接的服务。
9. 对方只要在每次超时前发一点就能一直占用资源；固定整帧期限避免这种刷新。
10. 不能。还需要跨连接/账号/来源与全局限流、并发和队列预算，必要时配合网络层防护。

</details>

### 15.2 手算与规则题

1. 正文 128 字节的两字节大端长度是 `00 80`。129、256、65535 分别怎样表示？本章接受哪些？
2. 容量为 128，头部占 8，正文长 121，为什么不能放入？若长度运算可能溢出，怎样在相加前检查？
3. 如果用户名同时要求“最多 20 个字符”和“最多 60 个 UTF-8 字节”，应该在什么阶段检查哪条规则？
4. 客户端发 `00 04 50 49` 后不再发送，是长度错误、截断 EOF，还是读取超时？如果随后关闭发送方向，分类怎样改变？

<details>
<summary>手算与规则题提示</summary>

1. `00 81`、`01 00`、`FF FF`。本章上限是 128，三者全部拒绝，不能因为两字节装得下就接受。
2. 总长 129 超容量；先检查 `header <= capacity`，再检查 `body <= capacity - header`。
3. 收取完整字段前先限制原始字节量；严格 UTF-8 解码后再按明确的字符计数规则检查。用户感知的一个“字”还可能由多个 Unicode 码点组成，需求要进一步定义。
4. 等不到后续数据时属于读取超时；如果读到 EOF，属于正文未收齐的截断。声明长度 4 本身合法。

</details>

| 进阶 | 支持 UTF-8 文本命令 | 严格解码，分别限制原始字节与业务字符规则，非法编码拒绝 |
| 进阶 | 增加并发接待 | 活跃连接数、每连接期限、全局内存、关闭所有权均明确 |
| 进阶 | 增加账号级限流 | 重连不重置账号预算，有有限的计数存储与过期策略 |
| 后续 | 接入成熟 TLS 库 | 主机名、证书、握手期限与非阻塞 TLS 状态均正确 |

不要只扩大 `MAX_BODY` 而忽略相关内存、发送队列和解析预算。改预算后，边界测试也要一起更新。

### 15.5 综合项目：给自己的聊天/RPC 服务加安全边界

产出一页设计和一张验收表：

1. 列出消息类型、帧头、正文上限、字段类型、编码与非法值。
2. 画出连接状态：未认证 → 已认证 → 关闭，并写清每种状态允许的操作。
3. 说明服务端如何取得真实用户身份，如何判断消息、文件、房间的归属与权限。
4. 写明证书信任、主机名验证、凭据传输、令牌过期与撤销规则。
5. 为连接、队列、请求数、速率、时间、解析深度和日志设上限。
6. 至少准备 12 项正常与异常测试，覆盖边界值、超长、截断、非法编码、未登录、越权、超时和重复请求。
7. 确认错误后没有句柄泄漏，后续合法用户仍能使用，日志没有泄密。

账户系统应采用成熟库或已有服务，不把教程里的公开计算器改成“硬编码一个密码、所有用户共用”的伪登录系统。

### 15.6 进一步认识模糊测试与内存检查

**模糊测试 fuzzing**是自动生成或修改大量输入，寻找崩溃、卡死和错误状态。随机字节只能覆盖一部分；还应从合法帧出发，改变长度、字段、边界和消息顺序。

**AddressSanitizer（ASan）**是发现部分越界和释放后使用问题的工具，不是安全证明。**UndefinedBehaviorSanitizer（UBSan）**帮助发现部分 C 未定义行为。

Linux 工具链支持时，可以另编译检查版并运行同一组测试：

```bash
gcc -std=c11 -Wall -Wextra -g -O1 -fsanitize=address,undefined -fno-omit-frame-pointer safe_linux.c -o safe_linux_asan
./safe_linux_asan
```

Windows 支持 ASan 的 Visual Studio 开发者环境可尝试：

```powershell
cl /nologo /std:c11 /W4 /Zi /fsanitize=address /TC safe_windows.c /Fe:safe_windows_asan.exe ws2_32.lib
.\safe_windows_asan.exe
```

不同编译器发行版支持不同；MinGW 不保证提供相同的 sanitizer 运行库。检查版和普通版不要同时占用 19105 端口。这些是后续增强检查命令，是否实际执行见第 17 节验证记录。

### 17.2 如果继续学习 UDP 安全

本章代码使用 TCP。UDP 还需重点学习：

- 源地址可能被伪造，不能仅凭数据报来源 IP 判断身份。
- 不能对未验证来源的小请求返回巨大的响应，否则可能被用于反射与放大流量。
- 一个数据报仍需做长度、格式、工作量和速率限制。
- 自行加“加密字段”容易遗漏密钥、认证、重放等问题；按需求研究成熟的 DTLS/QUIC 方案。

对应入口：[[UDP基础]]、[[UDP可靠性设计]]。不要把 TCP 的“读满 N 字节循环”原样当成 UDP 分帧代码。
