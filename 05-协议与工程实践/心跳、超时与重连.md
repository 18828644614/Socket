# 心跳、超时与重连

> 本章面向完全新手，沿用本知识库的 **C 语言 + TCP Socket** 路线。先弄懂“为什么会等不到”，再学习心跳、超时、重连，最后讨论“重连之后，请求能不能再发一次”。
>
> 阅读顺序是：**学习地图 → 前置知识 → 核心概念 → Windows/Linux 独立实验 → 故障观察 → 练习和检查**。不需要提前了解分布式系统，也不需要先背完 Socket 错误码。

## 0. 先规划：这一章究竟需要学哪些内容

### 0.1 学习目标

学完后，你应该能够：

1. 区分“TCP 连接存在”“对方进程能响应”“某项业务能成功”。
2. 解释心跳、超时、重试、重连、幂等性各自解决什么问题。
3. 为连接、心跳、业务请求、空闲连接分别设计等待时间。
4. 使用不会因校准系统时间而跳变的时钟计算等待期限。
5. 写出带编号的 `PING/PONG`，处理半条消息、错误响应和响应超时。
6. 关闭旧 Socket 后重新建立连接，并逐步延长重连间隔。
7. 解释为什么“请求超时”可能意味着“结果未知”，不能直接重新扣款。
8. 分别运行 Windows 和 Linux 示例，主动制造故障并根据日志判断原因。

## 1. 前置知识：把最容易混淆的词拆开

### 1.1 Socket、连接、请求分别是什么

把网络通信想成打电话：

- **IP 地址与端口**：帮助找到对方机器及其上的服务。
- **Socket**：程序使用操作系统网络功能的一项资源。Linux 常用整数文件描述符；Windows 使用 `SOCKET` 类型的句柄。
- **TCP 连接**：两端网络栈之间的一条有状态通信通道。网络栈可以理解为操作系统里负责网络传输的部分。
- **请求**：应用程序希望对方完成的一件事，例如查余额。
- **响应**：对方返回的结果，例如余额是多少。
- **会话**：应用维护的上下文，例如登录身份、订阅列表。它不等于 TCP 连接，断开后不一定自动恢复。

一条 TCP 连接可以承载很多次请求。关闭它，只会结束这条传输通道，不会自动撤销对方已经执行的业务。

### 1.2 TCP 是字节流，不是一封封信

发送 `PING 1\n` 时，接收方可能先收到 `PI`，下一次收到 `NG 1\n`；也可能一次收到 `PING 1\nPING 2\n`。

**字节流**表示有序的连续字节；**分帧**表示按应用约定从中切出完整消息。本章用换行字节 `\n` 作为边界。这里的 `\n` 在 C 字符串里代表一个换行字节，不是发送反斜杠和字母 n。

因此，“收到几个字节”和“收到一条完整、合法、编号匹配的心跳响应”是不同的事件。

### 1.3 `send()`、`recv()` 最少要会看哪些结果

| 调用结果 | 表示什么 | 本章如何处理 |
| --- | --- | --- |
| `send()` 返回正数 | 本次有这么多字节交给本机网络栈 | 如果没交完，就从剩余位置继续 |
| `recv()` 返回正数 | 本次收到了这么多字节 | 按协议拼出完整消息 |
| `recv()` 返回 `0` | 对方有序结束发送方向，即 EOF | 本章协议不使用半关闭，结束整个连接 |
| 非阻塞读写返回“暂时不可用” | 现在做不了，但未必故障 | 等待就绪后再试 |
| 复位、连接错误等 | 当前操作失败 | 保存错误、关闭旧连接、按策略恢复 |

**EOF** 是 End Of File 的缩写，在这里表示输入字节流结束。TCP 支持只关闭一个方向的“半关闭”；其他协议可能仍需发完响应，本章选择更简单的“EOF 就结束本次会话”。

Linux 通常用 `-1` 与 `errno` 表示错误；Windows 用 `SOCKET_ERROR` 与 `WSAGetLastError()`。不要混用两套错误获取方式。

### 1.4 阻塞、非阻塞与就绪

- **阻塞**：当前没数据时，调用可以留在那里等待。
- **非阻塞**：当前没数据时，调用尽快返回“暂时没有”。
- **就绪**：系统提示现在值得尝试读取或写入。`select()` 是等待这种提示的工具。
- **事件循环**：程序反复处理网络变化和定时任务的循环。

“可读”也可能意味着 EOF；“可写”也不等于远端业务成功。非阻塞 `connect()` 等到可写后，仍必须用 `SO_ERROR` 查询连接最终结果。

本章使用非阻塞读写，是为了让程序自己控制等待上限。不会无限循环调用 `recv()` 碰运气，而是让 `select()` 等待，避免 CPU 空转。

| 指针 | 指向某块内存的位置，例如发送剩余部分的起点 |

## 2. 为什么连接“看起来还在”，实际却无法工作

### 2.1 有声断线与无声失联

可以观察下面几个场景：

| 场景 | 可能观察到什么 | 能否保证立刻发现 |
| --- | --- | --- |
| 对方正常关闭连接 | 读到 EOF | 通常较快，但仍要等程序执行读取 |
| 对方进程退出或连接被复位 | EOF 或连接复位，取决于退出方式和连接状态 | 通常较快，不应固定假设一定是 RST |
| 网线断开、路径中断、数据被悄悄丢弃 | 长时间没有任何响应 | 不能保证立刻报错 |
| 服务端进程卡住，内核仍正常 | TCP 可能仍确认收包，业务不响应 | TCP 层未必能发现应用故障 |
| 服务端主循环正常，数据库卡住 | 心跳可能正常，业务请求仍超时 | 单靠心跳不能发现所有依赖问题 |

**无声失联**就是没有明确的关闭通知，只有“等不到”。连接显示 `ESTABLISHED` 只说明本机维护的 TCP 状态，不是对方当前健康的证明。

### 2.2 三种不同层次的确认

```text
send 返回成功
    → 本机接受了这些待发送字节
TCP ACK
    → 对方 TCP 栈确认了相应字节；不代表应用已经处理
应用返回 PONG 或业务响应
    → 处理该响应的应用路径实际运行过
```

**ACK** 是确认消息。不要把 TCP 的 ACK、应用层的 PONG、数据库事务提交当作同一个确认。

PONG 也有能力边界：如果由独立线程直接回复，它主要证明该线程能工作。想检查数据库，要另设业务健康检查，或把必要依赖纳入检测；这样又会增加检测成本，并可能在依赖抖动时触发大量断线。

### 2.3 失败检测其实是一种有依据的怀疑

设定“2 秒没有响应就视为本次连接不可用”，是程序的处理规则。对方可能已经停止，也可能只是网络拥堵、CPU 忙或电脑刚从睡眠恢复。

所以本章的超时日志表示“没有在约定时间内完成”，不表示“已证明远端宕机”。**宕机**就是机器或服务停止正常工作。

检测越急，越容易误判；检测越宽松，用户可能等得越久。选参数时要明确取舍。

## 3. 心跳：主动问一句“你还能回答吗”

### 3.1 心跳、探测与响应

**心跳**是应用定期发送的小消息，用来确认通信路径和对方的某段处理逻辑还能响应。

最简单的对话：

```text
客户端                         服务端
PING 1\n  -------------------> 解析完整 PING
          <------------------- PONG 1\n
确认这是对当前探测的回答
```

`PING` 和 `PONG` 只是本章自定义消息名称，与系统 `ping` 命令使用的 ICMP 不是一套协议。系统 ping 成功，也不能证明某个 TCP 端口或业务能工作。

### 3.2 为什么要带编号

假设第 1 次探测超时，第 2 次探测开始后才收到 `PONG 1`。如果只要看到 PONG 就算成功，旧响应可能替新探测“报平安”。

使用编号的规则是：

1. 发送 `PING 7`，记住当前等待的编号是 7。
2. 只接受完整、合法的 `PONG 7` 作为这一次探测的成功。
3. `PONG 6`、`PONG 8`、只有 `PO`，都不能证明第 7 次探测成功。

本章为简化实现，**同一连接最多只有一个正在等待的 PING**；编号错误直接视为协议错误并断开。生产系统也可以选择丢弃过期响应并继续等，但不能因此延长原来的截止时间。

### 3.3 心跳间隔与响应期限是两回事

| 参数 | 含义 | 本章实验值 |
| --- | --- | ---: |
| 心跳间隔 `H` | 本次成功收到 PONG 后，到下一次开始 PING 的等待时间 | 3 秒 |
| 心跳预算 `P` | 从开始发送 PING 到完整 PONG 到达，最多允许多久 | 2 秒 |
| 连接预算 `C` | 一次 TCP 建连最多允许多久 | 2 秒 |
| 服务端输入期限 | 接收一整条下一行消息的上限 | 15 秒 |

这些是方便观察的教学参数，不能直接当作所有网络的生产默认值。

时间线：

```text
t=0.0   收到 PONG 1
t=3.0   开始发送 PING 2；截止时间设为 t=5.0
t=3.1   收到 PONG 2 → 成功；下一次 PING 约在 t=6.1

如果这次没有响应：
t=5.0   截止 → 关闭旧连接 → 等待退避时间 → 新建连接
```

如果在最后一次 PONG 之后刚好失联，本例通常约需 `H + P = 5 秒` 才判定超时。线程调度、系统负载和系统睡眠会影响实际时刻，这不是硬实时保证。

### 3.4 连续失败阈值

**阈值**就是达到某个条件后采取动作的界限。例如“连续 3 次心跳失败才断开”。

- 好处：减少一次短暂拥堵导致的误判。
- 代价：真正失联后会等得更久。
- 要说明：失败后何时发下一次、是否允许多次探测重叠、成功后怎样清零。

不要只写“失败 3 次”，却不定义时间线。不同调度方式下，检测耗时并不总是简单的 `3 × 心跳间隔`。

本例取阈值 1：一轮 2 秒预算耗尽就结束连接，便于新手观察。后面的练习再改为连续失败策略。

### 3.5 业务数据能代替心跳吗

有时可以。例如协议约定“最近收到完整合法的业务消息，就说明对端刚刚活动过”，可以减少额外 PING。

但要分别保存这些时间：

- `last_valid_message_at`：最近收到完整合法消息的时间。
- `last_pong_at`：最近收到匹配 PONG 的时间。
- `request_deadline`：某个业务请求自己的截止时间。

收到聊天推送，可以证明对方发来过消息，却不能自动证明一笔正在等待的查询已经完成。

**不要收到任意一个字节就刷新健康时间。**否则坏客户端每隔一秒发一个字节、永远不完成消息，也可能一直占着连接。

### 3.6 TCP Keepalive 与应用心跳有什么区别

| 对比 | TCP Keepalive | 应用层 PING/PONG |
| --- | --- | --- |
| 谁负责 | 操作系统 TCP 栈 | 业务程序 |
| 主要判断 | 空闲 TCP 路径和对端 TCP 是否仍可达 | 应用中处理 PING 的路径是否响应 |
| 配置 | 启用开关、空闲时间、探测间隔、次数等 | 格式、编号、间隔、期限、失败策略 |
| 能否证明业务依赖正常 | 不能 | 取决于 PONG 实际经过了哪些逻辑 |

`SO_KEEPALIVE` 主要是启用开关，默认时间可能远长于业务可接受的等待；具体默认值和可调参数取决于系统。Linux 常见参数是 `TCP_KEEPIDLE`、`TCP_KEEPINTVL`、`TCP_KEEPCNT`；Windows 可使用相应 Winsock 配置接口，支持范围要看目标版本。

两者可以搭配使用。不要只打开 Keepalive 就以为实现了“3 秒业务健康检测”。

### 3.7 心跳的成本与局限

心跳会消耗网络、CPU 和电量。10 万条连接每 3 秒发送一次，单方向平均就约 3.3 万条消息/秒，还没计算 PONG、TCP/IP 头和日志。

NAT、防火墙、负载均衡器等中间设备可能清理长时间没有流量的连接。NAT 可以粗略理解为“替内部设备转换地址的网关”。心跳有时能维持这些映射，但必须结合实际设备的超时策略，不能保证所有设备都接受。

生产系统还应分散首次发送时刻，避免所有连接在整点一起发送。重连的随机等待与心跳的随机调度是两个不同位置，都可能需要处理。

## 4. 超时：给等待一条明确的边界

### 4.1 先分清哪些等待需要上限

| 超时类型 | 从哪里开始算 | 到哪里结束 | 超时后常见动作 |
| --- | --- | --- | --- |
| 名称解析超时 | 开始把域名解析成 IP | 得到地址或失败 | 换地址、报错；是否重试取决于解析器 |
| 建连超时 | 开始连接某个 IP/端口 | TCP 连接建立 | 关闭本次 Socket，按策略重试 |
| TLS/认证超时 | 开始加密握手或登录 | 安全会话/身份验证完成 | 清理连接，按错误类型决定是否重试 |
| 写入超时 | 开始写某条消息 | 消息全部交给本机网络栈 | 本例关闭连接，避免残帧混入下一轮 |
| 完整帧超时 | 开始等待某条消息 | 得到完整合法帧 | 清理解析状态，按协议关闭或报错 |
| 心跳超时 | 发起健康探测 | 匹配 PONG 到达 | 判定本连接不可用，恢复或停止 |
| 业务请求超时 | 请求开始 | 业务响应完整到达 | 标记失败或结果未知，按业务处理 |
| 空闲超时 | 最近一次约定的有效活动 | 再次有效活动 | 释放长期不用的连接 |
| 总预算 | 用户发起整个操作 | 所有尝试结束 | 停止新的尝试，向调用者返回结果 |

**TLS** 是为传输提供加密与身份验证的协议。连接成功后再做 TLS、再登录，这些步骤也会花时间，不能都漏在总预算外。

本例固定 `127.0.0.1`，不做域名解析、TLS 和登录，避免初学时同时引入太多内容。

### 4.2 相对时长与绝对截止时间

**相对时长**：“再等 2 秒”。**绝对截止时间**：“本轮必须在某个计时值之前完成”。

错误思路：每次 `recv()` 都重新等 2 秒。如果一条消息被拆成 100 次到达，总等待可能被不断延长。

正确思路：只在本轮开始时计算一次：

```text
deadline = 单调时钟当前值 + 本轮允许时长
每次等待前：remaining = deadline - 当前值
若当前值已经 >= deadline：立即超时
否则最多等待 remaining
```

例如预算 2 秒：第一次等 0.8 秒，处理花 0.1 秒，下一次只剩约 1.1 秒。**收到半条消息不重新发放 2 秒。**

在 C 中先判断 `now >= deadline`，再做无符号减法。顺序反过来可能让负差值变成一个巨大的正数。

### 4.3 为什么使用单调时钟

电脑显示的北京时间可以被用户或时间同步服务调快、调慢。用它计算超时，可能出现“还没等就超时”或“期限突然延后”。

**单调时钟**适合测量经过了多久，它不会因为修改日历时间而向后跳：

| 平台 | 本章使用 | 用途 |
| --- | --- | --- |
| Windows | `GetTickCount64()` | 读取系统运行相关的毫秒计时值 |
| Linux | `clock_gettime(CLOCK_MONOTONIC, ...)` | 读取单调时间，再换算成毫秒 |

日志显示年月日，可以使用日历时钟；判断本次是否超时，用单调时钟。不要把本机单调时钟的数值发给另一台机器，要求它拿自己的计时值直接比较。

系统休眠语义并非所有时钟都相同：Linux 的 `CLOCK_MONOTONIC` 不计算系统挂起时间。笔记本唤醒后可主动重探测或重建会话；需要把挂起时间也计入时，可以研究 Linux 的 `CLOCK_BOOTTIME` 等机制。

### 4.4 Socket 超时选项不等于业务总期限

`SO_RCVTIMEO` / `SO_SNDTIMEO` 常用于限制阻塞读写的等待，平台参数类型也不同。它们不会自动帮你：

- 将多次读写合并成一个业务总预算；
- 保证域名解析与 TLS 握手也受同一限制；
- 取消远端已经执行的请求；
- 在部分发送后恢复应用消息边界。

本例不依赖这些选项，而使用“非阻塞 Socket + `select()` + 一个共享截止时间”。详细平台差异参见 [[超时、断线与异常]]。

尤其不要把 Windows 阻塞 I/O 超时后套接字的后续状态，简单等同于“非阻塞本轮暂时没数据”。本例在整轮心跳期限耗尽后直接关闭旧连接。

### 4.5 超时后能不能继续用原连接

这取决于协议，不是一律重连：

- 普通的“本次没读到数据”，可能只是正常空闲。
- 一个带编号的查询响应晚到，可以由协议规定丢弃旧响应后继续使用连接。
- 如果一条消息只发了一半，随后直接发下一条，可能破坏消息边界。
- 如果解析器丢掉半条旧响应后继续读，新字节可能被误认成下一条消息。

本例没有设计复杂的晚到响应回收机制，因此任何心跳超时都关闭这条连接；输入暂存、未完成输出和待等待编号随连接一起废弃。

### 4.6 参数如何选择

先观察正常响应耗时，再留出余量。**RTT** 指一次往返耗时，本例记录从开始发送 PING 到完整 PONG 到达的时间，也包含应用处理和调度时间。

**p99 延迟**可以理解为：按耗时排序后，大约 99% 的样本不超过的值。不要用平均值直接当超时，否则稍慢但正常的请求就容易被误判。

选参数时一起考虑：用户能等多久、网络是否跨地域、服务器是否有长暂停、设备是否移动、失败后重连成本多大。本例服务端 15 秒输入期限应明显大于正常的 3 秒心跳间隔及网络/调度余量；真实协议还要统一双方的空闲策略。

## 5. 重连：恢复通道，也要管理节奏

### 5.1 重试与重连不是同一件事

- **重连**：旧 TCP 连接不可用，重新建立一条连接。
- **重试请求**：把某个业务操作再尝试一次，可以发生在旧连接，也可以发生在新连接。

可以只重连而不重发业务；也可以连接正常，但某次业务请求需要重试。不要用一个“retry”变量同时表达这两件事。

### 5.2 用状态机安排动作

**状态机**就是“把程序分成几个明确阶段，并规定遇到事件后怎样切换”。

```text
STOPPED --开始--> CONNECTING --TCP成功--> ONLINE
                     |                    |
                  建连失败             发起 PING
                     |                    v
                     |                WAIT_PONG
                     |              /           \
                     |       匹配PONG             超时/EOF/错误
                     |           |                    |
                     |           +--> ONLINE          |
                     +-------------------------------+
                                     |
                              关闭本次 Socket
                                     v
                                  BACKOFF
                                     |
                              到时间且预算未耗尽
                                     +--> CONNECTING

任意阶段遇到总预算耗尽、次数用尽或主动停止 → 清理 → STOPPED
```

注意 `ONLINE` 在示例日志里只表示 TCP 已建立；收到第一条合法 PONG 后，才有一次应用响应的证据。若协议包含登录，应在登录成功后再宣布业务就绪。

### 5.3 为什么不能失败后立即疯狂重连

假设服务器正在重启，10 万个客户端每毫秒都重连一次：服务器尚未恢复，就先被连接请求压住了。

这叫**重连风暴**。即使只有本机程序，无间隔循环也会浪费 CPU、刷屏、消耗临时端口，并让故障日志更难读。

### 5.4 指数退避：失败越多，间隔越长

**退避**就是失败后先等一等。**指数退避**表示等待上限按倍数增长，例如：

```text
第 1 次失败：上限 1 秒
第 2 次失败：上限 2 秒
第 3 次失败：上限 4 秒
第 4 次及以后：上限 8 秒
```

可以写成 `cap(k) = min(8 秒, 1 秒 × 2^k)`，其中 `k=0` 表示第一次失败。实际代码限制增长上限，避免移位或乘法溢出。

### 5.5 随机抖动：别让大家同时重试

如果所有客户端都准确等待 1、2、4、8 秒，仍可能一起冲向服务器。**随机抖动（jitter）**就是让等待时间略有不同。

本例采用“半上限到整个上限之间随机选”：

| 当前上限 | 实际随机等待范围 |
| --- | --- |
| 1000 ms | 500～1000 ms |
| 2000 ms | 1000～2000 ms |
| 4000 ms | 2000～4000 ms |
| 8000 ms | 4000～8000 ms |

这常被称为 equal jitter。另一种策略是在 0 到上限之间选取，常称 full jitter；不要把两种公式混在一起解释。

示例用 `rand()` 展示思路，种子取当前计时值。它不是安全随机数来源，也不保证大量同时启动的进程得到不同序列；大规模部署应使用更可靠的独立随机源。

### 5.6 什么时候把退避恢复到初始值

不能只因为 `connect()` 成功就清零：服务器可能接通后立刻断开，导致客户端永远每秒重连。

本例只有在“一段连接期间收到过合法 PONG，且这段连接持续至少 15 秒”后，才把退避上限恢复到 1 秒。生产实现可采用“连续多次探测成功 + 最近确有业务进展”的稳定条件。

### 5.7 每次重连都要清理什么

1. 保存失败原因，避免后续关闭操作覆盖原错误信息。
2. 关闭旧 Socket；每次新尝试都调用新的 `socket()`。
3. 废弃旧连接的半条输入、待发送字节和待响应编号。
4. 取消旧心跳、连接超时和重连定时器。
5. 给仍未完成的业务请求标记结果状态，按业务规则处理。
6. 新连接成功后，必要时重新认证、恢复订阅、查询未决结果。

复杂异步程序还应为连接增加**代次编号**：例如第 12 代连接的旧定时器触发时，发现当前已经是第 13 代，就丢弃这个回调，避免把新连接关闭。

始终让一个明确的管理者负责关闭，防止两个线程重复关闭同一资源。系统可能很快复用句柄数值，旧编号碰巧相同不代表还是原连接。

### 5.8 哪些错误应该停止自动恢复

| 情况 | 常见策略 |
| --- | --- |
| 短暂网络故障、服务器重启 | 有限次数退避恢复 |
| 地址/端口配置错误 | 提示配置问题，限制无意义尝试 |
| 密码错误、账号禁用 | 等待用户修正，避免连续登录 |
| 协议版本不兼容 | 停止或切换受支持版本 |
| 证书验证失败 | 报错并修复信任/配置，不通过关闭验证绕过 |
| 用户主动关闭 | 取消重连任务，保持停止 |
| 文件描述符/内存耗尽 | 处理本地资源问题，并限制新建连接 |

实验为了观察“错误编号也会触发清理”，将协议错误也送入有限重连；正式系统通常应对持续协议错误停止自动重试并报告。

### 5.9 停止条件也是重连设计的一部分

本例客户端默认总共运行 60 秒，最多尝试 12 次建连；任意一个条件达到就停止。**12 次是总尝试次数，包括第一次，不是额外重试 12 次。**

建连、心跳、间隔等待、退避都不能越过当前总预算。若最后只剩 300 ms，下一轮不能再拿到完整的 2 秒。

客户端退出码 `0` 只表示有限演示流程正常结束，不表示曾连接成功。监控程序若需要成功/失败退出码，应按业务目标单独定义。

## 6. 重连后的业务：重发之前先想清楚

### 6.1 超时后最危险的状态是“结果未知”

```text
客户端                    服务端
扣款请求 #A ------------> 扣款成功并保存结果
              网络中断   <---- 成功响应没有被客户端收到
客户端等待超时
```

此时客户端不知道是“请求没到”“执行中”还是“已成功但响应丢失”。重连只恢复通信，无法自动补全这段知识。

### 6.2 幂等性是什么

**幂等**的意思是：对同一逻辑操作重复提交，最终业务效果与提交一次相同。

| 操作 | 通常是否适合直接重试 | 注意点 |
| --- | --- | --- |
| 查询订单状态 | 通常适合 | 数据可能随时间变化，响应不一定完全相同 |
| 把灯设置为“关闭” | 常可设计为幂等 | 重复设置后仍是关闭 |
| 把余额加 10 元 | 不能直接假设幂等 | 执行两次会加 20 元 |
| 创建订单并带稳定业务操作编号 | 可通过服务端去重设计为幂等 | 编号、存储和原子性必须一起设计 |

不是“返回同一句话”就叫幂等，关键是业务效果不被重复施加。

### 6.3 请求编号和幂等键不一定是一回事

- **连接内请求编号**：帮助把响应对应到请求，换连接后可能从 1 重新开始。
- **幂等键**：代表同一个业务意图，在重试和重连后仍保持不变，例如一次订单创建操作的唯一编号。

本例 PING 编号会在新连接从 1 开始，只用于匹配本连接的 PONG，**不能拿来当持久化扣款去重键**。

### 6.4 一个可理解的服务端去重流程

下面是设计伪代码，不是可以直接运行的数据库程序：

```text
收到：用户身份 + 操作类型 + 幂等键 + 请求正文

在同一个数据库事务中：
    尝试创建该用户、该操作、该幂等键的唯一记录
    若已存在：
        检查请求正文摘要是否一致
        不一致 → 拒绝同键不同内容
        已完成 → 返回先前保存的结果
        正在处理 → 返回处理中或按规则等待
    若是首次处理：
        执行业务变更
        保存业务结果与完成状态
提交事务
发送响应
```

**事务**可以先理解为“一组数据库操作按整体提交或整体回退”。**唯一约束**用来确保两个并发请求不能同时取得“首次执行”的资格。**摘要**是正文的一种指纹，用来检查同一个键是否被错误地用于不同内容。

只用内存里的字典去重，进程重启后可能丢失；先扣款、后单独记去重记录，两个动作之间崩溃也可能重复扣款。需要让业务变更与去重结果具有一致的提交边界。

如果业务还调用外部支付服务，本地数据库事务不能直接包住对方的操作；需要对方也支持幂等键或采用可靠的跨系统协调方案。不要把上面几行伪代码当作“任意业务都能保证恰好一次”。

### 6.5 去重记录保留多久

**TTL** 是生存时间，表示一条记录保留多久。去重记录至少覆盖允许的重试窗口，还要考虑延迟消息、离线重放和人工补偿。记录过期后再重发，可能被当作全新请求。

“至少一次”表示可能重复但尽量不丢；“至多一次”表示尽量不重复但可能丢；“恰好一次业务效果”需要明确故障、存储、并发和过期条件，不能只靠 TCP 或重发实现。

### 6.6 恢复连接后，哪些状态需要恢复

可按顺序安排：

```text
TCP 建连 → TLS（如果需要）→ 身份验证 → 恢复会话/订阅
        → 查询未决请求结果 → 按规则重试 → 恢复正常业务
```

**未决请求**就是还没有明确终态的请求。可以按“尚未发出、部分发出、已发出等待结果、已确认完成”分类。部分发出或已经发出的非幂等操作，通常需要查询结果或人工确认，而不能统一塞回发送队列。

还有一个常见问题：每层都重试。界面重试 3 次、客户端库每次又重试 3 次、服务端再重试 3 次，可能变成最多 27 次下游尝试。应统一总预算，并明确由哪一层负责重试。

## 7. 贯穿实验：先把小协议约定清楚

### 7.1 文件与角色

下面提供两个**彼此独立、完整可编译**的 C 文件：

- Windows：`hb_windows.c`，使用 Winsock。
- Linux/WSL：`hb_linux.c`，使用 POSIX Socket。

每个文件既能作为服务端，也能作为客户端，通过启动参数选择。只复制自己平台的一个代码块即可，不需要拼接另一个平台的代码，也不依赖额外头文件。

| 项目 | 本章约定 |
| --- | --- |
| 地址 | `127.0.0.1`，只允许本机实验 |
| 端口 | TCP `19200` |
| 客户端职责 | 发 PING、等 PONG、记录 RTT、失败后有限重连 |
| 服务端职责 | 解析 PING、按指定模式回答、清理断开的连接 |
| 并发能力 | 服务端一次处理一个已接受连接；完成后再接下一个 |
| 默认运行长度 | 客户端 60 秒或 12 次建连尝试，先到者为准 |

监听积压队列不是并发处理能力：第二个客户端可能已经完成 TCP 握手，但仍在等服务端调用 `accept()` 并处理。因此第一轮只启动一个客户端。

### 7.2 消息格式

```text
客户端发送：PING <编号>\n
服务端响应：PONG <相同编号>\n
```

详细规则：

1. 使用 ASCII 可打印字符和单字节 LF 换行；不接受 CRLF，末尾不要额外空格。
2. 命令大小写固定，命令与编号之间恰好一个空格。
3. 编号由 1～9 个十进制数字组成，范围 `0..999999999`；解析允许前导零。本例客户端从 1 递增。
4. 每行内容最多 31 字节，不含 LF；接收数组 32 字节，最后一个位置留给 C 字符串结束符 `\0`。
5. 空行、错误命令、非数字、超长行、内嵌 NUL、其他控制字符均拒绝并关闭连接。
6. 客户端只接受当前编号的 PONG。编号错误不算健康证据。
7. 中途 EOF 或超过本轮截止时间，废弃残帧并关闭连接。

C 的字符串结束符 `\0` 只是内存里的终止标记，本协议不把它发到网络上。

### 7.3 故障模式

| 服务端参数 | 行为 | 客户端预期 |
| --- | --- | --- |
| `normal` | 立即回复正确 PONG | 成功，打印 RTT |
| `silent` | 收到 PING，但不回复 | 约 2 秒后本轮心跳超时 |
| `slow` | 等待 3.5 秒才回复 | 超过 2 秒预算，客户端先结束旧连接 |
| `split` | 先发 `PO`，100 ms 后再发剩余部分 | 收到完整行后才成功 |
| `wrong` | 回复下一个编号 | 协议错误、清理、有限重连 |
| `close` | 收到 PING 后直接结束连接 | EOF 或传输错误，清理并恢复 |

`silent` 模拟“TCP 仍在，应用不响应”，不等同于真实链路上所有数据包都被丢弃。它的优点是可控，不需要改防火墙就能验证超时策略。

`split` 人为拆成两次发送，但 TCP 仍可能合并交付；接收代码无论合并还是拆分都要正确。它不能用来证明操作系统每次恰好读到两个分段。

### 7.4 阅读代码的顺序

先看 `main()` 如何选角色，再按下面的路线读：

1. 平台函数：初始化、计时、非阻塞、错误码、关闭。
2. `wait_ready()`：只等剩余时间；Linux 被信号打断后重新计算。
3. `send_until()`：维护已发送位置，处理部分发送。
4. `line_until()`：逐字节拼出完整一行，不因收到半条消息刷新期限。
5. `dial()`：非阻塞建连，等待后查询 `SO_ERROR`。
6. `run_client()`：一次建连、反复探测、释放、退避、有限恢复。
7. `run_server()`：实验用单连接服务端与故障模式。

为了教学，`line_until()` 每次只读一个字节，避免一次读到下一行后还要额外管理剩余缓冲。这样容易理解但效率较低；正式程序通常批量接收并增量解析。

本例客户端在两次 PING 之间简单休眠，不接收其他业务消息；在这段间隔内到达的 EOF 也会延后到下次读写时发现。实际聊天/RPC 客户端应让事件循环同时处理网络、业务和定时器，不能照搬休眠结构。

### 8.1 保存为 `hb_windows.c`

```c
/* hb_windows.c -- Windows Winsock; see the chapter for commands. */
#define _WIN32_WINNT 0x0600
#include <winsock2.h>
#include <ws2tcpip.h>
#include <windows.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
typedef SOCKET Sock;
#define BAD INVALID_SOCKET
static int os_error(void) { return WSAGetLastError(); }
static int again(int e) { return e == WSAEWOULDBLOCK; }
static int interrupted(int e) { return e == WSAEINTR; }
static void drop(Sock s) { closesocket(s); }
static uint64_t now_ms(void) { return (uint64_t)GetTickCount64(); }
static void nap(unsigned ms) { Sleep(ms); }
static int nonblock(Sock s) {
    u_long on = 1;
    return ioctlsocket(s, FIONBIO, &on) == 0;
}
static int startup(void) {
    WSADATA w;
    int e = WSAStartup(MAKEWORD(2, 2), &w);
    if (e) fprintf(stderr, "WSAStartup: %d\n", e);
    return e == 0;
}
static void cleanup(void) { WSACleanup(); }
static int wait_ready(Sock s, int writing, uint64_t deadline) {
    for (;;) {
        uint64_t now = now_ms();
        if (now >= deadline) return 0;
        uint64_t left = deadline - now;
        struct timeval tv;
        tv.tv_sec = (long)(left / 1000);
        tv.tv_usec = (long)((left % 1000) * 1000);
        fd_set wanted, errors;
        FD_ZERO(&wanted); FD_SET(s, &wanted);
        FD_ZERO(&errors); FD_SET(s, &errors);
        int n = select(0, writing ? NULL : &wanted,
                       writing ? &wanted : NULL, &errors, &tv);
        if (n > 0) return 1; /* connect still needs SO_ERROR */
        if (n == 0) return 0;
        int e = os_error();
        if (!interrupted(e)) {
            fprintf(stderr, "select: %d\n", e);
            return -1;
        }
    }
}
static int connect_pending(int e) {
    return e == WSAEWOULDBLOCK || e == WSAEINPROGRESS;
}
static int connect_result(Sock s) {
    int e = 0, size = sizeof e;
    if (getsockopt(s, SOL_SOCKET, SO_ERROR, (char *)&e, &size) != 0) {
        fprintf(stderr, "SO_ERROR query: %d\n", os_error());
        return 0;
    }
    if (e) fprintf(stderr, "connect result: %d\n", e);
    return e == 0;
}
static int tx(Sock s, const char *p, int n) { return send(s, p, n, 0); }
static int rx(Sock s, char *p) { return recv(s, p, 1, 0); }
static int bind_listener(Sock s, struct sockaddr_in *a) {
    /* Exclusive ownership; do not use SO_REUSEADDR as a shortcut here. */
    BOOL on = TRUE;
    if (setsockopt(s, SOL_SOCKET, SO_EXCLUSIVEADDRUSE,
                   (const char *)&on, sizeof on) != 0) return 0;
    return bind(s, (struct sockaddr *)a, sizeof *a) == 0;
}

enum { PORT = 19200, LINE_CAP = 32, CONNECT_MS = 2000,
       HEARTBEAT_MS = 3000, PONG_MS = 2000, SERVER_IDLE_MS = 15000 };

static uint64_t earlier(uint64_t a, uint64_t b) { return a < b ? a : b; }
static void pause_until(uint64_t deadline) {
    uint64_t now = now_ms();
    if (deadline > now) nap((unsigned)(deadline - now));
}
static struct sockaddr_in address(void) {
    struct sockaddr_in a;
    memset(&a, 0, sizeof a);
    a.sin_family = AF_INET;
    a.sin_port = htons(PORT);
    a.sin_addr.s_addr = htonl(INADDR_LOOPBACK); /* 127.0.0.1 */
    return a;
}

/* 1 = complete, 0 = deadline, -1 = error/EOF. All waits share deadline. */
static int send_until(Sock s, const char *data, int size, uint64_t deadline) {
    int offset = 0;
    while (offset < size) {
        int ready = wait_ready(s, 1, deadline);
        if (ready <= 0) return ready;
        if (now_ms() >= deadline) return 0;
        int n = tx(s, data + offset, size - offset);
        if (n > 0) { offset += n; continue; }
        if (n == 0) return -1;
        int e = os_error();
        if (again(e) || interrupted(e)) continue;
        fprintf(stderr, "send: %d\n", e);
        return -1;
    }
    return 1;
}

/* One byte per recv for teaching: no loss of the next line's bytes. */
static int line_until(Sock s, char line[LINE_CAP], uint64_t deadline) {
    int used = 0;
    for (;;) {
        int ready = wait_ready(s, 0, deadline);
        if (ready <= 0) return ready;
        if (now_ms() >= deadline) return 0;
        char ch;
        int n = rx(s, &ch);
        if (n == 0) {
            puts(used ? "EOF in partial line" : "peer closed"); return -1;
        }
        if (n < 0) {
            int e = os_error();
            if (again(e) || interrupted(e)) continue;
            fprintf(stderr, "recv: %d\n", e); return -1;
        }
        if (ch == '\n') { line[used] = '\0'; return 1; }
        if (ch < 32 || ch > 126 || used == LINE_CAP - 1) {
            puts("invalid or too long line"); return -1;
        }
        line[used++] = ch;
    }
}

/* Exact grammar: prefix then 1..9 digits, no trailing space. */
static int parse_id(const char *line, const char *prefix, unsigned *id) {
    size_t len = strlen(prefix);
    if (strncmp(line, prefix, len) != 0) return 0;
    const char *p = line + len;
    unsigned value = 0, digits = 0;
    while (*p) {
        if (*p < '0' || *p > '9' || ++digits > 9) return 0;
        value = value * 10 + (unsigned)(*p++ - '0');
    }
    if (!digits) return 0;
    *id = value;
    return 1;
}

static Sock dial(uint64_t deadline) {
    Sock s = socket(AF_INET, SOCK_STREAM, 0);
    if (s == BAD) { fprintf(stderr, "socket: %d\n", os_error()); return BAD; }
    if (!nonblock(s)) {
        fprintf(stderr, "nonblock: %d\n", os_error()); drop(s); return BAD;
    }
    struct sockaddr_in a = address();
    if (connect(s, (struct sockaddr *)&a, sizeof a) != 0) {
        int e = os_error();
        if (!connect_pending(e)) {
            fprintf(stderr, "connect: %d\n", e); drop(s); return BAD;
        }
        int ready = wait_ready(s, 1, deadline);
        if (ready <= 0) {
            puts(ready == 0 ? "connect deadline" : "connect wait failed");
            drop(s); return BAD;
        }
        if (!connect_result(s)) { drop(s); return BAD; }
    }
    if (now_ms() >= deadline) { drop(s); return BAD; }
    return s;
}

static int run_server(const char *mode) {
    Sock listener = socket(AF_INET, SOCK_STREAM, 0);
    if (listener == BAD) { fprintf(stderr, "socket: %d\n", os_error()); return 1; }
    struct sockaddr_in a = address();
    if (!bind_listener(listener, &a) || listen(listener, 8) != 0) {
        fprintf(stderr, "bind/listen: %d\n", os_error());
        drop(listener); return 1;
    }
    printf("server 127.0.0.1:%d mode=%s\n", PORT, mode);
    for (;;) {
        Sock s = accept(listener, NULL, NULL);
        if (s == BAD) {
            int e = os_error();
            if (interrupted(e)) continue;
            fprintf(stderr, "accept: %d\n", e); break;
        }
        puts("accepted");
        if (!nonblock(s)) {
            fprintf(stderr, "nonblock: %d\n", os_error()); drop(s); continue;
        }
        for (;;) {
            char line[LINE_CAP], reply[LINE_CAP];
            int r = line_until(s, line, now_ms() + SERVER_IDLE_MS);
            if (r <= 0) {
                if (r == 0) puts("server input deadline");
                break;
            }
            unsigned id;
            if (!parse_id(line, "PING ", &id)) { puts("bad PING"); break; }
            printf("RX %s\n", line);
            if (strcmp(mode, "silent") == 0) continue;
            if (strcmp(mode, "close") == 0) break;
            if (strcmp(mode, "slow") == 0) nap(3500);
            unsigned reply_id = strcmp(mode, "wrong") == 0 ? (id + 1) % 1000000000U : id;
            int size = snprintf(reply, sizeof reply, "PONG %u\n", reply_id);
            uint64_t deadline = now_ms() + PONG_MS;
            if (strcmp(mode, "split") == 0) {
                if (send_until(s, reply, 2, deadline) != 1) break;
                nap(100);
                if (send_until(s, reply + 2, size - 2, deadline) != 1) break;
            } else if (send_until(s, reply, size, deadline) != 1) break;
            printf("TX PONG %u\n", reply_id);
        }
        drop(s);
        puts("connection released");
    }
    drop(listener);
    return 1;
}

static int run_client(unsigned seconds) {
    uint64_t finish = now_ms() + (uint64_t)seconds * 1000;
    unsigned cap = 1000, attempts = 0;
    srand((unsigned)now_ms()); /* demonstration jitter, not security randomness */
    while (now_ms() < finish && attempts < 12) {
        printf("CONNECTING attempt=%u\n", ++attempts);
        Sock s = dial(earlier(now_ms() + CONNECT_MS, finish));
        if (s != BAD) {
            puts("ONLINE (TCP connected; waiting for first PONG)");
            uint64_t connected = now_ms();
            unsigned seq = 0;
            int healthy = 0;
            while (now_ms() < finish) {
                char request[LINE_CAP], reply[LINE_CAP];
                unsigned answer;
                ++seq; /* new connection starts from 1 */
                int size = snprintf(request, sizeof request, "PING %u\n", seq);
                uint64_t start = now_ms();
                uint64_t deadline = earlier(start + PONG_MS, finish);
                printf("WAIT_PONG seq=%u\n", seq);
                int r = send_until(s, request, size, deadline);
                if (r == 1) r = line_until(s, reply, deadline);
                if (r != 1) {
                    puts(now_ms() >= finish ? "total budget ended" :
                         r == 0 ? "heartbeat deadline" : "connection failed");
                    break;
                }
                if (!parse_id(reply, "PONG ", &answer) || answer != seq) {
                    puts("protocol error: unexpected PONG"); break;
                }
                healthy = 1;
                printf("PONG OK seq=%u RTT=%llu ms\n", seq,
                       (unsigned long long)(now_ms() - start));
                pause_until(earlier(now_ms() + HEARTBEAT_MS, finish));
            }
            /* Reset only after a session with valid PONGs lasts >= 15 s. */
            if (healthy && now_ms() - connected >= 15000) cap = 1000;
            drop(s);
            puts("old socket released");
        }
        if (now_ms() >= finish || attempts >= 12) break;
        unsigned delay = cap / 2 + (unsigned)rand() % (cap / 2 + 1);
        printf("BACKOFF delay=%u ms cap=%u\n", delay, cap);
        pause_until(earlier(now_ms() + delay, finish));
        if (cap < 8000) cap *= 2;
    }
    puts(now_ms() >= finish ? "STOPPED: total time limit" : "STOPPED: attempt limit");
    return 0;
}

int main(int argc, char **argv) {
    setvbuf(stdout, NULL, _IONBF, 0); /* show each log immediately */
    int server = argc >= 2 && strcmp(argv[1], "server") == 0;
    int client = argc >= 2 && strcmp(argv[1], "client") == 0;
    const char *mode = argc >= 3 ? argv[2] : "normal";
    unsigned seconds = 60;
    if ((!server && !client) || argc > 3 ||
        (server && strcmp(mode, "normal") && strcmp(mode, "silent") &&
         strcmp(mode, "slow") && strcmp(mode, "split") &&
         strcmp(mode, "wrong") && strcmp(mode, "close"))) {
        puts("usage: hb server [normal|silent|slow|split|wrong|close]");
        puts("       hb client [seconds: 1..600]"); return 1;
    }
    if (client && argc == 3) {
        unsigned value;
        if (!parse_id(argv[2], "", &value) || value < 1 || value > 600) {
            puts("client seconds must be 1..600"); return 1;
        }
        seconds = value;
    }
    if (!startup()) return 1;
    int result = server ? run_server(mode) : run_client(seconds);
    cleanup();
    return result;
}
```

### 8.4 Windows 接口要点

- `WSAStartup()` 初始化 Winsock，成功后在正常结束路径调用 `WSACleanup()`。
- 用 `SOCKET` 保存句柄，用 `INVALID_SOCKET` 判断创建失败。
- `ioctlsocket(..., FIONBIO, ...)` 设置非阻塞。
- `select()` 的第一个参数在 Winsock 中忽略，传 `0`；建连等待同时观察写集合与异常集合。
- 用 `WSAGetLastError()` 立即取得失败原因，用 `closesocket()` 关闭。
- 监听端使用 `SO_EXCLUSIVEADDRUSE` 明确独占端口。不要照搬 Linux 的 `SO_REUSEADDR` 以为两边含义完全一样。

```c
#define _POSIX_C_SOURCE 200809L
#include <sys/types.h>
#include <sys/socket.h>
#include <sys/select.h>
#include <netinet/in.h>
#include <arpa/inet.h>
#include <unistd.h>
#include <fcntl.h>
#include <errno.h>

#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
typedef int Sock;

static int os_error(void) { return errno; }

static int interrupted(int e) { return e == EINTR; }
static void drop(Sock s) { close(s); }
static uint64_t now_ms(void) {
    struct timespec ts;
    if (clock_gettime(CLOCK_MONOTONIC, &ts) != 0) {
        perror("clock_gettime"); exit(1);
    }
    return (uint64_t)ts.tv_sec * 1000 + (uint64_t)ts.tv_nsec / 1000000;
}
static void nap(unsigned ms) {
    struct timespec ts = { (time_t)(ms / 1000),
                          (long)(ms % 1000) * 1000000L };
    while (nanosleep(&ts, &ts) != 0 && errno == EINTR) {}
}
static int nonblock(Sock s) {
    int flags = fcntl(s, F_GETFL, 0);
    return flags >= 0 && fcntl(s, F_SETFL, flags | O_NONBLOCK) == 0;
}
static int startup(void) { return 1; }
static void cleanup(void) {}
static int wait_ready(Sock s, int writing, uint64_t deadline) {
    if (s < 0 || s >= FD_SETSIZE) {
        fputs("fd outside select range\n", stderr); return -1;
    }
    for (;;) {
        uint64_t now = now_ms();
        if (now >= deadline) return 0;
        uint64_t left = deadline - now;
        struct timeval tv;
        tv.tv_sec = (time_t)(left / 1000);
        tv.tv_usec = (suseconds_t)((left % 1000) * 1000);
        fd_set wanted;
        FD_ZERO(&wanted); FD_SET(s, &wanted);
        int n = select(s + 1, writing ? NULL : &wanted,
                       writing ? &wanted : NULL, NULL, &tv);
        if (n > 0) return 1;
        if (n == 0) return 0;
        int e = os_error();
        if (!interrupted(e)) {
            fprintf(stderr, "select: %d\n", e); return -1;
        }
    }
}
static int connect_pending(int e) { return e == EINPROGRESS; }

        perror("SO_ERROR query"); return 0;
    }
    if (e) fprintf(stderr, "connect result: %d\n", e);
    return e == 0;
}

}

        return 0;
    return bind(s, (struct sockaddr *)a, sizeof *a) == 0;
}

       HEARTBEAT_MS = 3000, PONG_MS = 2000, SERVER_IDLE_MS = 15000 };

}

        if (ready <= 0) return ready;
        if (now_ms() >= deadline) return 0;
        int n = tx(s, data + offset, size - offset);
        if (n > 0) { offset += n; continue; }
        if (n == 0) return -1;
        int e = os_error();
        if (again(e) || interrupted(e)) continue;
        fprintf(stderr, "send: %d\n", e);
        return -1;
    }
    return 1;
}

        if (ch < 32 || ch > 126 || used == LINE_CAP - 1) {

        }

    }
}

static Sock dial(uint64_t deadline) {
    Sock s = socket(AF_INET, SOCK_STREAM, 0);
    if (s == BAD) { fprintf(stderr, "socket: %d\n", os_error()); return BAD; }
    if (!nonblock(s)) {
        fprintf(stderr, "nonblock: %d\n", os_error()); drop(s); return BAD;
    }
    struct sockaddr_in a = address();
    if (connect(s, (struct sockaddr *)&a, sizeof a) != 0) {
        int e = os_error();
        if (!connect_pending(e)) {
            fprintf(stderr, "connect: %d\n", e); drop(s); return BAD;
        }
        int ready = wait_ready(s, 1, deadline);
        if (ready <= 0) {
            puts(ready == 0 ? "connect deadline" : "connect wait failed");
            drop(s); return BAD;
        }
        if (!connect_result(s)) { drop(s); return BAD; }
    }
    if (now_ms() >= deadline) { drop(s); return BAD; }
    return s;
}

static int run_server(const char *mode) {
    Sock listener = socket(AF_INET, SOCK_STREAM, 0);
    if (listener == BAD) { fprintf(stderr, "socket: %d\n", os_error()); return 1; }
    struct sockaddr_in a = address();
    if (!bind_listener(listener, &a) || listen(listener, 8) != 0) {
        fprintf(stderr, "bind/listen: %d\n", os_error());
        drop(listener); return 1;
    }
    printf("server 127.0.0.1:%d mode=%s\n", PORT, mode);
    for (;;) {
        Sock s = accept(listener, NULL, NULL);
        if (s == BAD) {
            int e = os_error();
            if (interrupted(e)) continue;
            fprintf(stderr, "accept: %d\n", e); break;
        }
        puts("accepted");
        if (!nonblock(s)) {
            fprintf(stderr, "nonblock: %d\n", os_error()); drop(s); continue;
        }
        for (;;) {
            char line[LINE_CAP], reply[LINE_CAP];
            int r = line_until(s, line, now_ms() + SERVER_IDLE_MS);
            if (r <= 0) {
                if (r == 0) puts("server input deadline");
                break;
            }
            unsigned id;
            if (!parse_id(line, "PING ", &id)) { puts("bad PING"); break; }
            printf("RX %s\n", line);
            if (strcmp(mode, "silent") == 0) continue;
            if (strcmp(mode, "close") == 0) break;
            if (strcmp(mode, "slow") == 0) nap(3500);
            unsigned reply_id = strcmp(mode, "wrong") == 0 ? (id + 1) % 1000000000U : id;
            int size = snprintf(reply, sizeof reply, "PONG %u\n", reply_id);
            uint64_t deadline = now_ms() + PONG_MS;
            if (strcmp(mode, "split") == 0) {
                if (send_until(s, reply, 2, deadline) != 1) break;
                nap(100);
                if (send_until(s, reply + 2, size - 2, deadline) != 1) break;
            } else if (send_until(s, reply, size, deadline) != 1) break;
            printf("TX PONG %u\n", reply_id);
        }
        drop(s);
        puts("connection released");
    }
    drop(listener);
    return 1;
}

static int run_client(unsigned seconds) {
    uint64_t finish = now_ms() + (uint64_t)seconds * 1000;
    unsigned cap = 1000, attempts = 0;
    srand((unsigned)now_ms()); /* demonstration jitter, not security randomness */
    while (now_ms() < finish && attempts < 12) {
        printf("CONNECTING attempt=%u\n", ++attempts);
        Sock s = dial(earlier(now_ms() + CONNECT_MS, finish));
        if (s != BAD) {
            puts("ONLINE (TCP connected; waiting for first PONG)");
            uint64_t connected = now_ms();
            unsigned seq = 0;
            int healthy = 0;
            while (now_ms() < finish) {
                char request[LINE_CAP], reply[LINE_CAP];
                unsigned answer;
                ++seq; /* new connection starts from 1 */
                int size = snprintf(request, sizeof request, "PING %u\n", seq);
                uint64_t start = now_ms();
                uint64_t deadline = earlier(start + PONG_MS, finish);
                printf("WAIT_PONG seq=%u\n", seq);
                int r = send_until(s, request, size, deadline);
                if (r == 1) r = line_until(s, reply, deadline);
                if (r != 1) {
                    puts(now_ms() >= finish ? "total budget ended" :
                         r == 0 ? "heartbeat deadline" : "connection failed");
                    break;
                }
                if (!parse_id(reply, "PONG ", &answer) || answer != seq) {
                    puts("protocol error: unexpected PONG"); break;
                }
                healthy = 1;
                printf("PONG OK seq=%u RTT=%llu ms\n", seq,
                       (unsigned long long)(now_ms() - start));
                pause_until(earlier(now_ms() + HEARTBEAT_MS, finish));
            }
            /* Reset only after a session with valid PONGs lasts >= 15 s. */
            if (healthy && now_ms() - connected >= 15000) cap = 1000;
            drop(s);
            puts("old socket released");
        }
        if (now_ms() >= finish || attempts >= 12) break;
        unsigned delay = cap / 2 + (unsigned)rand() % (cap / 2 + 1);
        printf("BACKOFF delay=%u ms cap=%u\n", delay, cap);
        pause_until(earlier(now_ms() + delay, finish));
        if (cap < 8000) cap *= 2;
    }
    puts(now_ms() >= finish ? "STOPPED: total time limit" : "STOPPED: attempt limit");
    return 0;
}

int main(int argc, char **argv) {
    setvbuf(stdout, NULL, _IONBF, 0); /* show each log immediately */
    int server = argc >= 2 && strcmp(argv[1], "server") == 0;
    int client = argc >= 2 && strcmp(argv[1], "client") == 0;
    const char *mode = argc >= 3 ? argv[2] : "normal";
    unsigned seconds = 60;
    if ((!server && !client) || argc > 3 ||
        (server && strcmp(mode, "normal") && strcmp(mode, "silent") &&
         strcmp(mode, "slow") && strcmp(mode, "split") &&
         strcmp(mode, "wrong") && strcmp(mode, "close"))) {
        puts("usage: hb server [normal|silent|slow|split|wrong|close]");
        puts("       hb client [seconds: 1..600]"); return 1;
    }
    if (client && argc == 3) {
        unsigned value;
        if (!parse_id(argv[2], "", &value) || value < 1 || value > 600) {
            puts("client seconds must be 1..600"); return 1;
        }
        seconds = value;
    }
    if (!startup()) return 1;
    int result = server ? run_server(mode) : run_client(seconds);
    cleanup();
    return result;
}
```

### 9.4 Linux 接口要点

- 句柄使用 `int`，创建失败是 `-1`，用 `close()` 关闭。
- `fcntl()` 保留原标志并加上 `O_NONBLOCK`。
- `select()` 第一个参数是最大文件描述符加 1；本例只有一个受观察连接，所以是 `s + 1`。
- `select()` 可能修改等待时间和集合，因此每轮重新构建，并根据原截止时间计算剩余时长。
- `EINTR` 表示被信号打断；重试前仍要核算剩余预算。
- `send(..., MSG_NOSIGNAL)` 防止连接断开时 `SIGPIPE` 默认行为直接结束进程；错误仍通过返回值和 `errno` 处理。这个标志是本例 Linux 写法，不保证所有 Unix 平台相同。
- `SO_REUSEADDR` 用于常见的监听重启场景，不代表可以安全抢占任意正在使用的监听端口。

## 10. 按步骤运行并解释日志

### 10.1 实验一：先获得一条正常时间线

先启动 `server normal`，再启动 `client 10`，可能看到：

```text
CONNECTING attempt=1
ONLINE (TCP connected; waiting for first PONG)
WAIT_PONG seq=1
PONG OK seq=1 RTT=1 ms
WAIT_PONG seq=2
PONG OK seq=2 RTT=0 ms
...
old socket released
STOPPED: total time limit
```

本机 RTT 很小，显示 `0 ms` 是计时分辨率与整数毫秒取整的结果，不表示没有传输和处理成本。

解释顺序：尝试建连 → TCP 成功 → 发起编号 1 的探测 → 完整响应匹配 → 等约 3 秒 → 下一次探测。

在总预算最后一小段时间开始一轮探测，可能看到 `total budget ended`，这是整段演示到期，不应误读为一次完整 2 秒预算内的服务故障。

### 10.2 实验二：服务端在线，但不回复

先结束上一轮客户端，再在服务端终端按 `Ctrl+C`，换成下面模式。不要同时启动多个占用同一端口的服务端。

Windows：

```powershell
# 终端 A
.\hb_windows.exe server silent
# 终端 B
.\hb_windows.exe client 15
```

Linux：

```bash
# 终端 A
./hb_linux server silent
# 终端 B
./hb_linux client 15
```

服务端会打印 `RX PING 1`，客户端却在约 2 秒后打印：

```text
heartbeat deadline
old socket released
BACKOFF delay=... ms cap=1000
CONNECTING attempt=2
```

观察重点：TCP 接通与心跳成功被明确区分；关闭旧 Socket 发生在退避之前；每个新连接的 PING 编号重新从 1 开始。

### 10.3 实验三：延迟响应、半条响应与错误编号

依次替换服务端模式，每轮重启客户端：

| 模式 | 应观察到的现象 | 需要解释的问题 |
| --- | --- | --- |
| `slow` | 客户端约 2 秒超时；服务端稍后可能打印发送或错误 | 为什么晚到响应不能挽救已废弃的连接？ |
| `split` | 正常收到 `PONG OK`，RTT 通常包含约 100 ms 延迟 | 为什么收到 `PO` 时不能宣布成功？ |
| `wrong` | `protocol error: unexpected PONG` | 为什么收到 PONG 仍可能是错误？ |
| `close` | `peer closed` 或传输错误 | 为什么正常关闭和无声超时的发现路径不同？ |

`slow` 中，服务端的 `send()` 可能返回成功，即使客户端已经超时关闭；发送成功只说明本机接受字节，不是客户端仍愿意接收的证明。

### 10.4 实验四：服务端重启与恢复

1. 启动 `server normal`。
2. 启动 `client 60`，等至少一条 `PONG OK`。
3. 在服务端终端按 `Ctrl+C`，客户端继续运行。
4. 等客户端打印 EOF/连接错误与 `BACKOFF`。
5. 在同一终端重新启动 `server normal`。
6. 观察客户端的新一次 `CONNECTING`、`ONLINE`、`PONG OK`。

重启后不一定立刻连接，因为客户端可能正在退避。恢复时间包括“发现旧连接失败 + 已安排的退避 + 新建连 + 首次 PONG”，不能只看连接超时一个参数。

如果重启出现端口占用，先确认旧监听进程已经退出；Windows 独占绑定还可能受尚未完全结束的旧连接影响，等待其释放后再启动，不要盲目去掉独占设置或结束无关进程。

### 10.5 实验五：先启动客户端

不启动服务端，直接运行 `client 20`。

- 本机没有监听时，常见结果是快速“连接被拒绝”，不一定要等满 2 秒。
- 数据包被丢弃的路径可能一直没有结果，才会耗尽建连预算。
- 无论哪种失败，都应释放本次 Socket，等待退避，最后受次数或总时间约束而停止。

常见码：Windows `10061` 常表示连接被拒绝，`10054` 常表示连接复位；Linux 可能显示 `ECONNREFUSED`、`ECONNRESET` 对应的数字。不要把某个 Linux 数字当成所有系统都固定相同的值。

## 11. 从代码中逐步学会关键实现

### 11.1 `wait_ready()` 为什么每轮重建参数

它做三件事：

1. 读取当前计时值，先判断是否已经到期。
2. 把剩余毫秒拆成 `timeval` 的秒和微秒。
3. 构造本轮关注的 Socket 集合，调用 `select()`。

毫秒转微秒使用“余下毫秒 × 1000”。不要把 2000 毫秒直接写进秒字段，也不要把整段 2000 毫秒全塞入必须小于 1000000 的微秒字段。

Linux 的 `select()` 可能因信号提前返回。下一轮重新计算剩余时间，而不是再给完整 2 秒。Windows 的异常集合主要还承担非阻塞建连失败通知；得到通知后不能跳过 `SO_ERROR` 检查。

### 11.2 `send_until()` 为什么保存 `offset`

假设消息长 7 字节，第一次只发送了 3 字节：

```text
已发送：[0..2]
待发送：[3..6]
下一次：data + 3，长度 7 - 3
```

每次都从头发，会重复发送前缀。遇到“暂时不可用”也不重置位置。所有片段仍共用同一个截止时间。

### 11.3 `line_until()` 为什么不能收到字节就返回

它只在遇到 LF 时返回“完整行”。此前收到的字节暂存在数组中，且受容量限制；不接受 NUL 和其他控制字符，防止协议内容与 C 字符串解释不一致。

EOF 时如果已经收到部分内容，会打印 `EOF in partial line`。这不是一条合法的短消息，而是一条被截断的消息。

### 11.4 为什么不用 `atoi()` 随意解析编号

`atoi()` 不方便区分“合法的 0”和“根本不是数字”，也不提供清晰的范围检查。本例逐字符检查，最多 9 位，所以乘 10 累加不会超过本协议上限。

对任意更长输入，必须在累加前检查溢出，或者正确使用 `strtoul()` 等带错误检查的转换函数；不要随意删掉位数限制。

### 11.5 为什么建连等待后必须检查 `SO_ERROR`

非阻塞 `connect()` 返回“进行中”，并不代表最终成功。`select()` 提示结果已经变化后，`SO_ERROR == 0` 才表示这次连接成功；非零就是实际失败原因。

连接成功的 Socket 在本例中继续保持非阻塞，之后的发送和接收也走自己的期限控制。不要一边认为 `send()` 永不阻塞，一边悄悄把 Socket 改回阻塞。

### 11.6 `earlier()` 怎样保护总预算

```text
本轮正常截止：now + 2000 ms
整个演示截止：finish
真正使用的截止：两者更早的那个
```

同样的裁剪也用于 3 秒心跳间隔与退避等待。它保证程序不会因为进入了新一轮就忽略已经快用完的总预算。

### 11.7 为什么客户端在自己的循环里拥有 Socket

每次 `dial()` 返回的新 Socket，只属于这一次连接的处理循环。失败后退出内层循环，由外层路径统一关闭，再等待并创建下一条连接。

这种结构让“哪个路径负责关闭”比较清楚。以后改成异步事件循环时，也要保留明确的资源所有权，不能让超时回调、接收线程与重连线程各自随手关闭。

## 12. 常见错误与排查顺序

### 12.1 编译与启动问题

| 现象 | 常见原因 | 下一步 |
| --- | --- | --- |
| Windows 找不到 `sys/socket.h` | 编译了 Linux 文件 | 换成 `hb_windows.c` |
| Linux 找不到 `winsock2.h` | 编译了 Windows 文件 | 换成 `hb_linux.c` |
| `WSAStartup` 等链接失败 | 缺 Winsock 库 | MinGW 加 `-lws2_32`，MSVC 加 `ws2_32.lib` |
| `gcc`/`cl` 找不到 | 工具未安装或终端环境不对 | 按环境章节检查编译器 |
| `bind/listen` 失败 | 端口占用、旧连接未释放或绑定配置问题 | 用端口观察工具确认进程与状态 |
| 客户端连不上 | 服务未启动、端口不一致、跨系统地址理解错误 | 先把同平台两端放在本机配对 |
| 程序一直停在 `accept()` | 正在等待客户端 | 另开终端运行客户端 |

示例里 `bind/listen` 是合并日志；排障练习可以拆成两条，让日志明确指出失败调用。读取错误码要紧跟失败调用，不能等别的网络函数执行后再取。

### 12.2 逻辑问题

| 错误做法 | 为什么不对 | 改法 |
| --- | --- | --- |
| `send()` 成功就宣布远端健康 | 本机接受字节不等于远端应用响应 | 等完整合法且匹配的 PONG |
| 每读一个字节刷新 2 秒 | 半条消息可无限续命 | 一轮共用绝对截止时间 |
| `select()` 可写就宣布建连成功 | 失败也可能触发通知 | 查询 `SO_ERROR` |
| 所有超时都立即重连 | 可能只是正常空闲或单请求晚到 | 先定义是哪一层超时，再按协议行动 |
| 重用失败的 Socket 再 connect | 状态复杂，容易残留错误 | 关闭后重新创建 |
| 每次连接成功就重置退避 | 快速连接又断开会一直高频重试 | 等稳定期和有效响应 |
| 固定等待且全部同时启动 | 客户端可能同步重试 | 加随机抖动，分散首次调度 |
| 服务端只负责 PONG，不管资源 | 空闲连接仍可能无限占用 | 设置输入/空闲期限和连接上限 |
| 主动关闭后仍然重连 | 旧任务没取消或停止状态没检查 | 停止状态优先，清理定时器 |
| 新连接恢复后重发所有请求 | 非幂等操作可能重复执行 | 分类请求、查询结果、使用稳定幂等键 |
| UI 中直接睡眠等重连 | 界面会失去响应 | 把等待接入事件循环或后台任务 |

### 12.3 为什么客户端超时，服务端却说“我发成功了”

两端日志描述的是两件不同的事情：服务端把字节交给了本机网络栈，客户端在自己的期限内没有收到可接受的完整响应。这两句话可以同时成立。

排查顺序：先确认消息编号，再看两端事件先后与耗时，必要时抓包。不同机器的日历时间可能不一致，不要直接拿各自的单调计时值互相相减。

### 12.4 为什么本地实验正常，远程就频繁超时

回环网络没有覆盖真实路由、防火墙、设备空闲清理、无线网络抖动与远端负载。先区分：建连失败、连接重置、心跳期限耗尽还是业务期限耗尽，再观察 RTT 分布和系统负载。

不要一看到超时就把所有参数改成几分钟，也不要一律缩成几十毫秒。参数应由实际等待目标和观测数据决定。

### 12.5 为什么服务端重启后还没立刻恢复

可能仍在退避，也可能总预算/尝试次数已耗尽；还可能新 TCP 已接通，但服务器尚未处理 PING。按 `BACKOFF → CONNECTING → ONLINE → PONG OK` 的顺序检查，而不是只看端口能否连上。

## 13. 工程实践：把小实验扩展成真正的客户端

### 13.1 同时管理业务、心跳和超时

真实程序不应在心跳间隔中简单睡眠，而应保存多个截止时间：

```text
当前最近期限 = min(下一次心跳时刻、等待 PONG 的期限、
                   各业务请求期限、连接总期限、退出期限)

等待网络事件，最多等到最近期限
处理网络输入/输出
检查到期任务
更新状态和下一次关注的事件
```

多连接系统还可以使用优先队列、最小堆或时间轮组织定时器。这些结构的作用是快速找到“下一项何时到期”，初学时先用一个小数组扫描也可以。

### 13.2 心跳也可能被本地发送队列堵住

**背压**表示下游处理较慢，上游必须控制继续产生数据的速度。如果大量业务数据已经排在 TCP 字节流前面，后加入的 PING 也要等前面的字节，不能跨过去。

因此要限制待发送队列、记录排队耗时，并区分“本地没能及时发出”与“发出后远端没回”。本例把两者合并在 2 秒心跳预算中，日志只能说本轮没有按时完成，不能据此断言远端卡住。

### 13.3 服务端也要限制资源

除了客户端检测服务端，还应考虑服务端怎样处理失联或恶意客户端：

- 每连接输入大小、输出队列、未完成请求数量有上限。
- 握手、认证、完整帧、长期空闲都有清晰期限。
- 读写回调每轮处理数量有限，避免一个连接独占循环。
- 非法消息及时结束，不允许任意单字节流量无限续命。
- 心跳处理足够轻量，同时明确它实际检查了哪些工作路径。

本例 15 秒是“每条输入行的总接收期限”，不是严格的“从最后一个字节开始计时的空闲超时”。这正是为了避免残帧慢速输入不断延长等待。

### 13.4 日志与监控记什么

最有用的字段是：连接编号/代次、状态变化、探测编号、失败类别、原始错误码、心跳 RTT、计划退避、实际恢复耗时、未决请求数量。

可以统计心跳超时次数、建连成功率、重连次数、恢复耗时、请求超时率。**连接健康**与**业务成功率**应分别统计；PONG 正常不能掩盖业务大量失败。

日志不要包含密码、令牌或完整敏感业务正文。频繁成功心跳可采样记录，故障与状态变化应能追踪。详细方法见 [[日志、监控与调试]]。

### 13.5 避免过度恢复

如果服务端明确表示“过载，请稍后”，客户端应遵守允许的重试提示与总预算；不要用不断重连绕过限流。

**熔断**可以粗略理解为“持续失败时先暂停新请求，过一会儿再少量探测”。它比每次失败都重连更进一步，后续做 RPC 或调用外部服务时再深入。

## 14. 练习题：从解释到改造

### 14.1 基础理解题

1. 为什么 `ESTABLISHED`、TCP ACK、PONG、业务成功是四种不同证据？
2. `PING 12\n` 只收到 `PO`，随后 2 秒预算耗尽，应该算成功吗？
3. 一条消息分三次读取，耗时分别 700 ms、600 ms、800 ms。在 2000 ms 总预算下，第三次开始时最多还能等多久？
4. 最后一次合法 PONG 在 `t=10`，间隔 3 秒，预算 2 秒，下一轮一直无响应，大约何时判定本轮失败？
5. 当前退避上限是 4000 ms，本例实际等待可能是多少？下一次上限是多少？
6. 客户端本次连接已持续 200 ms，然后断开，应该立刻重置退避吗？
7. 查询订单和“给余额加 10”超时后，为什么不能套用同一重试规则？
8. 请求响应丢失时，关闭连接能否撤销已经提交的数据库操作？

### 14.2 观察实验题

1. 将 `normal` 与 `split` 的 RTT 各记录 5 次，解释差异。
2. 启动 `silent`，写出每次失败、清理、退避、新建连的顺序。
3. `slow` 中同时观察两端日志，说明为什么服务端可能发送成功、客户端却失败。
4. 不启动服务器，确认连接被拒绝与心跳超时的日志区别。
5. 服务端重启前让连接保持 20 秒，观察稳定连接之后退避是否回到初始范围。
6. 把客户端总时间改为 1 秒，说明为什么本轮不应再等满 2 秒。

### 14.3 代码改造题

**练习 A：连续失败阈值。**允许同一连接连续 3 次心跳失败才关闭。先写规则：每轮失败后何时重探、迟到响应如何处理、半条旧响应如何保留或废弃。不能只把 `break` 改为 `continue`，因为读函数现在不会保留超时后的半行。

**练习 B：改成事件循环。**取消客户端 3 秒休眠，持续等待可读事件与最近期限。要求在间隔中也能及时发现 EOF，并能主动取消。

**练习 C：增加业务 `ECHO`。**约定 `ECHO <请求号> <正文>\n`，区分业务响应与 PONG。收到业务响应不能随意清除另一个业务请求的截止时间。

**练习 D：拆分失败原因。**把 `bind/listen` 合并错误拆开；把心跳失败分成“发不完”和“响应没读完”，日志同时带剩余预算。

**练习 E：实现稳定幂等键。**先写模拟接口，不接真实支付：同键同正文重复提交只增加余额一次；同键不同正文被拒绝。增加并发、进程重启、去重记录过期场景，说明哪些保证还没实现。

### 14.4 综合项目验收

制作一个“有限自动恢复的健康检查客户端”，要求：

- Windows/Linux 至少在自己可用的平台完整运行。
- 协议、参数单位、所有停止条件写清楚。
- 能处理部分读写、EOF、暂时不可用、非法输入。
- 建连、写入与完整响应等待都有期限，且不超出总预算。
- 重连使用新 Socket，退避有上限并有随机抖动。
- 稳定连接后才恢复短退避；用户取消后不再重连。
- 能通过正常、静默、慢响应、半帧、错误编号、服务重启实验。
- 能解释为什么该客户端尚未实现业务请求去重与会话恢复。
